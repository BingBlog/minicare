# UX · 快捷入口重设计

> 来源：产品体验优化专项  
> 文档类型：UX 分析 & 产品方案  
> 版本：v1.4 · 日期：2026-04-11

---

## 一、问题定义

### 1.1 背景

敏宝日记首页「快捷记录」区域承载了用户进入各记录模块的主要路径。随着记录模块从最初的4个扩展到当前的12个功能入口（含饮食子Tab），快捷入口的设计面临明显的体验问题。

### 1.2 核心问题

**问题 1：信息平铺，缺少层次感**

当前 8 个格子等权重平铺，用户需要逐一扫描才能找到目标。在凌晨喂奶、单手持机、精神疲惫的高频使用场景下，认知成本过高。

**问题 2：语义颗粒度不一致**

当前入口混合了两种维度：

- **行为维度**（配方奶、母乳、辅食）：描述"我正在做什么"
- **身体维度**（健康、生长）：描述"宝宝身体发生了什么"

两种维度并置，用户无法形成清晰的"分区感知"，增加决策摩擦。

**问题 3：高频与低频入口等权重**

配方奶/尿布是每日 6~10 次的超高频操作，生长/医疗可能 2 周才用一次。两者占据相同视觉面积，导致真正重要的入口被稀释。

**问题 4：缺乏上下文感知**

用户打开 App 的首要问题往往是"上次喂了多少？多久前喝的？"——但当前快捷入口只是导航格子，无法回答这个问题，用户必须先进入详情才能获取信息。

| 母乳      | 8~12次/天       | 5~8次/天          | 1~3次/天         | 超高频   |
| 尿布      | 6~10次/天       | 5~8次/天          | 4~6次/天         | 超高频   |
| 睡眠      | 4~6次/天        | 3~4次/天          | 2~3次/天         | 高频     |
| 辅食      | 无              | 1~2次/天          | 2~3次/天         | 中高频   |
| 表现      | 1~3次/天        | 1~2次/天          | 0~1次/天         | 中频     |
| 营养素    | 1次/天          | 1次/天            | 隔天             | 中低频   |
| 活动      | 0~1次/天        | 1次/天            | 隔天             | 低频     |
| 体温/健康 | 偶发            | 偶发              | 偶发             | 偶发     |

> **关键发现**：超高频的3类（配方奶/母乳/尿布）每天合计操作次数可达 20~30 次，占全部操作量的 70% 以上。

### 3.2 使用场景与时机分析

| 功能      | 典型使用场景       | 时机特征             | 操作条件             |
| --------- | ------------------ | -------------------- | -------------------- |
| 配方奶    | 冲奶喂奶后立即记录 | 即时性极强，不记就忘 | 常单手、抱娃中       |
| 母乳      | 哺乳中或结束时     | 即时性极强           | 常单手、坐卧中       |
| 尿布      | 换尿布时/换完后    | 即时性强，动作触发   | 双手操作，可留空     |
| 睡眠      | 宝宝入睡/醒来      | 即时性强，有计时需求 | 需快速触达计时       |
| 辅食      | 喂食过程中/结束后  | 即时性中等           | 需输入食物名，稍复杂 |
| 营养素    | 每天固定时间补记   | 规律性强             | 有余裕，不紧急       |
| 表现      | 宝宝状态异常时     | 情绪驱动，偶发       | 有焦虑感，需快速     |
| 体温      | 发烧/儿保测温后    | 偶发，紧迫性高       | 数字输入即可         |
| 活动      | 活动结束后补录     | 补录为主，即时性弱   | 有时间余裕           |
| 生长      | 儿保/家用体重秤旁  | 极低频，计划性强     | 有充裕时间           |
| 健康/医疗 | 就诊后整理         | 极低频，内容详细     | 需要安静环境         |

### 3.3 操作复杂度分析

```
低复杂度（≤3步完成）        中复杂度（3~6步）         高复杂度（≥6步）
─────────────────────     ──────────────────      ──────────────────
配方奶（调奶量即可）         辅食（需输入食物名）        医疗（多字段）
尿布（选类型即可）           睡眠（需计时或填时长）       健康（多维度症状）
体温（输数字即可）           母乳（侧别+时长）           营养素（多项目勾选）
表现（选状态即可）           活动（类型+强度+时长）       生长（3项测量值）
```

### 3.4 用户心理模型分析

用户使用 App 时存在四种截然不同的心理驱动：

**类型 A：「我刚做了什么」→ 行为记录（主动触发）**

> 代表功能：配方奶、母乳、辅食、尿布、睡眠  
> 特征：事件驱动，发生即记，不记就忘。对响应速度要求最高，≤2步必须进入表单。

**类型 B：「宝宝现在怎么样」→ 状态观察（被动触发）**

> 代表功能：表现、体温、健康  
> 特征：观察驱动，有一定延迟容忍，但情绪上有焦虑感（宝宝不舒服时），需要快速找到入口。

**类型 C：「今天要做的事」→ 计划执行（定时触发）**

> 代表功能：营养素、活动  
> 特征：规律性强，本质上更适合"提醒"模式，而非"快捷入口"。

**类型 D：「留作存档」→ 里程碑记录（低频计划）**

> 代表功能：生长、医疗  
> 特征：极低频，有意识地打开 App 完成，不需要快速入口，对操作路径长度不敏感。

## 四、优化思路

### 4.1 核心原则

1. **频率决定权重**：高频功能占更大面积，低频功能降权或隐藏
2. **上下文感知优先**：快捷入口不只是"导航按钮"，还应该展示上次记录信息，帮助用户"零步骤获取关键信息"
3. **分类降低决策成本**：给功能打上语义标签，让用户在视觉层面就能定位目标
4. **渐进式披露**：常用功能首屏展示，低频功能折叠到"更多"层

### 4.2 分类框架（初始版）

```txt
A类：喂食核心（超高频 · 行为记录 · 低复杂度）
配方奶 / 母乳 / 辅食
→ 最高优先级，卡片式大入口，展示上次记录摘要

B类：日常高频（高频 · 行为记录 · 低复杂度）
尿布 / 睡眠 / 表现 / 营养素
→ 第二优先级，标准格子，每天必用

C类：低频偶发（低频 · 混合触发 · 中高复杂度）
活动 / 体温 / 健康 / 生长 / 医疗
→ 折叠到"更多"抽屉（FAB弹层），不占首屏空间
```

> **营养素的特殊处理**：营养素频率属于"每日一次"，但它不是事件驱动而是计划执行，放在B类（日常高频）而非A类，是因为它不具备配方奶/母乳那种"事件发生→立刻记录"的即时紧迫性。

### 4.3 边界功能的归属争议

以下功能在分类时存在归属争议，需要做出明确决策：

#### 争议一：「体温」放哪一层？

**正方（放 B 区快捷格子）**：体温偶发但具有极强的紧急性——宝宝发烧时家长情绪焦虑、操作速度要求最高，若埋入 FAB 弹层会显著增加操作路径（≥3步），恰恰在最需要快速的场景下反而更慢。

**反方（放 C 区 FAB 弹层）**：体温使用频率极低（平均每月不到 5 次），占据首屏格子位置性价比极低；且紧急场景下用户会主动在 FAB 弹层顶部寻找，不构成障碍。

**决策：体温保留在 B 区，替换「营养素」**

理由如下：

1. 「即时性 × 紧迫感」双高的功能必须在 ≤2 步内触达，这是比频率更重要的排序标准
2. 「营养素」的使用场景有余裕，更适合 C 区 FAB 弹层
3. B 区变更后：**尿布 / 睡眠 / 体温 / 表现**——4个格子在语义上形成"今天护理状态"的清晰心智分组

**更新后的分类框架**：

```txt
A类：喂食核心（超高频 · 行为记录 · 低复杂度）
配方奶 / 母乳 / 辅食
→ 最高优先级，卡片式大入口，展示上次记录摘要

B类：即时护理（高频/偶发高紧迫 · 行为+状态 · 低复杂度）
尿布 / 睡眠 / 体温 / 表现
→ 第二优先级，标准格子，需要快速触达

C类：计划/存档（低频 · 计划性 · 中高复杂度）
营养素 / 活动 / 健康 / 生长 / 医疗
→ 折叠到"更多"抽屉（FAB弹层），不占首屏空间
```

#### 争议二：「表现」放 B 区还是 C 区？

「表现」（情绪/精神状态）频率中等（1~3次/天），但驱动场景是「宝宝状态异常时」，具有情绪焦虑感，和「体温」类似属于"状态观察类高紧迫"入口。**保留在 B 区**，理由与体温相同。

## 五、产品方案

### 5.1 方案概述：双区分层布局

将快捷入口从"等权重宫格"升级为"分层分组布局"：

```
┌──────────────────────────────────────────────────┐
│  快捷记录                          更多 (5) ›    │
│                                                  │
│  ─── 喂食 ────────────────────────────────────  │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐         │
│  │  配方奶  │ │   母乳   │ │   辅食   │         │
│  │ 120ml   │ │  3h前    │ │  今日2次  │         │  ← A区：3列大卡片
│  └──────────┘ └──────────┘ └──────────┘         │    含上次记录摘要
│                                                  │
│  ─── 护理 ────────────────────────────────────  │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐           │
│  │ 尿布  │ │ 睡眠  │ │ 体温  │ │ 表现  │         │  ← B区：4列小格子
│  └──────┘ └──────┘ └──────┘ └──────┘           │
└──────────────────────────────────────────────────┘
```

> **B区调整说明**：`§4.3` 决策将「体温」替换原「营养素」进入B区，「营养素」下移至 FAB 弹层 C区。分区标签由"日常"更新为"护理"，更准确反映 B 区四项功能（尿布/睡眠/体温/表现）的共同语义——即时护理状态。

### 5.2 A区：喂食核心卡片（详细设计）

#### 布局结构

每张卡片包含两个信息层：

```
┌────────────────────────────────┐
│  [图标]  配方奶                 │  ← 标题行（图标+名称）
│  上次 120ml · 2h前             │  ← 摘要行（上次记录信息）
└────────────────────────────────┘
```

整张卡片可点击，进入对应 Tab。

#### 摘要内容规则

| 类型   | 有数据时显示                     | 无数据时显示 |
| ------ | -------------------------------- | ------------ |
| 配方奶 | 上次 `{ml}ml · {时距}`           | 点击开始记录 |
| 母乳   | `{侧别}` · `{时长}` · `{时距}`   | 点击开始记录 |
| 辅食   | 今日 `{次数}` 次 · 最近 `{时距}` | 点击开始记录 |

时距显示规则：

- `< 60分钟`：显示「刚刚」
- `60分钟 ~ 24小时`：显示「Nh前」（N=小时数，保留整数）
- `> 24小时`：显示「昨日」或「N天前」

#### 数据来源

读取 `todayRecords` 中对应类型的最新一条，今日无记录时读取 `recentRecords` 接口（最近7天）。无需为此新增额外后端接口，利用现有 `today API` 即可满足大多数场景。

#### 视觉规格

- 卡片高度：约 84px（比B区格子高 30~40%）
- 背景色：各类型浅色背景（与 RECORD_TYPE_CFG 的 `bg` 保持一致）
- 摘要文字：`text-[11px]`，颜色 `#9A8090`（次要文字色），不抢主题
- 标题文字：`text-[13px] font-semibold`，颜色 `#4A3035`

#### 空状态处理

新用户首次使用时，三张卡片全部为空，需要有引导感：

```
┌────────────────────────────────┐
│  [图标]  配方奶                 │
│  ＋ 点击开始记录                │  ← 浅色引导文字，非报错感
└────────────────────────────────┘
```

- 不展示"暂无数据"等负向措辞
- 卡片整体可点击区域保持，引导用户直接点进去记录

### 5.3 B区：即时护理格子（详细设计）

保持现有宫格样式，4列平铺，**成员构成更新**：

| 位置 | 功能 | 决策理由                           |
| ---- | ---- | ---------------------------------- |
| 1    | 尿布 | 超高频，每日 6~10 次，绝对头部     |
| 2    | 睡眠 | 高频，有计时需求，进入即启动       |
| 3    | 体温 | 偶发高紧迫，≤2步触达原则优先于频率 |
| 4    | 表现 | 状态观察，焦虑场景下需快速入口     |

**B区统一视觉**：小格子保持现有样式（图标 + 文字标签），不展示摘要信息（高度有限，避免信息过载）。

### 5.4 C区（折叠）：FAB 弹层分组设计

#### 分组结构

移入 FAB 弹层的功能按使用场景分为两组，加分组标题区隔：

```
┌────────────────────────────────────┐
│  记录什么？                         │
│                                    │
│  ─── 日常补录 ─────────────────── │
│  [ 营养素 ]  维D / 铁剂 / 益生菌   │
│  [ 活动   ]  大运动 / 户外 / 亲子  │
│                                    │
│  ─── 健康档案 ─────────────────── │
│  [ 健康   ]  体温 / 过敏 / 症状    │
│  [ 生长   ]  身高 / 体重 / 头围    │
│  [ 医疗   ]  儿保 / 就诊 / 疫苗    │
└────────────────────────────────────┘
```

#### 分组依据

| 分组     | 包含功能                   | 特征                                       |
| -------- | -------------------------- | ------------------------------------------ |
| 日常补录 | 营养素、活动               | 规律性操作，有时间余裕，用户每天可能会翻到 |
| 健康档案 | 健康（含体温）、生长、医疗 | 低频但记录详细，有意识地打开归档           |

> **注意**：「健康」表单已覆盖详细体温记录（多次测温、异常标注），与 B 区「体温」格子（快速单次记录）形成互补——B 区体温是快速入口，FAB 中健康是完整记录入口。

### 5.5 FAB 功能可发现性设计

将5个功能移入 FAB 弹层后，最核心的风险是：**用户不知道这些功能还存在**，尤其是「营养素」（原本在宫格中，现在消失了）。

#### 5.5.1 问题根源分析

可发现性的核心矛盾：

- 降权折叠 → 减少认知负担（优点）
- 降权折叠 → 降低功能感知（风险）

用户的学习路径通常是：

1. **首次使用期**（前3天）：会主动探索，FAB 弹层一定会打开，功能都能被发现
2. **习惯形成期**（第4~14天）：进入固定操作路径，很少打开 FAB
3. **稳定使用期**（14天后）：已经知道哪里有什么，但被折叠的功能容易被遗忘

因此，真正的风险不在于「找不到」，而在于**「记不住」和「想不起来」**。

#### 5.5.2 可发现性解法：三层机制

**第一层：FAB 按钮本身的视觉强调（备选，不做默认实现）**

可在底部 Tab 栏中增加一个小徽标提示，在用户今日尚未打开过 FAB 时展示：

```
┌───────────────────────────────┐
│  首页  记录  [+]  分析  我的   │
│              ● ← 当日未开红点  │
└───────────────────────────────┘
```

此方案打扰感较强，仅作为备选，**不做默认实现**。

**第二层：快捷入口区「更多」文字的强化（一期默认实现）**

文字从「更多 ›」改为「更多 (5) ›」，括号内的数字表示 FAB 弹层中的功能数：

```
┌──────────────────────────────────────────┐
│  快捷记录                    更多 (5) ›  │
│                              ↑            │
│         显示被折叠的功能数量              │
│         带数字，提示有更多内容            │
└──────────────────────────────────────────┘
```

用户看到数字会好奇，自然触发探索行为。这是**成本最低、打扰感最弱**的可发现性方案。

**第三层：新用户引导——首次打开触达机制（一期默认实现）**

用户首次安装后进入首页，通过 `localStorage` 记录 `fab_first_open` 状态。若尚未打开过，在首页 B 区下方显示一行极浅的提示文字：

```
┌──────────────────────────────────────────┐
│  ─── 护理 ──────────────────────────────│
│  [ 尿布 ]  [ 睡眠 ]  [ 体温 ]  [ 表现 ] │
│                                          │
│  还有营养素、活动等 5 项记录 →            │  ← 浅灰色小字，点击打开 FAB
└──────────────────────────────────────────┘
```

用户点击该行或首次打开 FAB 后，`fab_first_open` 置为 `true`，提示行永久消失，不再干扰日常使用。

#### 5.5.3 方案选型决策

| 方案                   | 成本 | 打扰度         | 有效性 | 推荐             |
| ---------------------- | ---- | -------------- | ------ | ---------------- |
| FAB 按钮红点           | 低   | 高（每日都有） | 中     | 不推荐           |
| 「更多 (5) ›」数字徽标 | 极低 | 极低           | 中     | **一期默认实现** |
| 新用户首次引导提示行   | 低   | 低（仅一次）   | 高     | **一期默认实现** |
| 弹层内顶部引导语       | 极低 | 无             | 低     | 作为兜底         |

**结论：一期同时实现「数字徽标」和「新用户首次引导行」，两者成本都极低，联合覆盖新用户和现有用户两种场景。**

#### 5.5.4 引导文字规格

新用户提示行（B区下方）：

- 文字：`还有营养素等 5 项记录，点击` **`更多`** `查看 ›`（「更多」加粗）
- 样式：`text-[11px] text-[#C0A8AD] px-4 pb-3 pt-1`
- 整行可点击，点击后触发 FAB 弹层打开
- 仅在 `localStorage.fab_first_open !== 'true'` 时展示

### 5.6 布局对首页高度的影响评估

**当前高度**（8格子宫格）：约 230px

**改版后高度**：

- A区标题行：36px
- A区3列卡片：84px
- A/B分区间距 + B区标题行：约 40px
- B区4列格子：约 100px
- **合计：约 260px**（增加约 30px）

**影响**：首页时间线会被推下约 30px，在 667px+ 屏幕上不感知，在 667px（SE 等小屏）上首屏可见时间线条目数从约 3 条减少到约 2 条。

**缓解策略**：

1. A区卡片高度压缩到 76px（最小可接受）
2. A区和B区共用同一个白色卡片容器，减少一次 `padding + margin`（节省约 20px）
3. 接受这个权衡：多出的 30px 换来了更强的"上下文感知"，是值得的

**推荐方案**：采用策略 2，A/B区合并容器，总高度控制在 240px 以内。

### 5.7 二期方案：个性化排序（基于使用习惯）

**触发条件**：用户使用数据积累到 7 天以上

**数据来源**：本地 `localStorage` 记录各入口点击频次和最近点击时间

**排序算法**：

```
score = 最近7天点击次数 × 0.6 + (1 / 距上次点击天数) × 0.4
```

**实现形式**：

- B区4个格子按 score 降序排列
- 用户可通过"长按 → 进入编辑模式"手动调整顺序
- 冷启动期间（<7天数据）使用默认顺序

**注意事项**：

- 仅 B 区参与个性化排序，A 区（喂食核心）始终固定
- 家庭共用账号时，排序数据存在 per-device 层面，不做跨设备同步
- 个性化排序不影响 FAB 弹层的展示顺序

### 5.8 自定义快捷入口（用户主动配置）

#### 5.8.1 问题背景

当前 A/B 区配置基于「统计意义上的通用场景」硬编码，但喂养方式高度个体化：

| 家庭类型     | 实际高频操作     | 当前快捷区匹配度                 |
| ------------ | ---------------- | -------------------------------- |
| 纯配方奶     | 配方奶（超高频） | ✅ 配方奶在 A 区                 |
| 纯母乳       | 母乳（超高频）   | 🟡 母乳在 A 区，但配方奶格子空占 |
| 6 月以前     | 无辅食           | ❌ 辅食格子长期空置，噪音        |
| 6 月开始辅食 | 辅食↑，奶量↓     | 🟡 比例失调，需动态调整          |
| 断奶后       | 辅食+活动+睡眠   | ❌ 两个奶的格子变成高频噪音      |
| 少生病宝宝   | 体温极少用       | ❌ 体温格子占 B 区 25% 面积      |

根本矛盾：**快捷入口的「最优配置」因家庭、月龄、喂养方式的不同而截然不同，不存在一个对所有人都正确的默认值**。

#### 5.8.2 方案对比

| 方案         | 原理                         | 优点                   | 缺点                             | 推荐度      |
| ------------ | ---------------------------- | ---------------------- | -------------------------------- | ----------- |
| 月龄自动适配 | 根据宝宝月龄推断阶段         | 零操作                 | 无法感知喂养方式；准确率有限     | 🔸 辅助手段 |
| 频次自动学习 | 按点击次数自动上浮           | 零操作                 | 冷启动差；无法主动「去掉」某入口 | 🔸 辅助手段 |
| 用户主动设置 | 用户自己选择哪些出现在快捷区 | 完全精准；用户自主决定 | 有设置门槛；设置入口需可发现     | ✅ 主要方案 |

**决策：用户主动设置为主，月龄推断为辅（影响默认初始值）。**

#### 5.8.3 交互设计

##### 进入编辑模式

两个触发路径（保持可发现性）：

1. **标题行「编辑」按钮**：QuickActions 标题行右侧，文字链样式，常驻展示
2. **长按任意格子**：iOS 主屏同款心智，适合已有使用习惯的用户

```
┌──────────────────────────────────────────────────┐
│  快捷记录             更多 (N) ›  [编辑]          │ ← 「编辑」常驻，text-xs 文字链
│                                                  │
│  [配方奶] [母乳] [辅食]                           │
│  [尿布]   [睡眠] [体温] [表现]                    │
└──────────────────────────────────────────────────┘
```

##### 编辑模式状态

点击「编辑」后，QuickActions 区域切换为编辑态：

```
┌──────────────────────────────────────────────────┐
│  快捷记录                            [完成]       │ ← 「编辑」变为「完成」
│                                                  │
│  ─── 已添加（7 / 7）─────────────────────────  │ ← 当前格子数 / 最大格子数
│  [配方奶 ×] [母乳 ×] [辅食 ×]                   │
│  [尿布 ×]   [睡眠 ×] [体温 ×] [表现 ×]           │ ← 格子右上角有 × 删除按钮
│                                                  │
│  ─── 更多功能（点击添加）─────────────────────  │ ← 「格子库」区域
│  [营养素 +] [活动 +] [健康 +]                    │
│  [生长 +]   [医疗 +]                              │ ← 未在快捷区的功能，可点击添加
└──────────────────────────────────────────────────┘
```

交互规则：

- 「已添加」区最多 7 格（A区3 + B区4），达到上限时「更多功能」区的 `+` 按钮变灰
- 点击「已添加」区的 `×`：移出快捷区，该格子转移到「更多功能」区
- 点击「更多功能」区的格子：添加到「已添加」区末尾
- 不支持拖拽排序（二期再做，一期仅支持增删）
- 点击「完成」：保存配置，退出编辑模式

##### A/B 分区的自动决定规则

用户编辑的是「7 个格子的有序列表」，A/B 分区由系统自动划分：

- **前 3 个 = A 区**（大卡片，展示摘要）
- **后 4 个 = B 区**（小格子）

用户不感知 A/B 的分界线，只感知「顺序」。默认顺序从前到后即为 A→B 的优先级。

> 例外：若用户只选了 5 个格子，则前 3 个为 A 区，后 2 个为 B 区（B区不足 4 格时自适应）。

#### 5.8.4 默认值策略（月龄推断辅助）

首次进入时，根据宝宝月龄设定不同的默认快捷配置，而非一刀切：

| 月龄阶段  | 默认 A 区（前3）   | 默认 B 区（后4）         | 说明                    |
| --------- | ------------------ | ------------------------ | ----------------------- |
| 0 ~ 5 月  | 配方奶、母乳、尿布 | 睡眠、体温、表现、营养素 | 辅食尚未开始            |
| 6 ~ 11 月 | 配方奶、母乳、辅食 | 尿布、睡眠、体温、表现   | 辅食加入，尿布降至 B 区 |
| 12 月+    | 辅食、母乳、配方奶 | 睡眠、尿布、体温、表现   | 辅食权重提升            |

> 这只是初始默认值，用户可随时通过编辑模式调整。

#### 5.8.5 数据持久化

- 存储位置：`localStorage`，key 为 `quickaction_keys`（字符串数组，长度 ≤ 7）
- 结构：`["formula", "breast", "food", "diaper", "sleep", "temperature", "symptom"]`
- 首次使用时写入月龄默认值（见 §5.8.4）
- 「完成」按钮点击时写入最新配置
- 读取时：`QuickActions` 组件从 `localStorage` 读取，无则使用月龄默认值

#### 5.8.6 FAB 弹层的联动规则

快捷区更新后，FAB 弹层内容也需要同步：

- **首页「更多」弹层（精简版）**：展示「未出现在快捷区」的全部功能，按原分组归类
- 若快捷区已包含某功能，该功能从首页弹层中隐藏，避免重复
- **导航栏 `+` 弹层（完整版）**：始终展示全部 11 项，不随快捷区变化（全局入口，功能完整性优先）

```
快捷区：[配方奶] [母乳] [尿布] [睡眠] [体温] [表现] [营养素]
                                    ↓
首页「更多」弹层动态内容：
  日常补录：活动（营养素已在快捷区，隐藏）
  健康档案：健康、生长、医疗
  喂食：辅食（辅食未在快捷区，展示）
```

> 注意：辅食不在快捷区时，「更多」弹层的喂食分组会出现，提醒用户还可以记辅食。

#### 5.8.7 边界情况处理

| 边界                                 | 处理方式                                |
| ------------------------------------ | --------------------------------------- |
| 用户删光所有格子                     | 最少保留 1 格，不允许清空               |
| 格子数不足 3 时 A 区如何展示         | 按实际数量展示，A 区最少 1 格           |
| 格子数不足 4 时 B 区如何展示         | B 区为空时整行隐藏，A 区独占            |
| 新增记录模块（如未来的「疫苗」功能） | 新模块默认不进快捷区，仅在 FAB 弹层出现 |

## 八、v1.4 补充问题：两处「记录什么」弹层内容不一致

### 8.1 问题描述

v1.3 方案实施后，App 内存在两个入口可以打开「记录类型选择弹层」：

| 入口         | 触发位置                | 当前实现                         |
| ------------ | ----------------------- | -------------------------------- |
| 导航栏 `+`   | 底部 Tab 栏中央         | `AppLayout.tsx` 内联弹层，无分组 |
| 首页「更多」 | QuickActions 标题行右侧 | `FabSheet.tsx` 组件，有分组      |

**两者的内容差异**：

| 维度     | 导航栏 + 弹层              | 首页「更多」弹层            |
| -------- | -------------------------- | --------------------------- |
| 功能范围 | 全部 9 项（含 A/B 区功能） | 仅 C 区 5 项                |
| 分组结构 | 无分组，平铺列表           | 有分组（日常补录/健康档案） |
| 实现方式 | `AppLayout.tsx` 硬编码     | `FabSheet.tsx` 组件         |
| Tab 跳转 | 无（跳至饮食主入口）       | 无                          |

**体验问题**：

1. **内容割裂**：同一个操作意图（「我要记录一件事」），走不同入口看到完全不同的内容，用户形成混乱心智
2. **功能重复不一致**：导航栏弹层有「饮食」「睡眠」「尿布」等，这些在首页 A/B 区已有快捷入口；两个入口覆盖不同的功能子集，难以形成统一认知
3. **视觉风格不一致**：导航栏弹层是旧版无分组样式（简单平铺），首页弹层是新版分组样式，同一 App 内两种视觉语言并存

### 8.2 问题根因

v1.3 实施时，只重构了首页 `FabSheet.tsx`（C区 FAB 弹层），未同步更新 `AppLayout.tsx` 中独立实现的导航栏弹层，导致两个弹层各自维护，产生分歧。

### 8.3 解决方案

#### 方案 A（推荐）：统一弹层内容——导航栏弹层展示「完整版全功能分组弹层」

**核心思路**：导航栏 `+` 作为「全局快速记录入口」，应该覆盖所有记录类型，展示完整功能；首页「更多」作为「首页快捷入口的溢出入口」，只展示未在首屏出现的 C 区功能。两个弹层**目的不同，内容理应不同，但结构和视觉应该统一**。

**分组结构（导航栏完整版）**：

```

│              ━━━━━━━━━━                         │ ← 拖拽把手
│                                                 │
```

**分组设计依据**：

| 分组     | 包含功能               | 依据                                   |
| -------- | ---------------------- | -------------------------------------- |
| 喂食     | 配方奶、母乳、辅食     | 同类喂食行为，对应 A 区卡片            |
| 日常护理 | 尿布、睡眠、体温、表现 | 对应 B 区格子，即时性强                |
| 日常补录 | 营养素、活动           | 规律性但有余裕，对应 C 区 FAB 原有分组 |
| 健康档案 | 健康、生长、医疗       | 低频存档，对应 C 区 FAB 原有分组       |

**两个弹层的关系**：

```
导航栏 + 弹层（完整版，4个分组，11项）
= A区功能（喂食3项）
+ B区功能（日常护理4项）
+ C区功能（日常补录2项 + 健康档案3项）

首页「更多」弹层（精简版，2个分组，5项）
= C区功能（日常补录2项 + 健康档案3项）
```

用户认知：

- 首页快捷区：我最常用的入口（A/B区）
- 首页「更多」：我不常用但今天可能要用的（C区）
- 导航栏 `+`：我想记点东西，所有类型都在这里找

#### 方案 B（备选）：两个入口完全相同，都展示完整版

**优点**：用户无需区分两个入口的差异，任意一个都能找到全部功能。  
**缺点**：首页「更多」弹层如果包含 A/B 区功能，会与首屏快捷入口产生重复感，削弱 A/B 区设计的意义。

**不推荐**：与分层布局的设计逻辑矛盾。

#### 决策

**采用方案 A**：导航栏 `+` 展示完整分组弹层（4组），首页「更多」保持现有 C 区精简版（2组）。两者内容有差异但**视觉语言统一**（都用分组 + 条目 + 图标 + 副标题 + 右箭头的样式）。

### 8.4 实施方案

#### 需要修改的文件

| 文件                           | 改动内容                                                                              |
| ------------------------------ | ------------------------------------------------------------------------------------- |
| `src/lib/constants.ts`         | 新增 `GLOBAL_FAB_GROUPS` 常量，覆盖全部 4 个分组（喂食/护理/补录/健康档案）           |
| `src/components/AppLayout.tsx` | 删除内联 `fabMenuItems` 数组和内联弹层 UI；改为复用 `FabSheet` 组件并传入完整分组配置 |
| `src/pages/home/FabSheet.tsx`  | 改为接受外部 `groups` prop，支持渲染任意分组配置（完整版/精简版都复用此组件）         |

#### 关键设计决定

1. **`FabSheet` 组件泛化**：将分组配置从组件内部移到外部 prop，使同一组件可服务两个入口
2. **喂食分组的 Tab 跳转**：导航栏弹层中的「配方奶/母乳/辅食」需传递 `state.tab` 参数（与首页 A 区卡片行为一致）
3. **体温的特殊跳转**：导航栏弹层中「体温」条目需传递 `state.expandTemp: true`（与 AppLayout 原有逻辑保持一致）
4. **复用 `constants.ts` 配置**：`GLOBAL_FAB_GROUPS` 引用 `FAB_SUBTITLES`，避免副标题文案重复维护
