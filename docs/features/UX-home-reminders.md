## 一、问题定义

### 1.1 背景

首页 Hero 卡下方「提醒横幅区」（banners）随功能迭代不断增员，2026-10 已达 **7 条**：

| # | 提醒条 | 组件 | 出现条件 |
|---|--------|------|----------|
| 1 | 日程提醒（五态） | `ScheduleBanner` | 有作息计划 |
| 2 | 还没有作息计划（引导） | 内联 | 无作息计划 |
| 3 | 宝宝正在睡觉 | `SleepBanner` | 有进行中睡眠 |
| 4 | 距上次喂奶 / 距上次辅食（两行） | `FeedingBanner` | 有进食记录 |
| 5 | 下次复查提醒 | `NextFollowUpBanner` | 有未过期复查 |
| 6 | 补剂 & 营养素 | `SupplementBar` | 有补剂记录 |
| 7 | 排敏进度 | `AllergyProgressBar` | 有排敏任务 |

全部同时出现时信息密度过大，用户需要逐条扫读才能找到当下关心的内容。

> 另有 home-content 区首位的「昨日日记卡」（`HomeDiaryCard`），两种形态（回顾 / 补写引导）同属提醒性质，一并纳入提醒开关体系（见 §2.3）。

### 1.2 核心问题

1. **同类信息重复**：喂奶与辅食是同一维度（进食间隔）的两行并列，家长实际只关心"距上一次进食多久"；
2. **提醒已完成仍占位**：营养素今日已吃后仍显示「今天已吃：xxx」确认态，提醒目的已达成却继续占一行；
3. **无法裁剪**：不同家庭关注点不同（如纯奶粉喂养不需要辅食间隔、无过敏宝宝不需要排敏进度），但用户没有任何手段关闭不关心的提醒。

## 二、需求与方案（2026-10-12 实施）

### 2.1 需求一：喂奶 / 辅食提醒合并为一项（只显示最近一项）

- **口径**：比较两者的**绝对时间**（`time` 为含日期的 ISO，跨天比较自然正确），仅展示更近的一项。
- **展示**：展示哪项即标题与按钮随哪项——「距上次喂奶」+「记喂奶」或「距上次辅食」+「记辅食」，强调色随类型（喂奶橙 / 辅食深橙）。
- **计时口径不变**：营养素不参与比较、不重置任何计时（`feedingFilter` / `foodFilter` 规则保持）。
- **比较逻辑放在页面**（`index.tsx` 的 `lastIntake`），组件只负责展示与计时。

### 2.2 需求二：营养素提醒在今日已吃后不再展示

`SupplementBar` 可见性规则调整为：

| 今日 | 昨日 | 展示 |
|------|------|------|
| 已吃（有任一补剂记录） | — | **不渲染**（原为显示「今天已吃：xxx」，取消） |
| 还没吃 | 有记录 | 「今天还没吃 · 昨日：xxx」 |
| 还没吃 | 无记录 | 不渲染（无提醒基线，行为不变） |

> **口径再次升级（2026-10-12 晚，[PRD-018](../prd/PRD-018.md)）**：上表「昨日反推」口径已被《营养素「每日补充计划」》替代——
> 家长在营养素记录页配置每日应吃清单，首页按「**计划 − 今日已吃**」展示未吃项（计划内全吃完才隐藏；未配置渲染引导条）。
> 本节仅存历史参考；现行口径见 PRD-018 §3 与 `F03-feeding.md`「每日补充计划与首页提醒对账」。

### 2.3 需求三：提醒设置（7 开关 · 默认全开）

- **入口**：「我的」→ 工具组 →「首页提醒」（副文案动态显示「全部开启 / 已关闭 N 项」）→ 独立设置页 `pages/settings/reminder/index`。
- **开关清单（7 项，默认全开）**：

| key | 名称 | 对应首页条目 |
|-----|------|--------------|
| `feed` | 喂奶 / 辅食提醒 | `FeedingBanner`（合并后） |
| `supplement` | 补剂 & 营养素提醒 | `SupplementBar` |
| `allergy` | 排敏进度提醒 | `AllergyProgressBar` |
| `schedule` | 日程提醒 | `ScheduleBanner` +「还没有作息计划」引导条（随开关） |
| `followup` | 复查提醒 | `NextFollowUpBanner` |
| `sleep` | 睡眠提醒 | `SleepBanner` |
| `diary` | 日记提醒 | `HomeDiaryCard`（昨日日记卡） |

- **存储**：本机设备级（Taro Storage，key `minicare_reminder_settings`），不做服务端同步——家庭成员各自设备独立设置。
- **读取约定**：无存储 / 存储损坏 / 未来新增开关 key，一律回落默认值 `true`。
- **生效时机**：首页在 `useDidShow` 重读本地存储，从设置页返回立即生效（无需刷新）。

### 2.4 补充决策（已拍板）

- 睡眠横幅**纳入**可配置清单；关闭后「结束睡眠」仍可从「记录 → 睡眠」页操作（该页会恢复进行中计时），无功能死角。
- 日记卡**纳入**可配置清单（2026-10-12 追补）：关闭后首页不渲染日记卡（含加载骨架）；日记数据加载逻辑不变，仅渲染受控。
- 设置页脚注说明「设置保存在本机，更换设备后需要重新设置」。

### 2.5 非目标 / 不做

- 不做服务端同步（多设备共享时刻再评估）；
- 不改 Web 端（维护模式）与 dashboard 提醒系统；
- 不给已关闭的提醒做"暂停 N 小时"等复杂语义。

## 四、验收清单（待人工验收）

- [ ] 首页同时存在今日喂奶与今日辅食时，喂养条只显示**时间更近**的一项（标题、按钮、跳转均对应该项）
- [ ] 跨天场景：喂奶在昨日、辅食在今日 → 显示的应是今日辅食（反向亦然）
- [ ] 营养素今日已记录 → 首页**无**营养素条；今日未吃且昨日有 → 「今天还没吃 · 昨日：xxx」
- [ ] 「我的 → 工具」出现「首页提醒」，副文案与开关状态一致（全开 =「全部开启」）
- [ ] 设置页 7 个开关默认全开；关闭任一开关 → 返回首页对应条**立即消失**；重新开启恢复
- [ ] 关闭「日程提醒」→ 首页日程 Bar 与「还没有作息计划」引导条都不显示
- [ ] 关闭「睡眠提醒」→ 首页不显示睡眠条；从「记录 → 睡眠」页仍能结束进行中的睡眠

- [ ] 全部关闭 → 首页横幅区与日记卡均不残留
- [ ] 杀进程重进小程序 → 开关状态保持（本地存储持久化）
