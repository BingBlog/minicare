# 音箱语音录入方案调研

> 调研时间：2026-08-23
> 目标：通过一个常驻家庭的「音箱」，免掏手机直接说一句话完成 minicare 数据录入（如"旺仔喝了 120 毫升奶粉"）

---

## 1. 背景与本质

minicare 已有完整的手机语音录入链路：

```
手机录音(mp3/16k) → POST /api/family/:familyId/voice/parse → 腾讯云 ASR → 混元 NLU → 结构化记录
```

音箱方案的本质：**把这条链路的「采集端」从手机挪到一个常驻设备上**。音箱 = 常驻麦克风 + 网络 + 播报反馈（TTS 确认"已记录 120 毫升奶粉"）。

核心问题只有一个：**用什么音箱、怎么把语音/文本送进 minicare 后端**。

---

## 2. 路线一：现成智能音箱 + 官方技能平台

### 2.1 小爱开放平台（小米）—— 最有希望
- 状态：**活跃**，支持「自定义技能」，音箱技能可配置 HTTPS 服务器回调
- 流程：小米账号实名认证 → 创建技能（对象=音箱）→ 可视化 NLP 交互模型（意图/槽位）→ 配置 HTTPS 回调 → 提交审核 → 上线
- 关键点：
  - 技能创建后**不能更改**，需谨慎设计
  - 回调事件带 `query`（用户语音识别文本）+ 槽位 → 开发者服务器处理 → 返回 TTS 播报
  - 支持 OAuth 账号绑定（小米账号体系）
- 对 minicare：技能回调拿到 ASR **文本** → 调 minicare 文本 NLU → 返回 TTS"已记录：奶粉 120 毫升"
- 门槛：个人实名可做，但**审核周期与通过率不可控**

### 2.2 小度开放平台（百度）
- 状态：自定义技能（Custom Skill）开放，可用百度 CFC 函数计算或自建 HTTPS
- 新动态（2025-07）：上线**智能硬件 MCP Server**——支持 `control_xiaodu`（下发文本指令）、`xiaodu_speak`（让音箱播报文本）、`xiaodu_take_photo`
- 注意：MCP 能力是"让音箱说话/执行"，**录入方向仍需技能**

### 2.3 天猫精灵（阿里）
- 状态：aligenie.com 技能接入仍开放，但平台重心已转向全屋智能（Genie OS+）
- 门槛：个人开发者技能审核严格，通常需**企业资质** → 不适合本项目

### 2.4 腾讯云小微 —— ❌ 已排除
- **2025-12-31 停止维护**（SDK/API/后台服务全停），现有功能不再修复，随时可能终止

### 路线一小结

| 平台 | 可行 | 个人门槛 | 审核风险 | 数据路径 |
|---|---|---|---|---|
| 小爱 | ✅ 自定义技能 | 实名即可 | 中高 | 音频过小米云 |
| 小度 | ✅ 自定义技能 | 实名即可 | 中 | 音频过百度云 |
| 天猫精灵 | ⚠️ | 需企业资质 | 高 | 音频过阿里云 |
| 腾讯云小微 | ❌ 已停服 | — | — | — |

## 3. 路线二：ESP32-S3 自建音箱（推荐主路线）

### 3.1 硬件（总成本约 100 元 / 带壳 200-400 元）

| 组件 | 型号 | 价格 | 说明 |
|---|---|---|---|
| 主控 | ESP32-S3（N16R8：16MB Flash + 8MB PSRAM） | 50-120 | 双核 240MHz，I2S 直连数字麦，AI 向量指令加速 |
| 麦克风 | INMP441 I2S 数字麦 | 15-25 | 全向拾音、16kHz 标准采样，可双麦做阵列 |
| 功放+喇叭 | MAX98357A + 3W 喇叭 | 10-25 | 播报反馈 |
| 可选 | 外壳 / 1.28 寸 LCD / 18650 电池 | 30-60 | 成品感 |

**免焊接成品开发板**（推荐省事）：立创·实战派 ESP32-S3、乐鑫 ESP32-S3-BOX3、M5Stack CoreS3（集成屏/麦/喇叭，200-400 元）。

### 3.2 开源固件：xiaozhi-esp32（小智 AI）⭐
- 仓库：`78/xiaozhi-esp32`，**MIT 协议**，ESP-IDF 5.4+，支持 **70+ 开发板**
- 核心能力：
  - **ESP-SR 离线唤醒词**（WakeNet，可自定义，如"旺仔记录"），断网也能唤醒
  - WebSocket / UDP 通信协议，OPUS 音频编码
  - 流式 ASR + LLM + TTS 全链路，支持国语/粤语/英语/日语/韩语
  - **声纹识别**（识别说话人，多成员家庭天然契合）
  - **MCP 协议扩展**（云端 MCP 让 LLM 调用工具 → 可挂 minicare API）
- 服务器端：官方免费测试服（不商用）或**自建** `xiaozhi-esp32-server`（Python/Java/Go 三套实现）→ 数据完全自有

### 3.3 接入 minicare 的两种子方案

#### B1：xiaozhi 服务器 + minicare 文本 NLU（推荐）
```
唤醒词(ESP-SR 离线) → 录音 → xiaozhi server ASR → 文本
  → POST minicare 新接口 /voice/parse-text（复用现有混元 NLU prompt）
  → 结构化结果 → 服务器组织 TTS 播报："已记录 120 毫升奶粉"
```
- 后端改动：把 `voice.service.ts` 的 `nluParse()` 抽成**文本入口**（新 controller 或 `?text=` 参数）+ **设备鉴权**
- 复用度：NLU prompt/字段校验/confidence 逻辑 100% 复用

#### B2：自研最小固件 + 复用现有音频接口（后端零改动）
```
ESP-SR 唤醒 → 录音 5-10s (WAV/MP3) → HTTP multipart 上传现有 /voice/parse
  → 返回 JSON → 本地或云端 TTS 播报确认
```
- 固件开发量中等（ESP-IDF / Arduino），ASR + NLU 完全复用腾讯云+混元
- 后端仅需加**设备鉴权**，接口本身不动

### 3.4 设备鉴权设计（两条路线都需要）
- 现状：JWT 短时效 + 家庭成员账号体系，**不适合设备长期驻留**
- 方案：新增「音箱设备」概念 —— 家庭管理员在 App 生成设备码 → 音箱配网时输入 → 后端签发**长期 device token**（绑定 familyId + 角色），调用语音接口时走设备鉴权
- 简单版：家庭固定码 + 长期 token 烧录进音箱配置

### 3.5 播报反馈闭环
- 现有 `VoiceParseResult` 已有 `confidence: high|low` + `missingFields`
- 交互设计：high → 直接播报"已记录：奶粉 120 毫升"；low → 播报"没听清，请再说一次/请补充奶量"

## 4. 方案对比总表

| 维度 | 小爱技能 | 小度技能 | 天猫精灵 | ESP32 自建 (xiaozhi) |
|---|---|---|---|---|
| 硬件成本 | ≈0（已有音箱） | ≈0 | ≈0 | 100-400 元 |
| 开发量 | 技能+回调 2-3 天 | 同左 | 同左 | 服务器 2-3 天 + 组装 1 天 |
| 审核风险 | 高（实名+审核） | 中 | 高（企业资质） | **无** |
| 数据主权 | 过小米云 | 过百度云 | 过阿里云 | **完全自有** |
| 唤醒词 | 固定"小爱同学" | 固定"小度小度" | 固定"天猫精灵" | **自定义** |
| 拾音质量 | 好（阵列） | 好 | 好 | 一般（单麦，可双麦阵列） |
| 可持续性 | 中 | 中 | 中 | **高（开源可控）** |
| 现有链路复用 | 低（需文本 NLU） | 低 | 低 | **高（B2 甚至零改动）** |
| 断网可用 | ❌ | ❌ | ❌ | 唤醒可离线，ASR 可降级 |

---

## 5. 推荐结论

1. **首选：B1 路线**（xiaozhi-esp32 自建音箱 + 自建服务器 + minicare 文本 NLU 接口）
   - 无审核风险、数据主权完整、复用现有混元 NLU、支持自定义唤醒词和声纹识别
   - 与用户对 EP32/ESP32 硬件的关注方向一致
2. **次选：B2**（后端零改动的极简固件）—— 如果不想部署 xiaozhi server，只想最快跑通
3. **备选：家里已有小爱音箱且接受审核** → 小爱自定义技能（技能创建后不可改，交互模型设计要一次到位）
4. **排除**：腾讯云小微（停服）、天猫精灵（企业资质门槛）

---

## 6. 落地步骤（B1 路线）

1. **后端（0.5-1 天）**：新增 `POST /api/family/:familyId/voice/parse-text`（复用 `nluParse` + 字段校验）+ 设备鉴权（device token）
2. **服务器（1-2 天）**：部署 `xiaozhi-esp32-server`（Python 版），配置 ASR（腾讯云/火山）与 TTS；加 minicare 工具调用（把 parse-text 封装为 LLM 工具或协议扩展）
3. **硬件（0.5-1 天）**：ESP32-S3 + INMP441 + MAX98357A，烧 xiaozhi 固件，自定义唤醒词（如"旺仔记录"）
4. **联调**：说"旺仔记录，奶粉 120 毫升" → 播报"已记录 120 毫升奶粉"
5. **评估**：识别准确率、端到端延迟、误唤醒率；后续可加声纹识别区分家庭成员

---

## 7. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| 单麦远场拾音差 | 3-5 米外识别率下降 | 双麦阵列（ESP32-S3-Korvo-2）或放近处 |
| 网络依赖 | 断网无法上传 | xiaozhi 支持离线唤醒；ASR 可切本地（效果降级） |
| 误唤醒 | 自定义唤醒词过短/常见 | 选独特词（如"旺仔记录"）、调 WakeNet 灵敏度 |
| 技能审核不确定 | 路线一特有 | 走 ESP32 自建可完全规避 |
