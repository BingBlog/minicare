# 敏宝 Agent 知识库建设方案分析

> 生成时间：2026-08-19 ｜ 基于：`docs/敏宝知识库/` 全部资料（20 份源文件 + 知识清单 + 资料分析）
> 目标：为 minicare 构建面向家长问答的医疗健康 Agent 知识库，按行业最佳实践拆解知识图谱、结构化、检索召回、重排、回答组装、风险提示六个维度。

---

## 〇、总体定位（先想清楚再动手）

医疗健康领域的 Agent 知识库与通用 RAG 有本质差异：

| 维度 | 通用 RAG | 医疗 Agent 知识库 |
|---|---|---|
| 容错度 | 允许部分模糊 | **极低**，过敏/急救内容错一档都可能出事 |
| 权威约束 | 不强 | **强**，必须锚定证据层级 |
| 合规要求 | 弱 | **强**，免责、不诊断、隐私保护 |
| 溯源 | 可选 | **必须**，每条结论可点击溯源 |
| 冲突处理 | 取多数 | **特判**，国内共识 > 国际指南 > 综述 |

**核心原则：这是一个"检索增强 + 证据锚定 + 安全护栏"的系统，不是简单的"PDF 灌进向量库"。**

## 一、数据治理（所有环节的前置）

> 再好的检索架构也救不了脏数据。医疗 KB 对数据质量要求是"一字不差"级别。

### 1.1 资料解析与清洗
- 20 份源文件（PDF/HTML）→ 统一解析为结构化 Markdown
- 清洗清单：
  - 剔除期刊版式噪音（页码、页眉、投稿信息、参考文献尾注）
  - 表格保留结构（如配方阶梯表、健康教育处方表）→ 转 Markdown 表
  - 图表 OCR 标注（生长曲线、剂量表需要二次核对）
- 产出：`资料ID → 清洗后正文`

### 1.2 元数据 Schema（每条知识落库的"身份证"）

```yaml
knowledge_id: KB-A1-001          # 对应知识清单条目
module: A                        # 8 大模块之一
title: 食物过敏的定义与分类
content: ...                     # 清洗后的正文
sources:
  - source_id: SRC-EAACI-2025    # 关联源文件
    page: 14-16                  # 页码，用于溯源
    statement: 原文引用句        # 逐句锚定
evidence_level: guideline        # guideline/consensus/RCT/policy/edu
region: both                     # cn / intl / both
year: 2025
applicable_age: 0-3y             # 适用年龄
risk_level: low / caution / emergency   # 风险分级（用于护栏）
disclaimer: false                # 是否需要强免责声明
review_status: pending / approved / expired
```

> 元数据是后续**过滤、排序、护栏**三个环节的开关，必须在入库时一次做对。

## 二、知识图谱（KG）

### 2.1 为什么医疗 KB 需要图谱
纯向量检索的两个死穴，正好被图谱补上：
1. **同义消歧**："牛奶过敏"、CMPA、"牛奶蛋白过敏"是同一实体 → 图谱实体归一化
2. **多跳推理**："宝宝湿疹反复" → 需关联 特应性皮炎 → 过敏进程 → 食物过敏风险 → 检测指征，向量检索无法跨文档关联

### 2.2 领域本体设计（轻量起步）

```
实体（Entity）：
  过敏原类  牛奶蛋白 / 鸡蛋 / 花生 / 小麦 / 大豆 / 海鲜 / 坚果
  疾病类    食物过敏 / CMPA / 特应性皮炎 / 过敏性鼻炎 / 哮喘 / 过敏进程
  症状类    皮疹 / 腹泻 / 便血 / 呕吐 / 喘息 / 血管性水肿
  检查类    sIgE / SPT / CRD / OFC
  干预类    母乳喂养 / 特殊配方(eHF/AAF) / 辅食引入 / 免疫治疗 / 急救

关系（Relation）：
  CMPA -(由)→ 牛奶蛋白；CMPA -(表现为)→ {皮疹,腹泻,便血...}
  湿疹 -(风险因子)→ 食物过敏；食物过敏 -(进程)→ 哮喘
  回避-激发 -(诊断金标准)→ CMPA；eHF/AAF -(治疗)→ CMPA
  严重过敏反应 -(急救一线)→ 肾上腺素
```

### 2.3 与检索结合的落地方式（GraphRAG）

| 方案 | 说明 | 适用阶段 |
|---|---|---|
| **概念字典 + 实体链接**（最低成本） | 维护"家长口语 → 医学概念"映射表，查询时先归一化再检索 | 阶段 1 必做 |
| **GraphRAG（Microsoft/LightRAG）** | 图谱社区摘要，支撑全局性问答（"过敏宝宝整体管理"） | 阶段 2 可选 |
| **知识图谱增强检索** | 检索结果沿图谱扩展一跳（查 CMPA 顺带召回 相关症状/配方） | 阶段 3 |

> **建议**：不要一上来建大图。敏宝领域实体约 50-100 个、关系 5-6 类，先用"概念字典+实体链接"满足 80% 消歧需求，图谱增强作为二期。

## 三、结构化（Chunking）

### 3.1 切分粒度：以"知识条目"为原子单位
- 不按页/按字切，按知识清单的 **P0-P2 条目粒度** 切
- 每个 chunk = 一个"可独立回答的完整知识点"（含 症状/建议/边界/来源）
- 理由：家长问题通常命中一个条目，粗切分导致答案被截断

### 3.2 医疗场景切分铁律
- **禁止语义截断**：剂量、禁忌、时限（"2-4 周复评"）必须完整保留在单 chunk 内
- **父子分块（Parent-Child）**：
  - 父块 = 完整条目（用于生成答案）
  - 子块 = 段落级（用于向量召回）
  - 检索命中子块 → 回引父块组装答案 → 引用精度高且上下文完整

### 3.3 风险分级标注（结构化的一部分）
每个条目打 `risk_level`：
- `emergency`：严重过敏反应识别、急救 → **触发强制就医引导**
- `caution`：配方选择、检测解读、辅食引入 → 答案必须附就医边界
- `low`：科普概念 → 正常回答

## 四、检索召回（Retrieval）

### 4.1 混合检索（Hybrid Search）是标配

```
Query ──→ 查询理解/改写
            ├─→ 向量检索（语义，bge-m3 / text-embedding）
            └─→ 关键词检索（BM25，医疗术语精确命中）
            └─→ 元数据过滤（年龄 / 模块 / risk_level）
            └─→ 图谱实体链接（消歧 + 一跳扩展）
                    ↓
            候选集融合（RRF 或加权）
```

- **为什么要 BM25**：医疗术语（"回避-激发试验"、"eHF"）是精确词汇，语义向量对术语匹配不可靠
- **为什么要查询改写**：家长口语 → 医学概念：
  - "宝宝吃了鸡蛋起红疹" → `鸡蛋过敏 症状 速发型`
  - "要不要做过敏原检测" → `过敏原检测 指征 无指征不查`
  - 改写失败时保留原 query 双路检索

### 4.2 医疗特有过滤
- **年龄过滤**：3 月龄婴儿不召回"2 岁辅食添加"类条目
- **模块路由**：先判定问题归属模块（急救 → 先命中 F 模块并触发护栏）
- **风险门控**：查询含"呼吸困难/休克/发绀"等词 → 直接走紧急响应通道

### 4.3 评估指标
- `Recall@k` / `MRR` / `NDCG@k`（通用）
- **医疗专项**：关键信息完整率（剂量/禁忌/时限是否都在召回结果中）、有害召回率（应召回急救条目的次数）

## 五、重排（Rerank）

### 5.1 两阶段架构

```
粗排（快）：向量 + BM25 RRF 融合 → Top 50
精排（准）：cross-encoder reranker → Top 5-8
            + 领域排序信号加权
```

### 5.2 领域排序信号（这是医疗 KB 与通用 KB 的核心差异）

| 信号 | 权重 | 说明 |
|---|---|---|
| 相关性（reranker 分数） | 高 | bge-reranker-v2-m3 等 |
| **证据级别** | 高 | guideline(5) > consensus(4) > RCT(3) > policy(2) > edu(1) |
| **区域优先级** | 中 | 同一问题国内共识优先（本土医疗体系） |
| 时效性 | 中 | 同级别取新版（2025 > 2022 > 2010） |
| 与 query 年龄/类型的匹配 | 中 | 元数据过滤后的加权 |
| 来源权威性 | 低 | 组织声誉加成（卫健委/学会 > 医院 > 机构） |

### 5.3 冲突处理规则（医疗特有）
- 多来源冲突时：**国内共识 > 国际指南**（如配方选择国内 AAF 经济性 vs DRACMA eHF 首选）
- 存在争议（如益生菌预防过敏）：命中"争议型"条目时，答案呈现**双方观点 + 不确定性**，而非单边结论

## 六、回答组装（Answer Generation）

### 6.1 Prompt 策略

```
系统角色：你是 minicare 敏宝助手，基于权威医学资料提供健康教育信息。
规则：
1. 不提供诊断、不开处方；涉及诊断/治疗建议必须引导就医。
2. 只能基于检索到的资料回答，资料中没有的明确说"资料中未找到"。
3. 每条关键结论标注来源（编号 + 出处 + 年份）。
4. 命中 emergency 级条目时，回答必须包含就医/急救指引，不得淡化风险。
5. 面向家长，语言通俗，避免术语堆砌，术语首次出现给解释。
```

### 6.2 答案结构模板（按风险分级）

| 级别 | 结构 |
|---|---|
| `low`（科普） | 直接结论 → 简要依据 → 可选扩展 |
| `caution`（指导） | 结论 → 依据（含来源）→ **可执行步骤**（怎么做）→ **就医边界**（什么情况要看医生）|
| `emergency`（急症） | **红色警示** → 立即行动（就医/急救）→ 不应做什么 → 来源 |

### 6.3 引用溯源
- 引用必须到**源文件+页码/条目**，前端可点击跳转（"查看来源"）
- 冲突/争议条目标注"多来源存在不同建议，以面诊医生为准"
- **防幻觉硬约束**：检索为空 → 明确回复"目前资料库中没有覆盖这个问题，建议咨询儿科医生"，禁止模型编造

### 6.4 多轮对话记忆
- 记住宝宝的年龄、已知过敏原、喂养方式 → 后续回答自动过滤
- 状态变更（如"宝宝确诊 CMPA 了"）→ 更新对话上下文中的风险画像

## 七、风险提示（Safety & Compliance）

### 7.1 分层安全架构

```
Layer 1 输入侧：高风险词识别（呼吸困难/休克/抽搐/嘴唇肿）
     ↓ 命中 → 直接返回急救引导，不进入常规 RAG
Layer 2 检索侧：risk_level 门控（emergency 条目强制进答案）
Layer 3 生成侧：prompt 硬约束（不诊断/不替代就医/必带来源）
Layer 4 输出侧：答案合规扫描（检测到诊断性断言 → 改写为就医引导）
```

### 7.2 合规要点（国内医疗 AI）
- **免责声明**：固定页脚"本内容基于权威指南整理，仅供参考，不构成医疗建议，具体诊疗请咨询医生"
- **不提供诊断**：不输出"你宝宝是 XX 病"；只输出"这些症状提示可能需要注意，建议就医排查"
- **个人信息保护**：宝宝健康数据属敏感个人信息，遵循《个保法》/《数据安全法》，对话数据最小化留存
- **内容审核链路**：知识条目需"来源 + 医学审核人 + 审核日期"三要素（已列入知识清单后续动作）

### 7.3 持续机制
- **医学内容定期复核**：全库 2 年一审，急救/配方/药物类 1 年一审（与源文件版本复核机制联动）
- **用户反馈闭环**：答案"不准确/不相关"反馈 → 回流到条目修订
- **风险事件告警**：高危问答（如家长描述严重过敏反应）触发记录与运营关注

## 八、落地路线图（结合 minicare 现状）

| 阶段 | 内容 | 产出 | 依赖 |
|---|---|---|---|
| **P0 数据层** | 20 份源文件解析清洗、元数据标注、条目化结构化 | 结构化知识库（JSON/Markdown 库） | 已就位的 20 份资料 |
| **P1 检索层** | 向量库 + BM25 混合检索、查询改写、元数据过滤 | 可回答 demo（Top-K 召回可看） | P0；嵌入模型选型 |
| **P2 生成层** | Prompt 模板、来源标注、免责页脚 | 家长可用的问答 MVP | P1 |
| **P3 增强层** | reranker + 冲突处理 + 风险分级护栏 | 质量达标的正式版 | P2 |
| **P4 图谱层** | 概念字典 → 实体链接 → 图谱扩展（GraphRAG） | 多跳推理、全局问答 | P3；按需启动 |

### 技术选型建议（腾讯云栈）
- 向量检索：**腾讯云向量数据库 / CloudBase AI 知识库**（与现有 CloudBase 生态一致）
- 嵌入模型：bge-m3（中文医学语义强）或腾讯混元 embedding
- 重排模型：bge-reranker-v2-m3
- 应用层：minicare-server（NestJS）提供 `/api/kb/ask` 接口，小程序端调用
- 或直接使用 CloudBase AI 智能体（自带知识库检索编排），降低自研成本

## 十、总结

```
最佳实践一句话：
  医疗 Agent 知识库 = 结构化+元数据（地基）
                    + 混合检索+图谱消歧（召回准）
                    + 证据加权重排+冲突特判（排序对）
                    + 分级组装+溯源引用（答得好）
                    + 四层安全护栏（不出事）
```

**针对敏宝的落地优先级建议：**
1. 先把 **P0 数据层** 做扎实（20 份资料条目化 + 元数据标注）—— 这是后面一切的前提
2. **风险护栏（七节）与检索评估（九节）应尽早搭骨架**，不要等功能完整后再补
3. 图谱从**概念字典 + 实体链接**起步，GraphRAG 看实际多跳需求再上
