# M5 · 每日日记（产品方案）

> 上级文档：[PRD-003](../prd/PRD-003.md) ｜ [TECH-006 v2.0](../tech/TECH-006-minicare-agent-plan.md)
> 状态：规划中 ｜ 优先级：P2（生成）/ P3（页面）

## 1. 模块背景与目标

健康记录是数据，但成长是故事。本模块把**当天记录（含图片）+ 对话内容 + 捕捉的生活事件**合成一篇温情日记——像爸爸妈妈自己写的那样，支持编辑、配图、永久回看。

**目标**：
1. 说一句"帮我写今天的日记"即得一篇温情日记；
2. 数据真实（来自记录）、事件真实（来自对话/用户补充），不编造；
3. 可编辑、可配图、每天一篇、永久保留。

## 2. 覆盖故事与业务规则

### 2.1 日记生成（US-08）

1. **前置条件**：已登录且绑定宝宝；当天至少一种素材（记录/对话/图片任一）。
2. **Happy Path**：
   - 触发：对话页说"帮我写今天的日记"，或日记页「写日记」按钮；
   - 素材三源：① 当天健康记录（数据聚合概览）② 当天记录与对话中上传的图片 ③ 当天对话捕捉的生活事件（如"今天带旺仔去露营了""游了泳"）；
   - 生成**日记文体**（温情叙事，如"今天旺仔胃口不错，喝了约 780ml 奶，下午我们去公园露营……"），可整合当天/近期总结分析结论（M4）；
   - 展示草稿 → 用户预览后可保存；
   - 保存后持久化、按日期组织、**每天一篇**、**永久保留**（删宝宝档案时清理），支持回看。
3. **异常处理**：
   - 当天无素材 → "今天还没有素材，可以先去记录或和我聊聊宝宝"；
   - 有生活事件无图片 → 提示"要不要上传一张照片，日记更有纪念意义"；
   - 无健康记录但有对话事件 → 生成生活日记，不编造健康数据；
   - 生成失败/超时 → 提示重试，不产生半截日记；
   - **同一天重复触发 → 重新生成并覆盖当天草稿/已保存日记，覆盖前需用户确认**。

### 2.2 日记编辑与照片补充（US-09）

1. **前置条件**：已有日记草稿或已保存日记。
2. **Happy Path**：编辑文字/补生活事件/加照片（相册选图，复用 COS 直传）→ 保存覆盖并记录更新时间。
3. **异常处理**：
   - 照片上传失败 → 保留正文，提示重试，不丢已编辑内容；
   - 编辑中退出 → 提示"有未保存的修改"，可保存/放弃；
   - 删除图片 → 从日记引用清理。

## 4. 验收标准

- **场景1: 生成**：当天有记录 + 对话提过露营 → "帮我写今天的日记" → 日记含数据概括 + 露营事件 + 温情口吻，数据与记录一致；
- **场景2: 持久化回看**：保存后从日记入口查看 → 按日期展示，内容一致；
- **场景3: 覆盖确认**：当天已有日记 → 再次生成 → 弹窗确认 → 确认后覆盖；
- **场景4: 编辑补充**：改文字/补事件/加照片保存 → 展示更新后内容；
- **场景5: 照片提醒**：有生活事件无照片 → 提示可上传照片；
- **场景6: 无素材**：当天无记录无对话 → "今天还没有素材"引导。
