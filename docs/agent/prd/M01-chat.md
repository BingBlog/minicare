# M1 · 对话会话与语音输入（产品方案）

> 模块：M1 ｜ 对应故事：US-01（进入对话）、US-10（多轮会话与中断恢复）
> 上级文档：[PRD-003](../prd/PRD-003.md) ｜ [TECH-006 v2.0](../tech/TECH-006-minicare-agent-plan.md)
> 状态：规划中 ｜ 优先级：P0（服务端）/ P3（UI）

## 1. 模块背景与目标

对话页是「敏宝助手」全部能力的统一入口。本模块解决"用户如何进入、如何连续对话、如何输入（文字/语音）、如何恢复会话"。

**目标**：
1. 一键进入对话，页面明确"在回答哪个宝宝"；
2. 支持文字与语音两种输入方式；
3. 多轮上下文连续、中断可恢复（最近 20 条）、切换宝宝即新会话。

## 2. 覆盖故事与业务规则

### 2.1 进入对话（US-01）

**入口**：TabBar 中央 FAB 弹出菜单「问敏宝助手」+ 首页快捷操作（可配置）。

**业务规则**：
1. 已登录且家庭有宝宝档案 → 进入对话页；
2. 未登录（游客）→ 登录引导，不提供对话能力；
3. 家庭无宝宝档案 → 引导建档，不进入；
4. 顶部**宝宝上下文条**：显示当前宝宝（姓名 + 出生日期 + 过敏摘要）；多宝宝家庭可切换，**切换即开新会话**；
5. 输入方式：
   - 文字：键盘输入发送；
   - 语音：长按麦克风 → 录音 → 转写为文字 → **发送前可编辑** → 发送（转写复用现有语音录入链路）。

**异常**：
- 服务未就绪 → "服务升级中"占位页，不崩溃；
- 语音转写失败（嘈杂/口音/未授权麦克风）→ 提示重试或转手动输入；
- 麦克风权限拒绝 → 提示并降级为文字输入。

### 2.2 多轮会话与恢复（US-10）

**业务规则**：
1. 回答后可连续追问，智能体结合上文作答；
2. 中途退出/断网 → 会话保存在服务端；
3. 再次进入 → 恢复最近一次会话，展示历史消息；
4. **历史会话永久保留，但可恢复/展示的仅最近 20 条**；更早会话不可恢复（提示开启新会话）；
5. 上下文过长 → 提示开新会话或自动截断，回答不中断；
6. 切换宝宝 = 必须开新线程（跨宝宝混用会污染上下文）；
7. 用户主动清空 → 删除该会话历史。

**异常**：会话恢复失败（服务重启/数据丢失）→ 提示无法恢复，可开新会话，不阻塞使用。

## 4. 验收标准

- **场景1: 正常进入**：已登录有宝宝 → 点入口 → 显示宝宝上下文条 + 输入框可用；
- **场景2: 未登录拦截**：游客点入口 → 登录引导，不进对话页；
- **场景3: 切换宝宝**：A→B → 会话清空为新线程，回答只引用宝宝 B 数据；
- **场景4: 语音输入**：长按说话 → 转写文字回填（发送前可改）→ 发送后正常对话；
- **场景5: 连续追问**：追问"那氨基酸配方呢" → 结合上文对比，不重复基础介绍；
- **场景6: 中断恢复**：对话 5 轮后退出，再进入 → 历史消息完整可继续；
- **场景7: 最近 20 条**：历史会话超过 20 条 → 仅最近 20 条可恢复，更早提示开新会话。
