## 0. 结论摘要

| # | 问题 | 根因一句话 | 归属 | 优先级 |
|---|---|---|---|---|
| 1a | 历史日记没有保存功能 | 存储链路（表/接口/页面）**已全部就绪**，但「生成」与「保存」是断开的两步，保存纯手动且不可发现；生产库 3 个月只写入 3 篇 | 小程序 + agent | P0 |
| 1b | 日记是纯文本无重点 | 详情页用 `<Text>{content}</Text>` 整段渲染，日记只有叙事没有结构化数据 | 小程序 + 数据模型 | P1 |
| 1c | 日期/保存时间不跟随 | **线上已发生真实错位**：内容写 9-18、落库日期 9-19 | 小程序 + agent prompt | P0 |
| 2 | 缺少宝宝整体画像 | systemPrompt 只注入 `familyId/babyId`，画像（过敏/当前喂养方式）从未进入模型上下文 | agent | P0 |
| 3 | 医疗/儿保变更后 tool 未同步 | `SELECT *` 导致字段随环境漂移；**生产库尚未应用 migration 020**，直接改 tool 会线上报错 | agent + 迁移 | P0（有前置依赖） |
| 4 | 进入/刷新停在顶部 | `scrollIntoView` 绑定 `useRef`，改 ref 不触发重渲染 → 首屏恢复消息后永远读不到目标 id | 小程序 | P0 |
| 5 | 缺医疗/儿保数据获取能力 | medical 维度只有条数、无分型；疫苗本进度/儿保测量/复查计划完全缺失；排敏无食材维度聚合 | agent | P1 |
| **6** | **日记列表点击不进详情**（二轮补充 1） | `DATE` 列经 mysql2 变成 ISO 串（`2026-09-18T16:00:00.000Z`），拼进 URL 后被详情接口的 `DATE_RE` 拒收 → 恒显示「这一天还没有日记」；**列表日期显示却是对的**，掩盖了问题 | 后端 + 小程序 | **P0** |
| **7** | **日记缺省写「今天」语义错误**（二轮补充 2） | 全部入口（首页卡/列表页/详情页/对话预置）都硬编码"今天"；agent 侧也无"默认昨天"规则。当天数据不全，日记应是回顾式总结 | 小程序 + agent | **P0** |
| **8** | **首页日记卡渲染闪动**（二轮补充 3） | `diaryLoading` 初值 `false` + loading 时 `return null` → 空态卡闪现 → 卡片消失（布局上跳）→ 内容卡再出现；每次返回首页都重演 | 小程序 | P1 |

**最关键的四个硬约束**：

1. **生产库未应用 migration 020** —— agent tool 任何引用 `vaccine_*` / `checkup_*` / `sick_*` 的改动，都必须等 020 上生产，否则线上报 `Unknown column`。
2. **日记日期错位是既成事实**，生产库存在脏数据需修复。
3. **画像注入必须带缓存**，否则每轮多一次 DB 查询会推高已优化到的 4.3-6.8s 时延。
4. **API 对外 DATE 字段必须收口为 `YYYY-MM-DD` 字符串**（问题 6 的根因）——服务端统一走 `formatSqlDate()`，前端加 `toDateOnly()` 兜底，并写入 `.agents/rules/api-conventions.mdc` 防复发。

## 0.1 问题分类：Bug 缺陷 vs 功能迭代

> v1.2 新增。分类依据是**问题性质**，与 §3 的执行顺序、下面的发版批次是两个正交维度。

**判定标准**

| 类型 | 定义 | 判据 |
|---|---|---|
| Bug 缺陷 | 已有明确预期的行为，实际表现错误 | 能写出「预期 → 实际」对照；同一份代码在正确环境下本应正常 |
| 功能迭代 | 此前不存在的能力或语义，需要新增设计 | 改造以「新增」为主，完成后是产品能力扩张 |

| 项 | 为什么不按字面归 |

| 问题 1a「历史日记没有保存功能」 | 用户感知是「功能缺失」，但**手动保存链路（表/接口/页面/按钮）已全部就绪**，缺的是自动闭环 → 归 F1 迭代，不算 bug。其中「按钮不可发现」与「正文含过程话术」另行归入体验项与 B7 |

**风险**：R8（用户习惯"写日记=今天"）。处置：空态文案显式写「昨天」，且明确说"写今天的"仍走今天。

### F1｜日记自动保存闭环 —— 简单，因为链路本来就齐了

> **实现方式已修正（v1.5）**：原设计要新增 `diary_draft` 事件，实现时判定**不必要**，改为
> **小程序侧在 `generate_diary` 完成后直接落库**。理由见本节末「为什么去掉 `diary_draft` 事件」。

**已就绪、无需重做**：

- 后端：`baby_diary` 表 + 5 个 REST 接口（`agent.service.ts`）
- 前端：`agentDiaryApi.save()`、手动保存 Draft 弹层（`draftText`/`draftOpen`/`savingDiaryDate`）、`ConfirmSheet` 确认组件
- B3 顺带完成：消息已挂上 `generate_diary` 的真实日期；`diaryRound` 标记已存在，前端**已能识别"本轮生成过日记"**

**实际改动**：

| # | 文件 | 改动 |
|---|---|---|
| 1 | `mp/src/pages/chat/index.tsx` | 新增 `persistMessages(patch)`（显式 patch 本轮状态，绕开 `messagesRef` 晚一拍的时序坑）与 `autoSaveDiary(msgId, text, date)`；`sendMessage` 累积 `answerText`/`roundDiaryDate`，`handle.promise` 结束后若 `wasDiaryRound && !aborted` 则自动落库 |
| 2 | `mp/src/pages/chat/index.tsx` | 新增 `looksLikeDiary()` 最后一道校验（≥40 字 **且** 含日期行）：防止把"今天记录很少，要不要我先看看？"这类答复当日记写进库 |
| 3 | `mp/src/pages/chat/index.tsx` | 消息新增 `diarySaved` 字段；渲染分支 `diarySaved` → 「已保存到日记 · 查看」（跳详情），否则 `diaryRound` → 原手动保存按钮 |
| 4 | `mp/src/pages/chat/index.scss` | `.chat-msg__diary-btn--saved` 完成态样式（弱化绿灰） |

**唯一的决策点**：自动保存 vs 自动弹确认。R4 已给答案 —— **首次自动存，已存在则弹确认**（复用现有组件）。

**为什么去掉 `diary_draft` 事件**（v1.5 修正）：事件方案要在 `runtime.js` + `routes/chat.js` + `api/agent.ts` 三处各加一段协议代码，而前端**本来就能**从已有 `tool_result(generate_diary)` 判断本轮是否生成日记、并拿到权威日期与正文。新增事件等于把同一事实用两条链路各传一遍，违反「单一真相源」。客户端落库后：

- agent 侧零改动，本轮发版不因 F1 增加任何协议面；
- 中断（用户手动停止）可自然跳过自动保存，避免存下半截正文 —— 事件方案反而要在 agent 侧判断中断；
- 保存失败静默，手动按钮仍作为兜底入口，不打断对话。

**代价（已接受）**：保存时小程序必须在前台（纯前端触发）。日记本就是家长在对话里当场看结果，可接受。

## 2. 逐条分析与方案

### 问题 1a｜历史日记没有保存功能

#### 现状（重要：能力已具备，闭环缺失）

| 环节 | 状态 | 位置 |
|---|---|---|
| 存储表 | 已有 | `migrations/018_baby_diary.sql`（`uk_baby_date` 每天一篇） |
| 后端 REST | 已有 5 个接口 | `minicare-server/src/agent/agent.controller.ts`（save/detail/list/:id/photos） |
| 小程序 API | 已有 | `minicare-mp/src/api/agent.ts` `agentDiaryApi` |
| 日记列表页 | 已有 | `pages/diary/index.tsx` |
| 日记详情/编辑页 | 已有 | `pages/diary/detail.tsx` |
| 对话页保存入口 | 已有（手动按钮） | `pages/chat/index.tsx` L626「保存为今天的日记」 |
| **agent 生成后自动落库** | **无** | `agent-poc` 全链路不写 `baby_diary` |

#### 根因

1. **保存是纯手动且不可发现**：按钮只在"本轮调用过 `generate_diary`"的消息下方出现（`diaryRound`），文案是「保存为今天的日记」。用户心智是"我说完写日记就该有了"，不会主动找按钮。
2. **离开会话 = 保存机会丢失**：`diaryRound` 随消息存在本地 Storage（`persist.slice(-40)`），一旦会话超出 40 条或清缓存，历史消息里的日记就再也存不进日记本。
3. **没有"已保存"状态**：按钮点完无痕迹，无法区分哪条已存、哪条未存。
4. **一篇覆盖**：同一天多次生成，后端 upsert 覆盖，用户以为"写了多篇都没了"。

#### 方案（P0：把保存做成闭环，两选一）

**方案 A（推荐，改动小、体验稳）：对话内自动保存 + 明确回执**

1. agent 侧新增 SSE 事件 `diary_draft`（在 `runtime.js` 检测到 `generate_diary` 工具调用后，把该次调用的 `input.date` + 最终正文一并下发）：
   ```
   event: diary_draft
   data: { date: "2026-09-18", content: "<净化后的日记正文>", autoSave: true }
   ```
2. 小程序 `chat/index.tsx` 收到 `diary_draft` 后：
   - 调 `agentDiaryApi.detail(familyId, babyId, date)` 判断当天是否已有日记
   - 无 → 直接 `save()` 并 toast「已存入 9月18日的日记」
   - 有 → 进入现有草稿面板，提示「9月18日已有日记，是否覆盖？」
   - 消息下方按钮变为状态标识「已保存 · 查看日记」→ 点击跳 `pages/diary/detail?date=…`
3. 保留手动草稿面板（用户想改文字再存）。

**方案 B（备选）：仅修文案与状态** —— 按钮改「存入宝宝日记」+ 保存后显示已保存态。改动更小，但"用户没点就丢"的问题依旧。

> 不建议让 agent 直接写 `baby_diary`（需给 agent 写权限，破坏"只读连接池"的安全边界，见 M08-ops）。

#### 附带修复：日记正文净化

`extractDiaryBody()` 目前只剥离末尾追问话术，需补一条**开头净化**（对齐 `runtime.js` 的准备语剔除规则）：
```
^(\s*(好的|好嘞|收到|我来|我先|让我)[^\n]{0,40}(～|~|。|，|：|:))+\s*
```
并过滤纯过程句（"…已经整理好了"）。存量脏数据（8-25 那条）需人工修正或删重写。

### 问题 4｜对话框进入/刷新时停在顶部

#### 根因（已定位到行）

```tsx
// chat/index.tsx
L133: const scrollIdRef = useRef('')
L278-282:
  useEffect(() => {
    if (messages.length > 0) {
      scrollIdRef.current = `msg-${messages[messages.length - 1].id}`   // ← 改 ref，不触发渲染
    }
  }, [messages])
L725: <ScrollView ... scrollIntoView={scrollIdRef.current}>              // ← 永远读到上一次的值
```

执行顺序问题：
1. `setMessages()` → 重渲染，此时 `scrollIdRef.current` 还是**旧值**（`useEffect` 尚未执行）
2. `useEffect` 更新 `scrollIdRef.current` → **不触发重渲染**
3. ⇒ `scrollIntoView` 永远慢一拍

**首屏场景彻底失效**：`loadChat()` 一次性 `setMessages(restored)`，此后没有新的 `setMessages`，`scrollIntoView` 保持为空字符串（首次渲染时 ref 初值），页面就停在顶部。流式对话时因每次 delta 都触发重渲染，恰好能"追上"，所以只有**进入页面/刷新**暴露——与用户描述完全一致。

#### 方案

```tsx
// ① 改为 state（触发渲染）
const [scrollTarget, setScrollTarget] = useState('')

// ② 列表尾部放哨兵，最稳（避免最后一条消息 id 的渲染时序问题）
<View id='chat-bottom-sentinel' />
<ScrollView scrollY scrollWithAnimation scrollIntoView={scrollTarget}>

// ③ messages 变化时滚到底
useEffect(() => {
  if (!messages.length) return
  // 同一值不会触发 ScrollView 变化 → 先清空再设置
  setScrollTarget('')
  const t = setTimeout(() => setScrollTarget('chat-bottom-sentinel'), 50)
  return () => clearTimeout(t)
}, [messages.length, messages[messages.length - 1]?.content])

// ④ 首屏恢复后再滚一次（等布局完成）
useEffect(() => {
  if (loading || !messages.length) return
  Taro.nextTick(() => setScrollTarget('chat-bottom-sentinel'))
}, [loading])
```

补充建议：
- 键盘弹起（`keyboardHeight` 变化）后也应滚底 —— 加进 ③ 的依赖
- 保留 `scrollWithAnimation`，进入页面建议首次用 `scrollWithAnimation={false}` 瞬移，避免长列表动画抖动

### 问题 6｜日记列表点击不进详情（二轮补充 1）

#### 根因（已用 mysql2 实测确认）

`database.module.ts` 的连接池**未配置 `dateStrings`**，mysql2 会把 `DATE` 列解析成 **JS `Date` 对象**。实测（dev 库，与线上同一份连接配置）：

```
DB   baby_profile.birth_date = '2025-12-28'
  → 驱动原始值   : 2025-12-27T16:00:00.000Z     (constructor = Date)
  → JSON 出口    : "2025-12-27T16:00:00.000Z"

DB   medical_record.visit_date = '2026-01-06'
  → JSON 出口    : "2026-01-05T16:00:00.000Z"
```

而 `agent.service.ts` 的日记接口**没有**像 `medical.service.ts` L55 那样调用 `formatSqlDate()`

故障链（逐行可查）：

| 步 | 位置 | 结果 |
|---|---|---|
| 1 | `agent.service.ts` L221 `diary_date: r.diary_date` | 返回 `"2026-09-18T16:00:00.000Z"` |
| 2 | `diary/index.tsx` L22 `friendlyDate()` 经 dayjs 解析 | **显示成 9月19日，看起来完全正确** |
| 3 | `diary/index.tsx` L193-197 `url: /pages/diary/detail?date=${item.diary_date}` | URL 里带上了 ISO 串 |
| 4 | `agent.service.ts` L192 `DATE_RE.test(date)` (`^\d{4}-\d{2}-\d{2}$`) | **校验失败 → throw** |
| 5 | `detail.tsx` L60 `catch { setDetail(null) }` | 静默落到「这一天还没有日记」空态 |

⇒ 用户感知的"点不进去"，实际是**跳过去了但永远显示空日记**。

> **第 2 步的巧合是关键**：`DATE '2026-09-19'` 被解析成本地午夜，序列化成 UTC 少 8 小时，dayjs 再按浏览器本地时区转回来，正好抵消——所以列表日期长期"看着是对的"，掩盖了底层值根本不是日期字符串。只有把它**当参数回传**时才会暴露。

#### 方案

**① 后端根治（对齐项目既有约定）**

`formatSqlDate` 已存在于 `src/common/utils/date.util.ts`，`medical` / `vaccine-book` / `timeline` 都在用，`main.ts` 也已设 `process.env.TZ='Asia/Shanghai'`，可安全按本地分量取日期。

```ts
// agent.service.ts
import { formatSqlDate } from '../common/utils/date.util';

// getDiaryDetail（L202）
return { ...row, diary_date: formatSqlDate(row.diary_date), photo_ids: row.photo_ids ? row.photo_ids.split(',') : [] };

// listDiary（L221）
diary_date: formatSqlDate(r.diary_date),
```
> 只改这两处，不动全局 `dateStrings`（全局改会波及所有 DATETIME 的消费方，且 `'YYYY-MM-DD HH:mm:ss'` 在 iOS 上 `new Date()` 会 NaN，风险大）。

**② 前端兜底（防御任意来源的脏日期）**

新增 `src/lib/date.ts`：
```ts
/** 任意日期值 → YYYY-MM-DD（ISO / Date / 字符串均安全） */
export function toDateOnly(v: unknown): string {
  if (!v) return ''
  const s = String(v)
  if (/^\d{4}-\d{2}-\d{2}$/.test(s)) return s
  return dayjs(v as string).format('YYYY-MM-DD')
}

/** 昨天（业务默认日记日期） */
export const yesterdayStr = () => dayjs().subtract(1, 'day').format('YYYY-MM-DD')
```
使用点：`diary/index.tsx` 跳转、`detail.tsx` 解析 `params.date`、`TodayDiaryCard` 跳转。

**③ 约定沉淀（防复发）**
`.agents/rules/api-conventions.mdc` 补一条硬规则：**对外的 DATE 列一律为 `YYYY-MM-DD` 字符串**，服务端由 `formatSqlDate()` 收口，禁止直接透传驱动返回的 `Date` 对象。

**④ 同类隐患扫描结论（本次已全量核对）**

| 模块 | 现状 | 判断 |
|---|---|---|
| medical / vaccine-book / timeline | 服务端已 `formatSqlDate()` | 安全 |
| growth | 服务端返回 ISO，前端 `isoToLocalDate()` 转换 | 可用，风格不统一 |
| food-observation | 前端 `dayjs().format('YYYY-MM-DD')` 转换 | 可用，风格不统一 |
| **diary** | **服务端未格式化 + 前端未转换** | **本次 bug** |

| agent 侧规则 | `prompts/system.js` | 无"写日记默认昨天"的任何约定 |

**为什么必须是昨天**：日记定位为「当日回顾式总结」。当天 23 点前数据（尤其睡眠、最后一顿奶、全天总量）都不完整——线上已有真实案例（09-18 02:38 就生成"今天"的日记，全天只有 420 毫升素材）。

#### 方案：把「昨天」做成贯穿 UI 到 agent 的唯一缺省语义

**① 前端所有写日记入口统一带上目标日期**

```ts

// 详情页 goRegen（该篇自己的日期，不是昨天）

// 首页 TodayDiaryCard：查询日期、跳转日期、文案全部改"昨天"
const yesterday = yesterdayStr()
onClick={() => Taro.navigateTo({ url: `/pages/diary/detail?date=${yesterday}` })}
<Text className='home-diary-card__title'>昨天的日记还没写</Text>
<Text className='home-diary-card__excerpt'>和敏宝助手说一句「帮我写昨天的日记」</Text>
```

**② 对话页 preset 支持日期参数**

```tsx
// chat/index.tsx L267-275
if (params.preset === 'diary') {
  presetDiarySentRef.current = true
  const d = toDateOnly(params.date) || yesterdayStr()
  void sendMessage(`帮我写 ${fmtCnDate(d)} 的日记总结`, [])

```

**③ agent 侧：缺省日期 = 昨天（在 1c③ 基础上强化）**

`prompts/system.js` 日期规则追加：
```
【写日记默认日期】用户说"写日记 / 记录一下 / 写个日记总结"且未明确指定日期时，

```
同时进入页面的预置消息已经显式带了日期，双保险。

### 问题 8｜首页日记卡渲染时闪动（二轮补充 3）

#### 根因（渲染时序）

`diaryLoading` 初值为 `false`（`home/index.tsx` L79），而卡片在 loading 时 **`return null`**（`TodayDiaryCard.tsx` L16）：

```
t0  首屏渲染      diaryLoading=false, todayDiary=null
                  → 渲染「今天的日记还没写」空态卡
t1  loadTodayDiary() → setDiaryLoading(true)
                  → 卡片 return null  →卡消失，下方 QuickActions 整体上移
t2  接口返回       setDiaryLoading(false) + setTodayDiary(item)
                  → 卡片重新出现，内容切为「今日日记 + 摘要」
```

用户看到的即：**空态卡闪现 → 消失（内容上跳）→ 内容卡出现**。

`useDidShow` 每次从子页面返回首页都会重跑 `loadTodayDiary`，`setDiaryLoading(true)` 会再次触发同样的消失/出现——所以不止首次进入会闪。

#### 方案

**① 加载期不卸载卡片，改用等高骨架**（消除布局跳动）

```tsx
// TodayDiaryCard.tsx
if (loading) {
  return (
    <View className='home-card home-diary-card home-diary-card--skeleton'>
      <View className='home-diary-card__badge'><Text className='home-diary-card__badge-text'>记</Text></View>
      <View className='home-diary-card__body'>
        <View className='home-diary-card__sk-line home-diary-card__sk-line--title' />
        <View className='home-diary-card__sk-line' />
      </View>
    </View>
  )
}
```
骨架复用 `home-card` 外框与相同内边距/行高 ⇒ **卡片高度恒定，零位移**；shimmer 动画只挂在 `--skeleton` 修饰类上。

**② `diaryLoading` 初值改 `true`**（与页面 `loading` 同步，避免先闪一帧空态）

**③ 二次进入不再进 loading 态**（从详情页返回时静默刷新）
```ts
const diaryLoadedRef = useRef(false)
// loadTodayDiary 内：
if (!diaryLoadedRef.current) setDiaryLoading(true)
// finally：
diaryLoadedRef.current = true
setDiaryLoading(false)
```

**④ 顺带修复：`diary:changed` 无人监听**
`chat/index.tsx` L567 与 `detail.tsx` L142 都在 `Taro.eventCenter.trigger('diary:changed')`，但**全项目没有任何 `on('diary:changed')`**。结果是刚保存完日记回到首页，卡片仍是旧内容。应在 `home/index.tsx` 补监听：
```ts
useEffect(() => {
  const h = () => { if (familyId && babyId) loadYesterdayDiary(familyId, babyId) }
  Taro.eventCenter.on('diary:changed', h)
  return () => { Taro.eventCenter.off('diary:changed', h) }
}, [familyId, babyId, loadYesterdayDiary])
```

#### 验收
- [ ] 冷启动进首页，日记卡全程**只出现一次**，无消失、无下方内容位移
- [ ] 从日记详情返回首页，卡片不闪且内容即时更新
- [ ] 弱网下显示骨架而非空白或空态文案跳动
