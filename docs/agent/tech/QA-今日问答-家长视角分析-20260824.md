# 今日 Agent 回答家长视角分析（8/24 会话）

> 分析对象：`QA-今日问答记录-20260824.md` 中 Q2「生成最近 7 天总结」、Q3「帮我写今天的日记」
> 视角：妈妈 / 爸爸 / 爷爷奶奶
> 日期：2026-08-24

---

## 零、先还原家长"看到"的是什么

在小程序聊天页里，回答以 markdown 渲染。家长真实看到的不是"排版精美的总结"，而是：

- 一堆 `**加粗**`、`#` 标题、`| 表格 |` 符号（渲染不全时直接暴露符号本身）
- 大段数字（5610ml、5111分钟、12.2小时、223分钟、117分钟……）
- emoji（📋🍼😴🧷📏❤️🩺🏃⚠️💛🌙📷）——老人手机字号大，表格横向溢出，部分 emoji 可能变方块

结论：**回答是"给人看的报表"，不是"说给人听的话"。**

---

## 一、最刺眼的问题：开头结尾各有一句"废话"（流式拼接 bug）

Q2 原文开头：

> 好的，我来帮您汇总宝宝最近 7 天的记录～**好的，数据已经整理好了**，这是宝宝最近 7 天的总结👇

Q2 原文结尾：

> 本回答仅供参考，不能替代专业医疗建议。**好的，我已在为您生成宝宝最近 7 天的数据总结，等数据整理好我马上把完整总结发您～**

Q3 同理（开头"我先帮您聚合一下…再动笔写日记～好的，…已经整理好了"，结尾"好的，我正在为您整理…稍等一下，马上为您写出今天的日记～"）。

### 家长体验
- 开头连续两个"好的"，啰嗦、像口吃。
- 结尾更荒谬：**总结都发完了，又说"马上把完整总结发您"**。家长会困惑："这是没发完？还是发重了？还是助手坏了？"
- 这种自相矛盾对信任感是**致命**的——一个"发没发完都搞不清"的助手，家长敢信它的育儿建议吗？

### 定性
技术 bug（流式中间状态文本被拼入最终 content），但它是所有格式问题的**放大器**——内容再好，结尾这半句就毁掉全部可信度。**必须优先修。**

## 二、格式问题

### 1. 结构像"数据库报表导出"，不像人话
Q2 按维度机械罗列：喂养 → 睡眠 → 尿布 → 生长 → 健康 → 表现 → 活动，每个维度都是"数字 + 一句模板化点评"。家长（尤其妈妈）要的第一个信息是：**"宝宝这周到底过得好不好？有没有要担心的？"**——这个结论被埋在文末，且说得含糊。

### 2. 表格在手机上不可读
- 异常记录表有 5 列（日期/项目/记录值/前后均值/说明），窄屏挤压成条，老人字号下根本没法看。
- 表格是"给运维看的"工具，不是"给家长看"的。

### 3. emoji 无规范、字体风险
📋📏🧷 等在小程序端可能缺字体显示成方块；emoji 使用也没有统一的情感/场景规范，视觉上杂乱。

### 4. markdown 符号依赖渲染
组件渲染稍有不全，`**`、`#`、`|` 直接裸露，对家长=乱码。

## 三、内容问题（逐条）

### 1. "数据口径""记录条数"是技术词，不是家长语言
- "最近 7 天共 **111 条记录**，涵盖喂养、睡眠、尿布、健康、表现等维度"
- "（50 条记录）""（48 条记录）"、"数据口径："
- 家长视角："111 条"是什么？我又不是运营。"口径"这个词，爷爷奶奶完全看不懂。
- 应换成："这周宝宝一共被记录了 111 次，喂养和睡眠记得最全"这种自然说法。

### 2. 给了数字，但没给"所以呢？"
- Q2：**"日均 800ml 这个量对配方喂养的宝宝在常见参考范围内，但具体是否合适要看月龄和生长曲线"** ——说了等于没说。家长问"这正常吗？"，回答"看情况"。
- Q2："这个时长比较符合小月龄宝宝的睡眠需求"——全文没提宝宝几个月，12.2 小时到底合不合适没给判断。
- 家长要的是："挺好的，不用担心"或"偏少了，建议留意"这种**有结论**的话。

### 3. 异常记录提示"系统化"，家长看了焦虑且不知该干嘛
原文：

> ⚠️ 系统提示 2 条可能的异常记录，请确认
> | 8/17 | 睡眠 | 264 分钟 | 约 735 | 偏差超 50%，可能是误录…… |

家长视角：
- "偏差超 50%""前后均值"是什么？735 又是啥？
- **8/17 睡眠只有 264 分钟（4.4 小时）**——如果宝宝平时睡 12 小时，家长第一反应是**担心**，不是看到"可能是误录"。
- 这个提示本应是全场最高价值的信息，现在做成了"数据核对工单"，家长看完不知道该干嘛。
- 更好说法："8/17 那天宝宝睡眠只有约 4 个半小时，比平时少很多。可能是宝宝不舒服，也可能是记录有误。需要我帮您查一下那天的明细吗？"

### 4. 日记不是日记，是数据流水账
家长要"日记"，期待：有温度、叙事性、能保存回味的文字。
实际给的：
- 喂养：3 行"时间 + 毫升"
- 睡眠：5 行"时间段 + 分钟"
- 照片：无
- 小结：一句话

**这不是日记，是"今日记录明细"。** 妈妈看完不会觉得"写得好想保存"，只会觉得"这不就是我自己记录的吗？我要 AI 干嘛？"
日记应把数据翻译成"宝宝的一天"：夜里睡了整觉、上午小睡、喝奶规律，再配上家长想听的贴心话。

### 5. 暴露系统能力局限，破坏信任
Q3 原文：

> 系统显示今天共有 5 条喂养记录，但明细里只展开了 3 笔。如果还有亲喂或加餐，记得随手补一下，让喂养记录更完整～

家长视角："有 5 条你只给我 3 条？为什么？还要我自己补？"
这种话不该出现在面向用户的回答里。要么补全数据再答，要么换措辞（"今天还有 2 次记录没展开，方便告诉我是什么吗？"）。

### 6. 结尾"免责声明 + 催促记录"组合奇怪
Q2 结尾："本回答仅供参考，不能替代专业医疗建议。" 紧接"尿布和症状记录偏少，如果想让总结更完整，可以多记两笔。"
家长感受：你一边跟我免责，一边让我多干活？语气像"客服推责 + 数据催办"。

### 7. 时间戳堆砌，毫无可读性
Q3 睡眠部分连列 5 个时间段（20:53 / 00:00–01:14 / 01:20–05:03 / 05:40–06:38 / 09:58–11:54），纯数字轰炸，老人看头晕。
应归纳成："夜里睡得长、白天睡了两觉，作息规律。"

## 四、分角色解读

### 妈妈（核心使用者）
- 想要：一眼看到"宝宝状态好不好" + 有温度的日记。
- 不满：全是表格数字、没有结论、"要看月龄和生长曲线"这种踢皮球回答。
- 失望：日记没有情感共鸣，看不到"今天宝宝睡得很香"的画面。

### 爸爸
- 相对能接受数据，但同样需要结论。
- 会注意到异常提示，希望知道"要不要处理、怎么处理"，却只看到"偏差超 50%"。
- 不耐烦"数据口径""均值"这种半懂不懂的词。

### 爷爷奶奶（最容易流失的用户）
- 最不友好的一组：markdown 符号、表格、术语（配方奶/亲喂/浅睡/均值/口径）全部超纲。
- "12.2 小时""5610ml"这些数字没有意义。
- 他们只需要一句话大白话："娃这周吃得好、睡得好，都挺好，不用操心。"

---

## 五、根本原因（是什么导致这些）

1. **prompt 没有引导"面向家长下结论"**——agent 默认按"数据维度"组织，像 BI 报表，不像育儿助手。
2. **缺少"结论先行"结构**——应先说结论（整体状态+关注点），再给要点，最后才给可选明细。
3. **没有区分提问者角色**——不知道对面是妈妈/爸爸/老人，统一模板应对。
4. **流式拼接 bug 污染内容**——开头结尾的重复"好的"是技术问题，非内容设计问题。
5. **"日记"的 prompt 定义错了**——当成"数据汇总"，没有"叙事"要求，才输出流水账。
6. **异常/风险没有"家长翻译层"**——把系统内部指标（偏差、均值）直接抛给用户。

---

## 六、改进方向（摘要）

1. **修流式拼接 bug**（前置项，否则一切格式优化都白做）。
2. **总结回答重写**：一句话结论（"这周整体很好/注意X"）→ 2~3 个关键点 → 可选明细。
3. **日记回答重写**：叙事化，把数据翻译成"宝宝的一天"，带温度、可保存。
4. **术语降维**：全换家长能懂的话（"喝了差不多800ml"而不是"日均800ml"）。
5. **异常提示只展示对家长有意义的**：给"这意味着什么 + 建议动作"，不给"偏差超50%"。
6. **排版按手机渲染优化**：少表格、少 emoji、控制篇幅。
7. **结尾自然收尾**：去掉"免责+催办"组合，改成贴心话。
