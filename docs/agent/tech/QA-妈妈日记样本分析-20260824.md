# 妈妈日记样本分析（旺仔三篇）

> 参考样本：旺仔妈妈手写的三篇同日（2026-08-23，7个月26天）日记
> 用途：优化 agent 日记生成的 prompt / few-shot
> 日期：2026-08-24

---

## 一、三篇样本全文对照

### 篇 1「旺仔小日记✨」— 温馨口语风

```
旺仔小日记✨

📅2026.08.23｜旺仔7个月26天
宝贝新冠刚刚好，身体还在慢慢回血💪

昨天小旺仔下午状态蔫蔫的，哼哼唧唧，睡得断断续续，小觉都睡得不安稳。可怜的小家伙还被蚊子偷袭，身上叮了好几个红红的小包，看着都心疼🥺

奶量还没有完全恢复到之前的水平，全天喝了750ml配方奶，每顿150ml。有一顿乖乖喝了五勺奶，喝完却吐了一小口，小胃胃还在恢复期，不能太着急。

睡眠总时长13小时13分，夜里睡得还算安稳，白天小觉碎碎的，一会儿睡一会儿醒。
```

## 二、结构拆解（三篇的共同骨架）

三篇风格迥异，但**骨架完全一致**，这是妈妈们写日记的天然结构，可直接作为 agent 日记生成模板：

| 段落 | 内容 | 篇1示例 | 篇2示例 | 篇3示例 |
|---|---|---|---|---|
| ① 标题 | 名字+日记类型 | 旺仔小日记✨ | 旺仔搞笑育儿日记🤪 | 旺仔记 |
| ② 日期行 | 日期+月龄 | 2026.08.23｜旺仔7个月26天 | 同左 | 丙午年七月十二｜旺仔七月廿六日 |
| ③ 总起 | 当日身体/状态总述 | 新冠刚刚好，身体还在慢慢回血 | 小勇士新冠刚通关归来，原地回血 | 甫愈新冠，元气未复 |
| ④ 状态描写 | 精神状态（情绪/睡眠状态） | 蔫蔫的、哼哼唧唧、睡得断断续续 | 哼哼唧唧模式、小觉七零八落 | 咿唔不宁，昼寝断续 |
| ⑤ 意外事件 | 当天特别的事（蚊子叮） | 被蚊子偷袭，叮了好几个红红的小包 | 惨遭蚊子大军偷袭，喜提N个红包 | 复为蚊虫所噬，遍体红疱 |
| ⑥ 喂养 | 奶量/辅食/恢复情况 | 全天750ml，每顿150ml，有一顿吐了一小口 | 干饭进度条没拉满…吃进去又还回去 | 乳食未复旧量…胃腑尚弱 |
| ⑦ 睡眠 | 睡眠总时长+质量 | 13小时13分，夜里安稳，白天小觉碎碎的 | 13小时13分，白天碎得像饼干渣 | 昼夜眠时凡十三时十三分…数醒数睡 |
| ⑧ 结尾 | 祝愿/期望 | 希望蚊子远离，安安稳稳睡个好觉 | 蚊子退退退，大口干饭睡整觉 | 愿蚊蚋远避，儿得安寝，徐徐养脾胃 |

**八段式结构 = 妈妈们公认的"好日记"模板。** 当前 agent 的日记 few-shot 只有"叙事化的一天"（①③④⑦），缺少标题、日期行、意外事件、喂养恢复状态、结尾祝愿这些段落。

## 三、可复用的写作手法（agent 应该学）

### 1. 用数据讲"状态"，而不是报数字
- 篇1："身体还在慢慢回血"（而不是"昨日恢复中"）
- 篇2："小胃胃罢工，哐当吐出来一小口，主打一个吃进去又还回去"
- 篇3："元气未复""胃腑尚弱"
- 关键：**数据（750ml、13h13m）作为叙事素材，服务于"宝宝今天状态如何"的结论**

### 2. 意外事件是日记的灵魂
三篇都写了"蚊子偷袭"。这类事件来自**用户对话中提到的事实**，不是数据。说明 agent 写日记时：
- 必须利用会话上下文（历史消息）里用户提过的事件
- 绝不能编造（现 generate_diary 的 note 已约束"只写用户明确提到的事实"）

### 3. 喂养/睡眠描述要结合"恢复期"背景
- 三篇都把"吐了一小口""白天小觉碎"与"新冠刚好"关联，读起来有逻辑
- agent 应把异常记录放在"身体恢复"语境下解释，而不是孤立列数字

### 4. 结尾有祝愿，日记才有温度
- "希望蚊子远离我的小旺仔，今晚可以安安稳稳睡个好觉"
- "蚊子退！退！退！今晚旺仔可以大口干饭"
- "愿蚊蚋远避，儿得安寝，徐徐养其脾胃"

## 五、需要确认的决策点

### 决策 1：emoji 用不用？
- 妈妈真实日记（篇1/篇2）用了 emoji（✨💪🥺🌙🤪🦟🔚😂），篇3文言文没用
- 项目规范明确 "No emojis anywhere (code, data, API responses)"
- **问题**：agent 日记是否允许 emoji？还是保持无 emoji（符合项目规范）？

### 决策 2：风格如何定？
- 三种风格差异极大（温馨 / 搞笑 / 文言）
- **选项 A**：固定温馨风（最通用，妈妈主流选择）
- **选项 B**：让用户选择风格（few-shot 里放多个风格示例 + 用户可切换）
- **选项 C**：默认温馨，用户可在对话中要求"换搞笑风/写文言"

### 决策 3：宝宝名字和月龄哪里来？
- generate_diary 当前返回 records/photos，**没有宝宝名字和月龄**
- 需要扩展工具查询 baby_profile（name + birth_date → 月龄），或由 minicare-server 在 ctx 注入
- **问题**：是否本次一并扩展？

### 决策 4：意外事件来源
- 蚊子事件来自对话上下文，不是数据
- agent 写日记时，应从**该会话的历史消息**中提取用户提到的事件
- 当前历史通过 systemPrompt 注入，模型可见，但工具 note 只约束了"不编造"
- **问题**：是否需要强化"从对话提取事件写入日记"的 prompt 规则？
