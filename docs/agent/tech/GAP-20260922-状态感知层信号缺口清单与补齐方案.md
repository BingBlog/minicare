## 1. 先说一个必须先解决的问题：PRD 的「41」对不上 —— ✅ 已修订

PRD §4.3 标题写「10 组 / **41 个信号**」，但同节的 §4.3.1 分组总览表自身加总是：

```
A5 + B7 + C5 + D8 + E7 + F5 + G4 + H2 + I3 = 46   （+ J 的 8 个 flag = 54）
```

而且表里的「信号数」与各小节实际列出的条目也对不上（组 D 标 8 却只列 6 项；组 E 标 7 却列了 8 项）。

**这意味着"补齐"目前没有终点定义** —— 按 41 算还是按 54 算，会差出一整组的工作量。**建议先修 PRD 这一处的自相矛盾，再谈补哪些。**

## 3. 缺口归因：三类，代价完全不同

| 类型 | 含义 | 涉及缺口 | 代价 |
|---|---|---|---|
| **① 数据源没接线** | 库里明明有数据，代码没读 | `allergy_symptoms`（腹泻真在里头）、`poop_type`、`head_mm`、`food_observation_log`、`supplement_items`、`birth_weight_g` 渲染、组 G 计数 | **低**：改 SQL + 加渲染，零迁移、零界面改动 |
| **② 规则没写** | 数据够，判定逻辑没做 | flag #1/#4/#5/#6/#7、覆盖率、频控、护栏、判定优先级链、`highRiskIntroduced`、`velocity`/`wfh` | **中**：纯服务端派生；频控需存状态（要落库） |
| **③ 外部阻塞** | 缺字段或未上生产 | 组 A 的诊断确定性 / 家族过敏史（**migration 022**）、`vaccineProgress`（**020 未上生产**） | **高**：被迁移与产品决策卡住 |

### 6.2 口径决策（本可以含糊过去，但必须写死）

| 项 | 决定 | 理由 |
|---|---|---|
| `mealRhythm` | 近 7 天**有记录日**的平均每天进食次数（奶顿数 + 辅食顿数），**不给达标结论** | 餐次随月龄与个体差异大，行业无共识阈值 |

| 头围分位 | 复用小程序同一份头围表 | 单一真相源；已加跨仓逐值断言 |

| 分型缺失 | 标"未采集"，**不硬锁定推进** | 字段不存在，假装锁定等于把缺失包装成结论 |
