## 6. 用户故事详述 (User Stories)

> 阅读说明：每个故事自包含业务规则、异常路径、验收标准；涉及 UI 的故事附 ASCII 线框图（草稿待评审）。

### 阶段一：目标确权

---

#### **US-20: 作为敏宝家长，我希望知道"我们最终要走到哪、现在走到哪了"，以便于在漫长的忌口期里看到盼头**

* **价值陈述 (Value Statement)**:
  * **作为** 一位正在给敏宝忌口/转奶的家长
  * **我希望** 在进入助手时就看到一张属于我宝宝的"回归普通饮食"里程碑地图与当前所处位置
  * **以便于** 我知道这场持久战有多长、现在在哪一步、下一步是什么
* **业务规则与逻辑 (Business Logic)**:
  1. **前置条件**：宝宝档案存在且已记录过敏原（`baby_profile.allergy_types` 含 `milk` 或家长明确说明）。
  2. **里程碑定义（单向推进，允许长期停留）**：

| 里程碑 | 名称 | 达成判定 |
|---|---|---|
| M0 | 稳定回避期 | 单一医学配方稳定 ≥14 天且无活跃症状 |
| M1 | 具备转奶条件 | US-22 的 8 项条件全部满足 |
| M2 | 完成首次降阶（第 1 瓶达标） | 第 1 顿新配方占比 100%，累计达标奶量 ≥200ml，无异常 |
| M3 | 全天替换当前阶 | 全天顿次全部为新配方，稳定 ≥14 天 |
| M4 | 阶梯再下一级 | 重复 M2-M3，阶位下移一级 |
| M5 | 回到普通配方 | 当前主导 `milk_type = std` 稳定 ≥30 天 |
| M6 | 食物谱达标 | 归一化后已耐受食材 ≥ 同龄推荐种类数，且高致敏食物均已成功引入 |

  3. **进度呈现规则**：每个里程碑显示"已达成/进行中/未解锁"三态；进行中的里程碑显示**已完成天数与预计总天数**（用区间，如"约 1-2 周"），不给精确倒计时（模板化预测会造成不必要的焦虑）。
  4. **不做排名与对比**：只与本宝宝的历史比，绝不与其他宝宝横向比较（敏宝家长对"别人家孩子"高度敏感）。
  5. **异常处理**：
     - 数据不足（无配方记录）→ 里程碑显示"待补充记录"，并给出一次记录引导，不猜测。
     - `allergy_mechanism` 未知 → M2 之后的内容**展示为锁定态**，提示"需先确认过敏类型，可与医生确认后回来更新"。
     - 中途回退（症状复发）→ 进度条**不回退已达成里程碑**（M2 已达成即保留），但当前阶段标记为"重来中"，文案用中性表达"我们回到更稳妥的台阶"。
* **验收标准 (Acceptance Criteria)**:
  * **场景1: 首次进入看到地图**
    * **GIVEN** 宝宝档案存在、机制分型已知、当前为纯 eHF 稳定 34 天
    * **WHEN** 家长打开助手的里程碑页
    * **THEN** 显示 M0 已达成、M1 进行中（并给出当前满足情况）、M2 及之后未解锁，不出现任何其他宝宝的数据
  * **场景2: 机制未知时锁定**
    * **GIVEN** `allergy_mechanism` 为空
    * **WHEN** 家长查看里程碑
    * **THEN** M1 之后显示锁定，并给出"如何确认过敏类型"的可执行说明与更新入口
  * **场景3: 回退后文案**
    * **GIVEN** 已达成 M2，之后出现中重度反应进入冷却期
    * **WHEN** 家长再次查看
    * **THEN** M2 保持已达成状态，当前进度显示"重来中"，且不出现"失败/白费"类措辞
* **页面布局线框图 (ASCII Wireframe)**:
```text
┌──────────────────────────────────────┐
│  ← 旺仔的回归计划                    │
├──────────────────────────────────────┤
│  已停氨基酸 34 天 · 当前：深度水解含乳糖 │
│  ████████░░░░░░░░░░░░  第 2 / 7 步    │
├──────────────────────────────────────┤
│  ● 稳定回避期            已达成        │
│  │  单一配方稳定 14 天以上             │
│  ● 具备转奶条件          进行中        │
│  │  还差：最近 6 个月未再出现便血       │
│  ○ 完成首次降阶          待解锁        │
│  │  需要先确认过敏类型                 │
│  ○ 全天替换当前阶                     │
│  ○ 阶梯再下一级                       │
│  ○ 回到普通配方                       │
│  ○ 食物谱达标                         │
├──────────────────────────────────────┤
│  [ 查看我能做什么 ]   [ 确认过敏类型 ]  │
└──────────────────────────────────────┘
```

### 阶段二：起点体检

---

#### **US-21: 作为敏宝家长，我希望助手明确记录我宝宝的过敏类型与确诊情况，以便于所有建议都建立在正确的前提上**

* **价值陈述 (Value Statement)**:
  * **作为** 家长
  * **我希望** 一次性把"过敏类型（IgE / 非 IgE / 混合 / 未知）、是否医院确诊、确诊时间、家族过敏史"填清楚
  * **以便于** 助手不会在不知道类型的情况下给出冒险的建议
* **业务规则与逻辑 (Business Logic)**:
  1. **前置条件**：宝宝档案存在。
  2. **采集方式**：对话式逐项确认（每轮最多问 2 项，避免表单感）；提供"我不确定，怎么查"的说明（看医生诊断、激发试验结论、化验单上的 sIgE / 皮肤点刺结果）。
  3. **落库字段（新增，migration 022 建议）**：

| 字段 | 表 | 取值 | 说明 |
|---|---|---|---|
| `allergy_mechanism` | `baby_profile` | `ige` / `non_ige` / `mixed` / `unknown` | **决定是否允许家庭阶梯（P0 阻断项）** |
| `allergy_diagnosed` | `baby_profile` | `self_reported` / `hospital_diagnosed` | 决定断言强度 |
| `allergy_diagnosed_at` | `baby_profile` | DATE | 用于计算"已管理时长" |
| `family_atopy_history` | `baby_profile` | JSON 数组 | 家族过敏史（最强遗传风险信号） |

  4. **分型影响规则（核心）**：
     - `non_ige` → 允许进入家庭阶梯流程（仍提示"建议在医生指导下"）；
     - `ige` / `mixed` → **禁止**输出家庭阶梯推进方案，改为"需要医院监督下的口服激发/引入"，并引导至专科；
     - `unknown` → 先走"确认分型"引导，期间只提供知识科普与记录能力。
  5. **异常处理**：
     - 家长填错 → 任何字段可二次修改，修改后**重新触发依赖它的计划校验**（如把 non_ige 改成 ige，正在进行的计划立即置为"暂停-需医生评估"）。
     - 家长拒绝填写 → 允许跳过，但所有推进类能力保持锁定，并在相关回答中说明原因（不反复追问，最多每 7 天提示 1 次）。
* **验收标准 (Acceptance Criteria)**:
  * **场景1: 填为 non_ige**
    * **GIVEN** 家长确认"医生说是迟发型、做了回避激发确诊"
    * **WHEN** 提交
    * **THEN** 落库 `allergy_mechanism=non_ige`、`allergy_diagnosed=hospital_diagnosed`，里程碑页 M1 解锁，转奶能力可用
  * **场景2: 填为 ige**
    * **GIVEN** 家长确认"喝奶半小时内起荨麻疹，医生说是速发型"
    * **WHEN** 提交
    * **THEN** 落库 `ige`；任何转奶/引入类请求返回"需在专科医生监督下进行"的引导，**不生成任何逐日计划**
  * **场景3: 修改分型**
    * **GIVEN** 正在进行家庭转奶计划
    * **WHEN** 家长把分型从 non_ige 改为 ige
    * **THEN** 计划立即置为"暂停-需医生评估"，后续对话不再推进该计划
* **优先级**：P0（**安全前置项**） ｜ **分期**：第 1 期（最迟第 3 期前） ｜ **依赖**：migration 022

---

#### **US-22: 作为敏宝家长，我希望助手帮我在转奶前做一次逐项体检，以便于我不会在不该转的时候开始**

* **价值陈述 (Value Statement)**:
  * **作为** 家长
  * **我希望** 得到一份基于我宝宝真实数据的"能不能开始转奶"的检查清单
  * **以便于** 避免过早转奶导致症状复发、白受罪
* **业务规则与逻辑 (Business Logic)**:
  1. **前置条件**：`allergy_mechanism = non_ige`；存在 `food_observation` 与 `formula_mix` 历史。
  2. **检查项（8 项，服务端计算，不由模型自行推断）**：

| # | 检查项 | 判定依据（数据源） | 未满足时的可执行建议 |
|---|---|---|---|
| 1 | 回避时长 ≥6 个月 | `formula_mix` 中致敏配方消失的连续天数；或 9-12 月龄以上 | 继续当前配方，给出还需等待的时间区间 |
| 2 | 症状已完全消失且稳定 | 近 30 天 `symptom_record` / `health_record.allergy_symptoms` / `diaper_record.poop_type ∈ (bloody, watery)` 无记录 | 逐项确认"最近是否还有这些表现" |
| 3 | 生长正常 | `growth_record` 最新分位（复用 `growth.js`，P3-P97）与趋势 | 建议先做一次身高体重测量 |
| 4 | 已顺利添加辅食 | `feeding_food_item` 近 30 天去重食材数 ≥ 3 | 先完成基础辅食引入 |
| 5 | 当前健康 | 近 7 天无发热/腹泻/湿疹活动期记录 | 等恢复后再开始 |
| 6 | 近期未接种疫苗 | 近 7 天 `medical_record.visit_type='vaccine'`（**依赖 migration 020 上生产**） | 顺延至接种后 1 周 |
| 7 | 家长可全天观察 | 对话确认（是否有空在上午/中午开始） | 建议选一个闲一点的上午 |
| 8 | 医生已知情 | 对话确认 | 给出复诊沟通要点 |

  3. **输出规则**：逐项显示"通过 / 待确认 / 未通过"；**只要有任何一项"未通过"，不生成计划**，只输出"还差什么 + 现在可以做什么"。
  4. **数据不可用降级**：第 6 项在生产迁移 020 完成前标记为"待人工确认"，不影响其他项判定；不得因字段缺失而误判为通过。
  5. **异常处理**：
     - 症状数据陈旧（如 31 天无记录）→ 标记为"信息不足"，走对话确认，**不得当作"无症状"直接放行**（区分"无记录"与"数据陈旧"）。
     - 家长坚持要开始 → 助手说明风险后尊重决定，但记录为"家长自主决定"，后续出现反应时优先建议就医。
* **验收标准 (Acceptance Criteria)**:
  * **场景1: 全部通过**
    * **GIVEN** 回避 34 天以上、近 30 天无症状、生长 P50-P85、已加辅食、近 7 天无不适与接种
    * **WHEN** 家长发起转奶
    * **THEN** 8 项全部显示通过（或待确认项经对话确认为通过），并给出"生成转奶计划"的入口
  * **场景2: 存在未通过项**
    * **GIVEN** 近 3 天有腹泻记录
    * **WHEN** 家长发起转奶
    * **THEN** 明确列出"当前健康"未通过，给出顺延建议，**不生成计划**
  * **场景3: 症状数据陈旧**
    * **GIVEN** 症状记录距今 31 天，但大便性状填写率仅 22%
    * **WHEN** 判定第 2 项
    * **THEN** 标记为"信息不足-需确认"，以提问方式请家长确认最近表现，不得直接判为通过
  * **场景4: 尝试越过分型直接要计划**
    * **GIVEN** `allergy_mechanism = ige`
    * **WHEN** 家长直接说"给我一个转奶计划"
    * **THEN** 不生成逐日计划，改为输出"需医院监督"的说明与就诊准备清单
* **页面布局线框图 (ASCII Wireframe)**:
```text
┌──────────────────────────────────────┐
│  ← 转奶前体检                        │
├──────────────────────────────────────┤
│  旺仔 · 8 个月 22 天 · 迟发型(non-IgE) │
├──────────────────────────────────────┤
│  ✓ 回避时长     已停氨基酸 34 天       │
│  ✓ 症状稳定     近 30 天无异常记录      │
│  ✓ 生长正常     体重 P50-P85 平稳      │
│  ✓ 已加辅食     近 30 天 12 种食材      │
│  ✓ 当前健康     近 7 天无不适           │
│  ! 疫苗接种     生产库暂无明细，请确认   │
│  ? 观察时间     今天上午方便观察吗？     │
│  ? 医生知情     上次门诊是什么时候？     │
├──────────────────────────────────────┤
│  还有 2 项待确认 [ 现在确认 ]           │
│  [ 生成转奶计划 ]  ← 未全部通过时禁用    │
```

### 阶段三：转奶推进

---

#### **US-23: 作为敏宝家长，我希望助手直接告诉我"今天第 1 顿放几勺新配方"，以便于我不必自己去理解转奶方法**

* **价值陈述 (Value Statement)**:
  * **作为** 家长
  * **我希望** 得到一份可直接照做的逐日转奶计划（第几天、第几顿、新旧配方各几勺）
  * **以便于** 操作标准化、出现反应时能准确归因
* **业务规则与逻辑 (Business Logic)**:
  1. **前置条件**：US-22 的 8 项全部通过；已知当前阶与目标阶（相邻阶，不可越级）。
  2. **计划生成算法（7 天第一瓶奶转换法 + 200ml 临界点）**：
     ```
     目标顿次 = 第 1 顿（默认）
     D1: 新 1 勺 + 旧（剩余勺数）
     D2: 新 2 勺 + 旧
     ...
     D7: 新配方占满第 1 顿
     判定：若第 1 顿奶量 >= 200ml → 可全天替换
           若 < 200ml → 以第 2 顿作为下一个转换目标，累计达标奶量 >= 200ml 后再全天替换
     ```
  3. **参数取值来源（不猜测）**：
     - 每顿总勺数与奶量：取近 7 天 `feeding_formula_mix` 的该顿真实均值（无数据时请家长确认一次）；
     - 观察期默认 7 天，可由家长调长（不允许短于 7 天）；
     - 目标阶由当前阶自动推断（`aa→eh_*→ph→std`），阶内乳糖变化（`eh_no_lactose → eh_lactose`）视为等同于转奶流程，需单独确认。
  4. **计划呈现**：以"日历 + 逐日卡片"呈现，今日任务置顶；每张卡包含：日期、顿次、新旧勺数配比、观察要点（皮肤/大便/精神/呼吸道）、"今天没问题"与"有情况"两个按钮。
  5. **互斥约束（写入计划本身）**：计划生效期间，系统**自动挂起**所有新食物引入任务与疫苗接种提醒，并在家长尝试违反时给出明确提示。
  6. **异常处理**：
     - 家长当天没喂新配方 → 计划顺延，不视为失败，不跳过该天。
     - 某顿未记录 → 次日提醒一次补记，仍无记录则该天标记"未完成"，**不自动推进**。
     - 计划跨度超过 21 天（如每顿都 <200ml 需逐顿转）→ 重新评估是否需要医生介入，并给出"与医生确认是否需要调整方案"的建议。
* **验收标准 (Acceptance Criteria)**:

#### **US-25: 作为敏宝家长，我希望出现反应时助手能告诉我"是继续、减量还是马上停"，以便于我不会因为慌张而放弃整个计划**

* **价值陈述 (Value Statement)**:
  * **作为** 家长
  * **我希望** 得到分级明确的处置意见（可继续观察 / 同阶减量 / 退回上一阶 / 立即就医）
  * **以便于** 既不因轻微变化而全盘放弃，也不因轻视而延误
* **业务规则与逻辑 (Business Logic)**:
  1. **前置条件**：存在进行中的计划；已记录反应信号。
  2. **分级处置矩阵（服务端判定 + 医学知识库支撑）**：

| 反应等级 | 典型表现 | 处置 | 计划状态 |
|---|---|---|---|
| 高危（立即就医） | 呼吸困难/喉部水肿、大面积荨麻疹、精神萎靡、便血量大、频繁呕吐致脱水 | 立即停止转奶/引入 + 就医引导 + 不再讨论进度 | 中断-待医生评估 |
| 中重度 | 便血/黏液便、明显腹泻（次数显著增多）、湿疹明显加重、持续拒奶 | 停止当前阶 + 退回**上一已耐受阶** + 2-3 个月后重试 | 已回退 → 冷却期 |
| 轻微 | 局部红点、少量风团、轻微胀气、大便略稀但无血、鼻塞打喷嚏 | **同阶减量**（退回前一日配比）继续观察 | 减量观察 |
| 不明确 | 家长描述模糊或与转奶时间关系不清 | 维持原配比观察 1-2 天，**重试同一食物/配比验证可复现性** | 不变 |

  3. **判定要点（必须告知家长的规则）**：
     - **可复现才算反应**：怀疑某阶食物致敏时，等 1-2 天重试同一配比，症状重现才判定；
     - **轻微变化不等于失败**：排便习惯小改变、胀气略多属可继续观察范围；
     - **不叠加变量**：判定期间不得同时引入新食物、接种疫苗。
  4. **升级与留痕**：中重度以上事件写入症状情节记忆，并在 US-30 复诊摘要中自动出现；高危事件同时触发就医引导 + 提示"可用复诊摘要给医生看"。
  5. **异常处理**：
     - 家长自述与记录矛盾（说"没事"但记录里写了便血）→ 以记录为准并温和指出，请其确认。
     - 家长情绪激动/自责 → 优先情绪承接与事实梳理，不输出长篇规则。
     - 助手无法判断 → 明确说"这种情况我判断不了，建议就医"，**不允许猜测式安抚**。
* **验收标准 (Acceptance Criteria)**:
  * **场景1: 轻微反应**
    * **GIVEN** 转奶 D3，家长反馈"有几颗小红点，其他都正常"
    * **WHEN** 走分级判定
    * **THEN** 判定为轻微 → 同阶减量回 D2 配比 → 计划状态"减量观察"，并告知观察多久、什么情况升级
  * **场景2: 中重度反应**
    * **GIVEN** 转奶 D5，出现黏液便
    * **WHEN** 走分级判定
    * **THEN** 停止转奶 + 退回上一已耐受阶 + 设定冷却期（≥2 个月），冷却期内请求重试被拒绝并说明原因
  * **场景3: 高危信号**
    * **GIVEN** 家长描述"嘴唇有点肿、呼吸有点快"
    * **WHEN** 走分级判定
    * **THEN** 立即输出就医引导，**不追问进度、不提供继续计划的操作**，计划置为中断
  * **场景4: 可复现验证**
    * **GIVEN** 家长单次反馈轻微不适
    * **WHEN** 助手处置
    * **THEN** 引导 1-2 天后重试同一配比，而不是直接判为过敏
* **优先级**：P0（安全） ｜ **分期**：第 3 期 ｜ **依赖**：US-24、M07 护栏、症状分级能力

#### **US-26: 作为敏宝家长，我希望助手告诉我"哪些食物已经真的安全，一共多少种"，以便于我不会被重复建档的记录误导**

    * **WHEN** 家长查看清单
    * **THEN** 显示"记录还比较少，暂时看不出规律"，不给出耐受结论

#### **US-27: 作为敏宝家长，我希望助手给我排一个不冲突的引入时间表，以便于我不要在转奶或打疫苗的时候踩坑**

* **价值陈述 (Value Statement)**:
  * **作为** 家长
  * **我希望** 系统统一安排"什么时候转奶、什么时候加新食物、避开疫苗和生病窗口"
  * **以便于** 出现症状时我知道是哪个变量引起的
* **业务规则与逻辑 (Business Logic)**:
  1. **前置条件**：US-26 的可吃清单可用。
  2. **串行规则（排敏的基本功）**：
     - 一次只引入一种新食物；观察期默认 3 天，可配 3-7 天；
     - 观察期内不引入任何其他新食物；
     - 已耐受食物可正常吃（不受限）。
  3. **档期互斥矩阵（服务端校验）**：

| 活动 | 与新食物引入 | 与转奶 |
|---|---|---|
| 转奶进行中 | **互斥** | — |
| 疫苗接种前后 7 天 | **互斥** | 互斥 |
| 生病/发热期 | 互斥 | 互斥 |
| 观察期未结束 | 互斥 | 互斥 |

  4. **引入顺序建议（循证导向：尽早、规律、足量，而非一味延迟）**：
     - 优先富铁辅食（强化铁米粉类）；逐步过渡到蔬菜 → 肉泥 → 蛋黄/全蛋 → 鱼虾 → 小麦/大豆 → 花生/坚果（**适龄形态，绝不给整粒坚果**）；
     - 高致敏食物（蛋/小麦/大豆/花生/鱼虾/坚果）单独标记为"需重点观察"，其中"重度湿疹或已有鸡蛋过敏"的宝宝提示"首次引入建议在专科指导下进行"。
  5. **异常处理**：
     - 家长想同时加两种 → 阻止并解释归因原理（不是硬性禁止，说明后果后尊重决定，但标记为"归因不可用"）。
     - 到达复引入日期（`retry_after_date`）→ 生成"可以再试一次"的建议，但不自动开始。
     - 与转奶计划冲突时，按"先转奶、后排敏"排序（转奶有明确窗口期与成本压力），并在计划页说明原因。
* **验收标准 (Acceptance Criteria)**:
  * **场景1: 冲突拦截**
    * **GIVEN** 转奶计划进行中
    * **WHEN** 家长要求今天加南瓜泥
    * **THEN** 提示冲突，给出"当前优先完成转奶，预计 X 天后可引入"的排期建议
  * **场景2: 串行执行**
    * **GIVEN** 小米粉刚进入观察期第 1 天
    * **WHEN** 家长要求再引入牛肉
    * **THEN** 阻止并说明"一次只加一种"，提供"等小米粉观察期结束（还剩 2 天）"的信息
  * **场景3: 高致敏食物分流**
    * **GIVEN** 宝宝有重度湿疹史，家长要加花生
    * **WHEN** 生成建议
    * **THEN** 提示"建议在专科医生指导下首次引入"，并给出复诊要点，不输出"在家怎么做"的操作细节
  * **场景4: 复引入到期**

| **agent** | 护栏 prompt + 出口校验**协同**（模型自觉 + 服务端兜底）；拒答与转向话术；越界输出漏报事件记录 | P0 |
| **服务端** | 出口校验拦截器（兜底，可独立于模型生效）；计划非法跃迁拒绝；调整动作留痕 | P0 |

### 阶段七：状态感知与主动提示（横切能力）

> 本阶段不对应某一段独立旅程，而是贯穿全部阶段的**感知层**（设计契约见 [§4](02-能力设计.md)）。编号放在最后，但**实施顺序必须最先**——它是 US-20~US-32 的共同前提。

#### **US-33: 作为敏宝家长，我希望助手一开口就知道我宝宝现在在哪个阶段，以便于我不必每次重复交代背景**

* **价值陈述 (Value Statement)**:
  * **作为** 一个已经记录了几个月数据的敏宝家长
  * **我希望** 助手开口就带着我宝宝的真实前提（配方阶位、喂养模式、排敏进度、生长趋势）
  * **以便于** 我不用每次先叙述一遍背景，也不会收到"默认母乳喂养"这类与我无关的建议
* **业务规则与逻辑 (Business Logic)**:
  1. **前置条件**：宝宝档案存在；至少有 1 组信号可用（否则走 `data_insufficient`，见 [§4.4](02-能力设计.md)）。
  2. **感知范围**：按 [§4.3](02-能力设计.md) 的 P0 组采集——A 基本情况、B 配方与转奶、C 喂养方式、D 排敏进度、E 生长、I 数据新鲜度、J 矛盾检测；F/G/H 逐次补齐。
  3. **注入形态**：按 [§4.7](02-能力设计.md) 契约注入「事实 + 推断 + 注意事项」三段，**不复述原始明细**（不回读记录清单、不用"你的记录显示…"话术）。
  4. **阶段判定**：按 [§4.4](02-能力设计.md) 的**优先级顺序**输出唯一一个当前阶段（护栏 > 数据不足 > 分型 > 活跃计划 > 空档），供里程碑页（US-20）、计划引擎与今日行动卡（US-24）共用同一结论——**全产品只允许一套阶段结论**。
  5. **断言强度随确诊情况变化**：`allergy_diagnosed = self_reported` 时统一用「如怀疑」口径，不下「过敏」定论；分型 `unknown` 时不输出任何进度承诺。
  6. **数据变更即刷新**：家长新增喂养/排敏/生长记录后，该宝宝画像缓存**主动失效**（最长 5 分钟），避免"刚记完助手还按旧情况说话"。
  7. **多宝宝隔离**：画像以 `babyId` 为键，家庭内切换宝宝即切换画像，**严禁跨宝宝复用**（与 PRD-003「切换宝宝即开启新会话」一致）。
  8. **异常处理**：
     - 某组信号查询失败 → 该组置空并标 `degraded`，其余组照常注入，回答中不暴露内部字段名；
     - 全量失败 → 使用保守默认（不默认母乳、不带任何进度断言）；
     - **反向异常**：已停母乳的宝宝被建议母乳喂养，属最高优先级缺陷（家长信任代价最大）。
* **验收标准 (Acceptance Criteria)**:
  * **场景1: 已停母乳的宝宝**
    * **GIVEN** 母乳记录 0 条、最后一次母乳记录在 34 天前、当前纯 eHF 稳定 34 天
    * **WHEN** 家长问"宝宝辅食能加什么"
    * **THEN** 回答先确认是否在排敏观察期，默认带 CMPA 前提，**全程不出现"母乳喂养 / 混合喂养"表述**
  * **场景2: 阶段结论三端一致**
    * **GIVEN** 同一时刻打开里程碑页、首页行动卡与对话
    * **WHEN** 三者分别渲染
    * **THEN** 阶段结论完全一致（不得出现首页说"可体检"、对话说"再等等"）
  * **场景3: 单组降级不影响对话**
    * **GIVEN** 医疗组因生产库未应用 020 而降级
    * **WHEN** 家长问"上次儿保怎么样"
    * **THEN** 只给计数与"详细评估项暂不可用"，其余画像正常生效，无报错、无字段名泄漏
* **页面布局线框图 (ASCII Wireframe)**:

#### **US-34: 作为敏宝家长，我希望助手能主动点出我记录里的矛盾，并且知道什么时候不该下结论，以便于我不会被自己的记录误导**

* **价值陈述 (Value Statement)**:
  * **作为** 家长
  * **我希望** 助手能发现我自己看不出来的问题（记录自相矛盾、任务烂尾、数据太少）
  * **以便于** 我不会拿着"看起来没事"的记录做出错误的推进决定
* **业务规则与逻辑 (Business Logic)**:
  1. **检测项**：[§4.5](02-能力设计.md) 的 8 个 flag（过敏食材仍在食用、排敏任务停滞、排敏窗口重叠、转奶停滞、停滞期出现反应、配方阶梯上移、生长分位下降、关键数据陈旧）。
  2. **计算归属**：**服务端算好直接给模型**，模型不做跨表推断（省 token、保一致）。
  3. **提示频控**：单轮最多 1 条；同一 flag 7 天内不重复；强度为「强」的项不受此限，可直接打断当前话题。
  4. **三态输出（核心规则）**——"没有数据"分三种，输出必须不同：

| 状态 | 判定 | 输出 |
|---|---|---|
| 有效结论 | 该维度确实为 0 且有历史 | 可下确定结论（例：已完全停止母乳） |
| 信息缺失 | 无记录但无法排除 | **不下结论**，提示可补记录（例：症状 31 天无记录 → "判断不了最近情况"，而非"无症状"） |
| 数据陈旧 | 有记录但超阈 | 结论带时效限定（例："按最近一次测量"） |

  5. **覆盖率限定**：`coverage.rate < 50%` 时不做任何阴性结论，降级为提问（实测：大便性状填写率仅 22%，便血 0 条**不得**当作"无便血"）。
  6. **措辞规范**：flag 提示只描述现象与选项，不替家长做决定，且不使用"失败 / 白费 / 你没做好"类措辞。
  7. **异常处理**：
     - 家长表示"现在不想聊这个" → 该 flag 静默 7 天，不再提醒；
     - flag 误报（家长纠正） → 记录修正原因并纳入回归用例；
     - 强提示被忽略但风险持续 → 下次对话以更明确的方式重提**一次**，此后转为复诊摘要（US-30）中的显性条目。
* **验收标准 (Acceptance Criteria)**:
  * **场景1: 停滞任务提示**
    * **GIVEN** 火龙果观察任务 day 2/3 停在 14 天前
    * **WHEN** 家长问一个无关问题（如"今天奶量够吗"）
    * **THEN** 回答主体正常，可在结尾附 1 条停滞提示并给"现在补上"入口；不刷屏、不并列罗列其他 flag
  * **场景2: 不得下阴性结论**
    * **GIVEN** 大便性状记录填写率 22%
    * **WHEN** 家长问"最近还有没有便血"
    * **THEN** 不回答"没有"，改为说明记录不足并给出补记录引导
  * **场景3: 过敏食材仍在食用（强提示）**
    * **GIVEN** 芹菜已标记"疑似（轻度）"，但近 14 天仍在 `feeding_food_item` 中出现
    * **WHEN** 家长描述"这两天有点起疹子"
    * **THEN** 主动指出两条记录的矛盾，建议暂停该食材并咨询医生；**不受"单轮 1 条"限制**
  * **场景4: 频控生效**
    * **GIVEN** 同一 flag 当天已提示过
    * **WHEN** 同日再次对话
    * **THEN** 不再提示，除非该 flag 升级为强提示
* **优先级**：P0（元信号层是 R10 的直接落地） ｜ **分期**：第 1 期 ｜ **依赖**：[§4.5](02-能力设计.md) / [§4.6](02-能力设计.md)、US-31 数据护栏

**三层改动（阶段七 · 状态感知与主动提示，横切能力）**

| 层 | 改动 | 优先级 |
|---|---|---|
| **助手** | 开口即知阶段（**不反问、不复述背景**）；主动点出记录矛盾（单轮 ≤1 条、同 flag 7 天去重、强提示可打断）；元信号**三态表述**（有效结论 / 信息缺失 / 数据陈旧） | P0（**实施顺序最先**） |
| **小程序** | 首页 / 里程碑页显性展示"当前阶段 + 需要注意"（是否显性见 [§14](05-风险与决策.md)-7）；数据新鲜度与覆盖率提示 | P1 |
| **agent** | **注入契约**：感知块进 systemPrompt（阶段判定 + flags + 元信号）；flags 消费；**模型不自算任何信号** | P0 |
| **服务端** | 聚合入口（约 7 条 SQL + 5 分钟 TTL，**写记录后主动失效**）；**判定顺序即优先级**（护栏 > 数据不足 > 分型 > 活跃计划 > 空档）；8 个矛盾 flag；覆盖率 <50% 不下阴性结论；多宝宝隔离 | P0 |
