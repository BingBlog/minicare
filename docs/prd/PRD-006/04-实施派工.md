## 8. 三层功能改动清单（助手 / 小程序 / agent）

> 本章是**实施派工的唯一入口**。每一项能力都同时给出四个层面的改动，四层的口径见 [主文档「三层改动视角」](README.md)。
> 判定某条改动归谁：**数据怎么进 → 小程序；判断怎么做 → 助手；信号怎么算 → 服务端；模型怎么表述 → agent**（详见 [§3.1](02-能力设计.md) 职责矩阵）。

### 8.2 助手层改动（对话产品）

**输入侧（注入）**
- 接入 [§4.7](02-能力设计.md) 注入契约：当前阶段判定 + 8 个 flag + 元信号（三态）+ 数据新鲜度/覆盖率
- 注入当前日期（解决“未指定日期默认昨天”的兜底）
- 保留 familyId / babyId 上下文，多宝宝隔离

**输出侧（三种结构化块）**
- 行动卡：今日这一件事 + 主按钮
- **建议卡**：`kind` 枚举至少覆盖 `reaction_grade` / `delay_task` / `plan_draft` / `profile_field` / `today_action`；含 `confidence` 与 `expiresAt`
- 数据卡：分位 / 趋势 / 可吃清单 / 计划进度

**口径侧（红线落地）**
- 未确诊一律「如怀疑」；数据缺失或陈旧**不得给阴性结论**；高危优先就医引导
- 成本一律"档位级参考价，按常见价位估算"，**不指向任何品牌**
- 专业术语全部家长语言化；单轮只呈现"今天这一件事"

**交互侧**
- 起手先复述它理解的问题，确认后再回答
- 提示频控：单轮最多 1 条；同 flag 7 天去重；强提示白名单（[§4.5](02-能力设计.md)）

**边界侧（本版新增的硬约束）**
- **不调用任何写工具**；不改计划状态；不代家长执行动作
- 分析结论必须能落成建议卡回到界面，否则不输出
- 语音录入与对话完全解耦（不产生 chat 历史、不关联 `sessionId`）

### 8.4 agent 层改动（`agent-poc`）

**工具（只读，本版不新增任何写工具）**
- 新增/升级：`get_baby_goal_profile`（**状态感知聚合入口**，含 `milestone` / `flags` / `freshness`）、`check_transition_readiness`、`get_today_actions`、`get_benefit_ledger`、`build_doctor_summary`
- 扩展：`query_baby_data` 增 `aggregate=foods` 与 `formula_mix` 构成序列
- **明确不作**：任何对话写库工具。以下 5 个已明确排除，**不得恢复**：`log_food_observation` / `mark_reaction` / `log_feeding` / `update_transition_plan` / `set_baby_allergy_profile`

**Prompt**
- `src/prompts/system.js` 增加"感知块"段与口径段（红线、断言强度、不指品牌、家长语言化）
- 注入当前日期

**事件协议与建议卡**
- SSE 通道新增 `event: block`，承载行动卡 / 建议卡 / 数据卡
- 建议卡 schema 由 agent 产出（`adviceId` / `kind` / `summary` / `target` / `confidence` / `expiresAt`）
- 低置信（`confidence=low`）时**禁止**生成"一键采纳"型卡片

**知识库**
- 入库：中国指南 7 天第一瓶奶转换法、iMAP / NHS milk ladder、LEAP 早期引入与维持暴露证据、分级处置矩阵的家长语言版

**评估与观测**
- `evals/` 新增用例组：感知三态表述、护栏与拒答、**建议卡不写库**、三端结论一致、语音不入会话
- R1 基线需重跑；**改判分逻辑须删除 `.deepeval-cache.json`**
- 保留 transcript → Langfuse 链路；建议卡产出进 telemetry

## 12. 范围、优先级与分期

> 本章解决一个具体问题：**§8 的改动清单（约 80 个改动点）既不能全做，也不能只按"重要程度"排序派工**。
> 结论先行：把改动按"性质"分三档（§12.3），再按"依赖 + 规模上限"排成 **5 期 + 1 条并行轨**（§12.4），第 1 期还能再切出最小切片（§12.5）。

### 12.1 为什么必须分档

改动点总量：§8.1 矩阵 20 行 × 4 层 ≈ **80 个改动点**，另有 2 个 migration、6 个新增页面/组件、5 个新/改工具。这些改动**性质完全不同**，混在一起排不出可执行的顺序：

| 性质 | 例子 | 应有的位置 |
|---|---|---|
| **不可绕过的前置**（不做则后续返工） | 分位下沉、排敏五态统一、感知聚合 | 最先做，但**用户看不见** |
| **安全底线**（不做会误导或致病） | 机制分型、元信号三态、护栏出口校验 | 与"第一个可见能力"同批 |
| **只是重要**（价值高但不阻塞） | 里程碑页、收益账本 | 明确后置 |

因此本章先按"性质"分三档（§12.3），再按"依赖 + 规模上限"排成期次（§12.4）。

### 12.2 评估口径

五维打分，每维 0-3：

| 维度 | 含义 |
|---|---|
| **前置性 P** | 不做它，后续是否无法开工或必须返工 |
| **安全 S** | 不做是否会误导家长或带来医疗风险 |
| **价值 V** | 家长能否直接感知 |
| **成本 C** | 工作量 × 跨层协调成本（**越大分越高**，综合分里作减项） |
| **可验证 E** | 能否在单端/单案例验证，而不依赖长周期数据、线下医生或用户授权 |

**分档规则**（先看两道门，再看价值；规则可复核，不做加权平均）：

| 档 | 判定 | 含义 |
|---|---|---|
| **甲** | `P = 3` **或** `S = 3` | 返工门 / 安全门 → 必须先做 |
| **乙** | 非甲，且 `V = 3` | 价值兑现 → 随后成组推进 |
| **丙** | 其余 | 可后置，或需外部条件 |

`综合 = 3P + 3S + 2V + E − 2C` **仅用于同档内排序**，不是优先级结论本身。
因此个别乙档条目的综合分低于丙档条目 —— 分档看的是**性质**，综合分看的是**同档内的先后**。

**每期都有用户可感知的变化**，避免"做了一大堆、用户没感觉"：
- 第 1 期虽不动界面，但**对话回答质量立刻变化**（不再谈母乳、不再报错分位、区分"没记录"与"陈旧"）——这是最快能验证方向是否正确的一期；
- 第 2 期的可见性来自"建议能点、两端同数"；
- 第 3-5 期是功能可见；
- 并行轨 B 的可见性是"少打字"。

### 12.6 规模控制规则（防止规模失控）

本版新增的约束，后续任何增项都必须满足：

1. **单期最多改 3 个小程序页面** —— 第 3 期正是为此把"排期 + 里程碑"推到第 4 期
2. **单期最多新增 1 张表** —— migration 022 与 023 分属不同期
3. **单期必须能独立发版、有独立验收**；不能独立验收的项并入下一期
4. **任何新项必须能回答三问**：属于哪一期 · 依赖谁 · 独立验收怎么做。**答不出就不进本 PRD**

### 12.7 实施顺序硬约束

1. **感知层先于一切计划类能力**（[§4](02-能力设计.md) / US-33 / US-34）。否则 US-22 / US-23 / US-27 会在没有前提（喂养模式、阶梯位、排敏状态、数据可信度）的情况下生成计划，**等于把"猜"包装成"计划"**。
2. **单一真相源收敛先于跨端协同**。两端各算一套时打通桥，只会让不一致更快暴露给家长。
3. **建议卡 schema 三层同版**（§8.6）。唯一一个不改就会"家长看到裸露 JSON"的强耦合点。
4. **机制分型先于任何转奶计划**。分型未确认时不得生成家庭阶梯路径（R1）。
5. **020 上生产先于复诊摘要**（US-30）。外部阻塞项，未上生产前医疗相关只能给计数并降级（R5）。

### 12.8 与既有 PRD / 已上线小程序的关系

**与既有 PRD**：本 PRD不改变 PRD-003 已定义的对话/知识/数据/总结/日记/护栏能力，只在其中新增"**感知层（[§4](02-能力设计.md)）** + 目标层 + 推进层 + 协同层"，并顺带修掉 `OPT-20260919` 列出的缺陷（画像缺失、日期缺失、日记落库）。

**与已上线小程序**：本 PRD中的多项能力（排敏任务与逐日打卡、生长分位与曲线、复引入日期、首页进度卡、语音录入）**小程序已具备**（盘点见 [§2](01-现状与差距.md)）。因此本版**不是重造**，而是：① 收回前端派生（[§2.3](01-现状与差距.md)-①③）；② 把已有界面接到服务端真相源；③ 补上"分析结果怎么回到界面"这条回路（[§7.3](02-能力设计.md)）。

> **关于非目标第 7 条**：本版需要给表单加计划预填、内嵌语音入口、建议卡参数接收（见 [§7.6](02-能力设计.md)、§8.3），故"不改记录表单形态"不作为约束；**医疗档案结构**仍不改动（重构见 PRD-005）。

### 12.9 验收（摘要）

- [ ] **三端一致**：同一时刻首页行动卡、对话回答、报告页结论**完全一致**（[§13](05-风险与决策.md)-R16）
- [ ] **写只有一条路**：全局搜索确认不存在任何"对话 / 推送触发记录写入"的路径（不含任何对话写库工具）
- [ ] **建议可落地**：agent 的每条建议都能一键回到对应界面且参数预选，采纳后记录带"来源：助手建议"标记
- [ ] **不重复录入**：转奶期从首页行动卡进入喂养表单，配比已预填，保存后**无需二次打卡**
- [ ] **犹豫有出口**：排敏详情页遇到"拿不准"时，一次点击进入对话且上下文完整（无需复述）
- [ ] **语音准确但不越权**：低置信字段留空高亮、不静默写错；语音路径不产生对话历史
- [ ] **感知三态**：有效结论 / 信息缺失 / 数据陈旧三种表述可区分（[§4.9](02-能力设计.md)）
- [ ] **两端约束一致**：已停母乳的宝宝，在回答与日记中均不出现"母乳喂养"
- [ ] **降级不炸**：migration 020 未上生产期间，复诊闭环相关能力标记"待确认"且不阻塞其余功能
- [ ] **每期可独立发版**：单期不依赖"下一期的功能"才能跑通（§12.6-③）
- [ ] **规模受控**：单期新增小程序页面 ≤ 3、新增表 ≤ 1（§12.6-①②）
