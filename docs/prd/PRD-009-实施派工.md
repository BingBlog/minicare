## 2. 服务端层改动清单（`minicare-server`）

### 2.1 新增模块

```
minicare-server/src/schedule/
├── schedule.module.ts            # 注册；imports 复用 records/family 的查询能力
├── schedule.controller.ts        # 4 个接口（含 P2 的 review）
├── schedule.service.ts           # 模板 CRUD 校验 + getTodaySchedule 派生
├── schedule.constants.ts         # ⭐ 判定窗口常量「单一定义处」
├── schedule.default-template.ts  # 默认模板常量 + getDefaultScheduleTemplate(ageMonths)
└── dto/
    └── save-schedule-template.dto.ts   # ScheduleItemDto + ItemTypeEnum
```

`app.module.ts` 注册 `ScheduleModule`。

### 2.2 接口与鉴权

沿用既有链路 `JwtGuard` → `FamilyMemberGuard`。`babyId` 必须校验归属当前家庭（复用既有校验，勿新写）。

⚠️ **取当日记录必须复用既有口径**（`family.service.getTodayRecords` 或等价），**不要另写一套记录查询** —— 否则会出现"首页显示完成、日程 Bar 显示未完成"的两套数据源。

### 2.3 三条校验（US-02）

| 校验 | 规则 | 失败文案 |
|---|---|---|
| 准备时序 | `prepare_time < execute_time` | 「准备时间需要早于执行时间」 |
| 不跨零点 | 两者同属当日 | 「暂不支持跨天的事项，请调整时间」 |
| 同类窗口不重叠 | 同判定依据的项，执行时间差 ≥ 提前量 + 宽限期 = **150 分钟** | 「这两项时间太接近…请至少间隔 150 分钟」 |

> ⚠️ 150 必须**由 `schedule.constants.ts` 的 60/90 推导**，禁止硬编码。改窗口参数必须同步改这里的提示文案。

### 2.4 派生逻辑（US-05）

**判定依据映射（唯一口径，必须复用首页既有的"营养素"排除逻辑）**：

> 📌 **2026-10-09 起：类型清单不再在本表维护**。权威源为
> `minicare-server/src/schedule/schedule-item-type.meta.ts`（类型/默认名/分组/可判定/默认提前量）
> \+ `schedule-item-type.registry.ts`（`match` / `summary`）。
> `schedule.service.ts::matchRecord` / `buildSummary` 已改为**查表**，不再有 switch；
> 小程序类型选项由 `GET /api/config` 的 `scheduleItemTypes` 下发。
> **新增一个类型只需改服务端这两个文件**（＋枚举文件 `schedule-item-type.ts`）。
> 完整 14 项映射见 PRD-009 §US-05。

**派生顺序**（每次请求重算，不落库）：`disabled` → **两遍配对**（① 窗口内命中 → ② 同类未配对项 × 未消费记录按时间升序一一配对，**不设偏差上限**，仅"执行时间已到"的项参与）→ 按当前时间 `upcoming` / `preparing` / `doing` / `missed`。时区固定 **Asia/Shanghai**。

> 📌 顺序兜底的完整口径、安全闸与已知代价见 **PRD-009 §1.4.2**；实现落在
> `schedule.service.ts::deriveItems()`（`rows` 下标 → 命中记录的 Map + `consumed` 记录下标集合，
> 返回顺序与 `rows` 一致）。**不要**退回"只做窗口匹配"的旧实现。
> ⚠️ 拖拽排序若改了列表顺序，**不影响顿次判定** —— 配对基准是 `execute_time` 升序。

**展示顺序**：`selectItems` 为 `ORDER BY sort_order ASC, execute_time ASC, created_at ASC`；保存时按提交数组下标整体重写 `sort_order`（migration **023**）。

**进度**：`done 数 / (enabled 且 item_type ≠ other 的项数)`。

### 2.5 出参契约（`GET /api/schedule/today`）

```jsonc
{
  "items": [
    {
      "id": "uuid",
      "itemType": "feeding_food",
      "title": "早餐辅食",
      "executeTime": "09:00",
      "prepareTime": "07:00",
      "sortOrder": 1,              // 展示顺序，0..n-1（拖拽决定）
      "status": "done",            // done|upcoming|preparing|doing|missed|disabled
      "matchedRecord": {           // status=done 时有值，否则 null
        "id": "uuid",
        "type": "feeding",
        "recordTime": "09:10",
        "summary": "09:10 · 米粉 30g"
      }
    }
  ],
  "progress": { "done": 3, "total": 10 }
}
```

> ⚠️ 项目约定：**无全局响应包裹层**（`ResponseFormatInterceptor` 未注册）。列表接口直接返回 `T[]`，前端**不要多读一层 `.data`**。

## 5. 支撑性需求：数据与能力清单

### 5.1 migration 022

表结构见主 PRD §3.2（`schedule_template_item`，含 `deleted_at` 软删除，`KEY idx_sched_baby_time(baby_id, execute_time)`）。

要点：
- 迁移编号 **022**（020 = 医疗类型化、021 = KB `retrieval_status` 已占用）
- **`sort_order` 由迁移 023 追加**（`INT NOT NULL DEFAULT 0` + `KEY idx_sched_baby_sort(baby_id, sort_order)`）；默认 0 让 023 之前的历史行自动退化为"按时间升序"，向后兼容
- **不建"每日日程表"** —— 今日状态实时派生（主 PRD 决策 D3）
- **不建唯一索引** —— 允许两条同名项（如两顿"户外活动"），时间不同即可；`sort_order` 也不建唯一索引（保存时整体重写 0..n-1，不做增量 diff）
- "同类项窗口不重叠"由**应用层校验**，SQL 无法表达；顺序兜底**不受**该约束

### 5.2 常量「单一定义处」清单 ⭐

| 常量 | 值 | **唯一定义处** | 消费方 |
|---|---|---|---|
| 判定窗口提前量 | 60 分钟 | `schedule.constants.ts` | US-02 校验 + US-05 派生 |
| 判定窗口宽限期 | 90 分钟 | `schedule.constants.ts` | US-02 校验 + US-05 派生 |
| 同类项最小间隔 | 150 分钟 | **由上面两个推导，不单独定义** | US-02 校验 |
| 辅食准备提前量默认值 | 120 分钟 | `schedule-item-type.meta.ts`（按类型声明，经 `/api/config` 下发；`schedule.constants.ts::defaultPrepareOffsetMin()` 转发） | 小程序准备时间联动推导 |
| 类型清单（14 项 / 4 组 / 可判定 / 默认提前量） | — | `schedule-item-type.meta.ts`（+ `schedule-item-type.registry.ts` 的 `match`/`summary`） | 服务端派生 + `/api/config` 下发 + 小程序类型选择区 |
| 拖拽落点计算 | — | `minicare-mp/src/pages/schedule/index.tsx::measureRowSlots()` | 作息计划页长按拖拽（⚠️ 依赖"拖拽期间行高一致"） |

> ⚠️ 小程序端如果硬编码 60 / 90 / 120，**必须在文件头注明指向服务端常量文件**。
> **更稳妥的做法**：这三个值随既有 `/api/config`（`fetchAppConfig`，已缓存到 Taro Storage）下发。
> 类型清单/默认提前量**已经**走这条路（`config.scheduleItemTypes`），前端不再维护清单。
