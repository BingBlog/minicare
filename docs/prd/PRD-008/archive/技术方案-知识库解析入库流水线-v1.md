## 1. 总体架构

```
┌─────────────────────────── kb 后端（Python 3.12，单进程） ───────────────────────────┐
│                                                                                      │
│  API 层（FastAPI）                                                                    │
│   ├─ 文档/步骤/产物/校对/导出/检索 REST（§11）                                          │
│   └─ 静态资源：PDF 页渲染图、图片裁切图、导出 MD                                        │
│                                                                                      │
│  编排层（Orchestrator）                                                               │
│   ├─ TaskQueue（SQLite 持久化，单 worker 串行）                                        │
│   ├─ PauseGate（暂停点 1/2 的放行逻辑）                                                │
│   ├─ 状态派生器（§6.2 规则 → 文档状态）                                                │
│   └── StepRunner ──┬── 缓存判定（cache key → ArtifactStore 查询）                     │
│                    ├── 失效传播（downstream stale 标记）                               │
│                    └── 步骤注册表（9 个 Step 的声明式定义）                             │
│                                                                                      │
│  步骤实现层（每个 Step = 纯函数 `run(inputs, params) → outputs`）                     │
│   ingest · preflight · parse · normalize · extract_meta                               │
│   · annotate_figures · repair_tables · segment · index                                │
│        │                              │                                              │
│   引擎抽象层                    LLM 网关（LLM Gateway）                                │
│   ├─ ParseEngine 接口           ├─ 触点开关（L1–L4）                                  │
│   │   ├─ MineruEngine           ├─ 预算控制器（次数+token 双口径）                     │
│   │   └─ PypdfEngine            ├─ 调用记录（provider/model/prompt_version/token）   │
│   ├─ OcrEngine 接口             └─ prompt 版本管理（prompts/ 目录）                    │
│   ├─ EmbeddingProvider          │                                                    │
│   └─ VlmClient（云 API）        外部 API                                              │
│                                 ├─ Crossref / PubMed（只发 DOI/PMID）                 │
│  产物层（ArtifactStore）         └─ VLM 云 API（仅图表裁切图）                          │
│   文件系统 + manifest.json + SQLite 索引                                              │
│                                                                                      │
│  编辑层（人工产物）                                                                    │
│   chunks.edited.json（diff + base_hash）· figures.review · tables.review              │
│                                                                                      │
│  检索层（复用 llama-index）                                                            │
│   Chroma（向量）+ bm25s/jieba（中文 BM25）+ 元数据过滤                                 │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

**设计原则**（对应 PRD D7/D8/D10）：

1. **Step 是纯函数**：`(上游产物引用, 参数) → 产物`，不读数据库业务状态、不直接写库——保证可重放、可缓存、可对比
2. **Orchestrator 拥有状态，Step 无状态**：stale/缓存/暂停点全部由编排层管理
3. **LLM 只出现在网关后面**：任何 Step 不得直接实例化模型客户端
4. **产物即事实**：界面上一切可显示的东西（状态、统计、成本）都从产物与 manifest 派生，不做第二份记录

## 3. 存储设计（ArtifactStore）

### 3.1 目录布局

```
data/
  docs/{doc_id}/
    file/                      # 原始上传文件（FileObject）
    raw/                       # parse 原始产物，原样保留，永不清理（FR-1.6）
    01_ingest/run__*/
    02_preflight/run__*/
    03_parse/run__*/           # parsed.json + capabilities + warnings
    04_normalize/run__*/
    05_extract_meta/run__*/
    06_annotate_figures/run__*/
    07_repair_tables/run__*/
    08_segment/run__*/         # chunks.json
    09_index/run__*/
    edits/                     # 人工产物（跨 run 存续，见 §9）
      chunks.edited.json
      figures.review.json
      tables.review.json
    export/                    # Markdown 导出（doc.md + assets/）
    manifest.json
```

### 3.2 run_id 与缓存键

```
run_id = run__{engine}@{engine_version}__{backend}__{params_hash前8位}

cache_key = sha256(
    step_id,
    上游各产物的 content_hash（文件级）,
    params_hash,
    engine_version,
    embedding_model@version        # 仅 index 步骤（FR-9.6）
)
```

- 产物目录名即 `cache_key` 的前 16 位（保证同参数重跑直接命中目录，O(1) 查找）
- manifest 中每个 step 记录 `current_run` 与历史 `runs[]`（PRD §7.8 契约不变）

### 3.3 SQLite 表（加速索引，非事实源）

| 表 | 关键字段 | 用途 |
| --- | --- | --- |
| `documents` | doc_id, sha256, filename, derived_status, tier, degraded, paused_at, created_at | 列表页与判重（derived_status 由派生器写入，每次 manifest 变更后刷新） |
| `steps` | doc_id, step_id, status(running/succeeded/failed/stale/skipped_cached/skipped_no_capability/pending), run_id, updated_at | 步骤视图与状态派生输入 |
| `tasks` | task_id, doc_id, kind(pipeline/step_run), payload, state(queued/running/cancelled/done/failed), enqueued_at, cancel_requested | 队列与取消（FR-1.14/1.15） |
| `llm_calls` | call_id, doc_id, touchpoint(L1..L4), provider, model, prompt_version, tokens_in/out, cost, created_at | FR-10.1/D6（同时落产物文件，双写） |

> **一致性规则**：SQLite 是 manifest.json 的物化视图。进程启动时做一次全量校验（对账），不一致以 manifest 为准重建。这保证 NFR-4（断点恢复）的正确性基线。

## 4. StepRunner 核心设计

### 4.1 Step 声明式定义

```python
@dataclass
class StepSpec:
    step_id: str
    requires: list[str]                 # 上游 step_id
    produces: str                       # 产物 schema 名
    params_schema: type                 # pydantic model
    needs_gate: str | None = None       # "meta_confirmed"（仅 segment）
    parallel_group: int | None = None   # 5/6/7 同组，可并行

STEP_REGISTRY: dict[str, StepSpec] = {
    "ingest":           StepSpec("ingest", [], "FileObject", IngestParams),
    "preflight":        StepSpec("preflight", ["ingest"], "PreflightReport", PreflightParams),
    "parse":            StepSpec("parse", ["preflight"], "ParseArtifact", ParseParams),
    "normalize":        StepSpec("normalize", ["parse"], "NormalizedDoc", NormalizeParams),
    "extract_meta":     StepSpec("extract_meta", ["normalize"], "DocumentMeta", MetaParams, parallel_group=1),
    "annotate_figures": StepSpec("annotate_figures", ["normalize"], "FigureNotes", FigureParams, parallel_group=1),
    "repair_tables":    StepSpec("repair_tables", ["normalize"], "TableSet", TableParams, parallel_group=1),
    "segment":          StepSpec("segment", ["extract_meta", "annotate_figures", "repair_tables"],
                                 "ChunkSet", SegmentParams, needs_gate="meta_confirmed"),
    "index":            StepSpec("index", ["segment"], "IndexedDoc", IndexParams),
}
```

依赖表与 PRD §6.1 拓扑一一对应：5/6/7 同为 `parallel_group=1`（互不依赖）；segment 依赖全部三者并挂暂停点闸门。

### 4.2 执行流程（单步 run）

```
run(doc_id, step_id, params, force):
  1. 读取 manifest 中上游步骤的 current_run → 收集输入产物引用
     - 任一上游 failed/无产物 → 报错退出（不允许盲跑）
  2. gate 检查：needs_gate 且闸门未开 → 转为 waiting_gate 挂起
  3. 计算 cache_key → 若产物目录存在且 force=false：
     - 校验产物完整性（schema 校验）→ 标记 skipped_cached，直接返回
  4. capabilities 短路检查（FR-4.9/5.11）：
     - 输入 ParseArtifact.capabilities 不满足本步所需 → 产出空集 +
       skipped_no_capability，计 succeeded（非失败）
  5. 写 tasks 表 state=running → 调用 Step 实现函数（工作目录 = run 产物目录）
     - Step 函数内部周期性检查 cancel_requested（协作式取消，步骤内子任务边界）
  6. schema 校验产物 → 写 manifest（追加 run 记录、更新 current_run）
  7. 失效传播：downstream 标 stale（产物文件不删，FR-1.8）
  8. 派生器刷新 documents.derived_status
```

### 4.3 失效传播与参数级失效

- 传播规则按依赖表反向闭包计算，与 PRD §6.3 一致：`invalidate(parse)` → normalize 及其全部下游
- **参数级失效**：`index` 的 cache_key 含 embedding 模型版本，换模型后旧 key 天然 miss；同时 Orchestrator 检测到配置变更事件，将全部 `index` 行显式标 stale（界面可见，PRD §6.3 v3.2 条款）
- L4 开关切换视为 `segment` 参数变更（写入 SegmentParams），同样显式标 stale segment+index（FR-10.10）

### 4.4 暂停点闸门（PauseGate）

```python
class PauseGate:
    meta_confirmed: bool | None   # None=未到，True=已确认放行
```

- 暂停点 1：`extract_meta` 完成后 gate 挂起等待；`5/6/7 并行组`**不受闸门约束**照常执行（PRD §6.4 并行语义）
- `segment` 是唯一 `needs_gate` 的步骤：启动条件 = 闸门开 ∧ 5/6/7 全部非 running
- `require_meta_review=false` 或批次快速模式（FR-3.5）时，Orchestrator 自动置 `meta_confirmed=True` 并留痕（任务日志 + manifest 注记）
- 暂停点 2 同理：`segment` 完成后停；`require_chunk_review=false` 且无红色标记自动放行

## 5. 调度与任务模型（FR-1.14/1.15）

- **单 worker 串行**：asyncio 主循环，一次只执行一个任务；CPU 密集步骤（parse/index）用 `asyncio.to_thread` 包裹，避免阻塞 API
- **队列持久化**：tasks 表即队列，进程重启后扫描 `queued/running` 重新入队（running 的标记为中断，产物目录若存在半成品则删除该 run 目录后重跑——run 目录的原子性通过"先写 `.tmp` 再 rename"保证）
- **取消语义**：`cancel_requested` 置位 → Step 在子任务边界（如 MinerU 的"每页完成后"）检查并退出；已完成步骤产物保留；队列中任务直接置 cancelled
- **进度上报**：MinerU 按页回调 / 解析日志解析两种方式，写入 tasks.progress，API 轮询（单用户场景不做 WebSocket，保持简单）

## 6. 各 Step 实现要点

| Step | 关键实现 | 验收锚点 |
| --- | --- | --- |
| `ingest` | sha256 流式计算；判重查 documents 表；FileObject 落盘 | FR-2.1/2.2 |
| `preflight` | pypdf 逐页抽文字层 → `text_layer_quality`（字符数/页面积比）；**逐页语言检测**（CJK 字符占比 > 阈值判 zh，产出 `page_langs`）；扫描页判定与 `recommended_tier` | FR-2.9、FR-2.14 |
| `parse` | 引擎按 tier 分发：standard→MinerUClient（cli 模式，工作目录=run 目录，完成后解析 MinerU 输出 JSON → `ParseArtifact`）；fast→PypdfEngine（**capabilities={layout:false, table:false, figure:false, formula:false, ocr:false}**，blocks 仅文本 + page，bbox 为空）。失败时按 FR-2.7 降级重跑（降级本身也是一次新 run） | FR-2.3/2.6/2.7、§7.2 契约 |
| `normalize` | MinerU content_list → Block 列表（带 page/bbox/type/category）；**页眉页脚过滤规则**（位置在页边距带 + 跨页重复文本，剔除结果进 warnings）；Markdown 派生视图 | FR-2.8 |
| `extract_meta` | 三级瀑布：① 规则（首页区域正则：标题=首页最大字号块、DOI/PMID 正则、年份）② Crossref/OpenAlex + PubMed（**只发 DOI/PMID**）③ LLM 兜底（字段级，走网关）。每字段带 source/confidence/evidence | FR-3.x、FR-10.7 |
| `annotate_figures` | 输入 capabilities.figure 检查 → ImageBody/ImageCaption 按 category+阅读顺序配对（bbox 规则兜底）→ 过滤规则 → 图类型分类（规则+VLM）→ VLM 描述（走网关，中文+英文术语保留，prompt 模板见 §7.3） | FR-4.1–4.9、D1/D2 |
| `repair_tables` | 三级级联：MinerU HTML → 结构校验（列数一致性/表头/单元格数/超长单元格）→ VLM 修复。`retrieval_text` 生成：题注+表头+行列配对文本 | FR-5.x、D3/D4 |
| `segment` | 前置：gate + 5/6/7 完成。一级按 Section 树切；二级父子块（中英分档阈值，配置表驱动）；abstract/参考文献特殊处理；表格/图片不参与普通切分（`content_type` 标记）；L4 关闭时直接拼装，开启时逐 chunk 调网关生成上下文前缀 | FR-6.x |
| `index` | 输入：`chunks.edited.json` 若存在则优先（§9）→ embedding（本地模型，批量化）→ Chroma upsert（按 doc_id 先删后插，保证 FR-9.4 覆盖语义）→ BM25 建索引（jieba 分词，医学术语词典热加载）→ IndexedDoc 记录向量 id 范围 | FR-9.1–9.6 |

## 7. LLM 网关（FR-10.x / G8 预算制）

### 7.1 接口

```python
class LLMGateway:
    async def call(self, *, doc_id, touchpoint: Literal["L1","L2","L3","L4"],
                   prompt, image_path: Path | None = None) -> LLMResult
```

### 7.2 预算控制器（FR-10.5）

- 每文档预算（次数 + token 双口径）从配置读取；`llm_calls` 表实时累计
- 超限动作：按 **L4→L3→L2** 顺序拒绝新调用（返回 `BudgetExceeded`，Step 捕获后降级——图片跳过描述仅保留题注、表格走 fallback 标记），**L1 不拒绝**（元信息兜底必须成功，否则 FR-3.3 必填校验会卡死流程）
- 每次超限拒绝写 warnings + 界面告警

### 7.3 Prompt 版本管理（FR-10.8）

```
prompts/
  L2_figure_description/v3.md      # 输入：裁切图+题注+图类型；输出 JSON：description/key_data/labels/confidence
  L3_table_repair/v2.md            # 输入：HTML+裁切图+校验错误项；输出：修复后 HTML+confidence
  L1_meta_fallback/v1.md           # 输入：首页文本块；输出：结构化字段
  L4_contextual_prefix/v1.md       # 输入：chunk+文档元信息；输出：50 字上下文前缀
```

- 版本号进 `llm_calls.prompt_version`，修改 prompt 必须 bump 版本（CI 校验目录内无未版本化文件）
- 所有 prompt 要求 JSON 输出 + 自报 confidence；**网关做规则校验融合**（FR-10.2 v3.2：如 L2 描述中出现的数值必须能在 key_data 中找到，不一致自动下调 confidence）

## 8. 状态派生器（PRD §6.2）

```python
def derive_status(steps: dict[str, StepStatus], meta_confirmed: bool) -> DocStatus:
    # 按优先级：
    if any(failed): return FAILED
    if extract_meta.ok and not meta_confirmed:
        if figures/tables running: return PROCESSING(progress_hint="元信息可先行确认")
        return AWAITING_META
    if segment.ok and not chunk_approved: return AWAITING_REVIEW
    if any(running): return PROCESSING
    if any(stale): return NEEDS_UPDATE
    if all succeeded: return INDEXED
    if disabled: return DISABLED
```

派生器在每次 manifest 变更后同步执行，结果写 `documents.derived_status`（列表页直查）+ 事件推送步骤视图刷新。暂停点 1 在并行期间可见性由第 2 条分支保证。

## 9. 人工编辑层（FR-1.13，跨 run 存续）

```
edits/chunks.edited.json
{
  "base_run_id": "run__...",           # 所基于的机器 ChunkSet
  "base_content_hash": "sha256:...",   # 该 ChunkSet 内容 hash
  "invalidated": false,                # 重切后置 true，界面列出可找回项
  "entries": [
    {"chunk_id": "c_017", "op": "edit", "text": "..."},
    {"chunk_id": "c_018", "op": "disable"},
    {"chunk_id": "c_019", "op": "delete"},
    {"op": "split", "src": "c_020", "new": ["c_020a", "c_020b"], "derived_from": ["c_020"]},
    {"op": "merge", "src": ["c_021","c_022"], "new": "c_021m"}
  ]
}
```

**语义**：

- `index` 步骤读入顺序：`edits（未失效）→ 机器 chunks.json`；失效则用机器版 + warnings 提示
- **重切后的编辑找回**：新 ChunkSet 生成时，对旧 entries 中 `op=edit` 的条目，用"原 chunk 文本前 80 字符 fuzzy match（difflib, ratio ≥ 0.6）"在新 chunk 中定位候选，写入 `edits/recoverable.json`；校对页顶部黄条提示"N 条历史编辑可找回"，逐条确认迁移
- 图片/表格编辑同理：`figures.review.json`（review_state + 人工改写文本）、`tables.review.json`；Step 重跑时**跳过 review_state ∈ {accepted, rejected, edited} 的条目**（FR-4.7/5.10/10.4 的"驳回后不再生成同一条"实现）

---

## 10. 检索层

- **混合检索**：llama-index `QueryFusionRetriever`（Chroma 向量 + bm25s），RRF 融合，`top_k` 可配
- **中文 BM25**：jieba.lcut 分词 + 自定义词典（`data/dict/medical_terms.txt`，可热加载追加）
- **元数据过滤**（FR-9.3）：Chroma where 条件（year/journal/study_type），检索测试页透传
- **图表切片**：`include_assets` 开关控制是否召回 `content_type ∈ {figure, table}` 的切片
- 检索测试接口复用现有实现，加 `doc_id` 限定参数（FR-8.2）

## 11. API 实现（对 PRD §9 的映射）

沿用 FastAPI router 分组：`/api/documents`、`/api/documents/{id}/steps`、`/api/figures|tables|chunks`、`/api/kbs`。实现要点：

| PRD 接口 | 实现要点 |
| --- | --- |
| `POST steps/{step_id}/run` | 入队 `step_run` 任务（非同步执行），返回 task_id；`?force=true` 透传 |
| `GET steps/{step_id}/artifact` | ArtifactStore 按 `run_id`（缺省 current_run）读文件，schema 校验后返回 |
| `PUT /meta` | 写确认 + 置 `meta_confirmed=True`（闸门开）；仅元信息字段更新，不触发任何 step 重跑（B5 语义） |
| `PATCH /figures|tables/{id}` | 更新 edits/*.review.json；`review_state` 流转 |
| `POST /approve` | 暂停点 2 放行 → 入队 index 任务 |
| `POST /reject` | invalidate(parse) 及下游 + 入队 pipeline 重跑（保留元信息：edits 目录与 meta 表单值不删，B6/FR-7.12） |
| `POST /export/markdown` | 同步生成（数据都在本地，秒级）：NormalizedDoc 线性骨架 + 三类 patch 应用 → `export/doc.md + assets/`（FR-7.14 重建机制） |
| `DELETE /documents/{id}` | 级联：Chroma 按 doc_id 删 + BM25 重建 + SQLite 删行 + **产物目录整体删除**（FR-9.5）；二次确认在前端 |
| `POST /pipeline/cancel` | tasks 表置 cancel_requested，返回；实际取消在下个步骤边界生效 |
| `GET /pages/{n}.png` | PyMuPDF 按需渲染（dpi=200），LRU 缓存 50 页 |

## 12. 配置系统（NFR-13 / PRD §14.4）

```yaml
meta:

figure:
  confidence_yellow: 0.6
  pair_vdist_ratio: 0.08
  pair_hoverlap: 0.50
  filter_area_min: 0.03
  filter_aspect_max: 8.0
  filter_text_overlap: 0.60
table:
  confidence_red: 0.7
  html_usable_target: 0.80
  long_table_rows: 60
  long_table_chars: 3000

  child_zh_chars: [300, 500]
  child_en_words: [200, 350]
  parent_zh_chars: [1500, 2500]
  parent_en_words: [1000, 1700]
llm:
  budget_calls: 20            # 单篇默认
  budget_tokens: 200000
  touchpoints: {L1: on, L2: on, L3: on, L4: off}   # L4 默认关（FR-10.10）

  fusion: rrf
  include_assets_default: true

  max_mb: 100
```

- pydantic-settings 加载 + 启动时校验；§14.4 表更新时同步本文件（评审检查项）
- 阈值变更不触发缓存失效（阈值属于 Step 内部行为参数，进 params_hash——**注意**：阈值改动会让 cache_key 变化，等效重跑，符合预期）

## 16. 风险与回退

| 风险 | 本方案的缓解 | 回退路径 |
| --- | --- | --- |
| MinerU 依赖冲突（R1） | MinerUClient 三模式抽象；冲突时切 cli + 双 venv | pypdf（fast 档）全量兜底，图表功能按 capabilities 短路 |
| CPU 解析慢（R4） | 队列 + 按页进度 + 取消；基准报告先行 | 官方云 API 路线（MinerUClient cloud 模式） |
| VLM 描述质量差（R5） | prompt 版本化 + confidence 融合 + 题注分字段 + 驳回重跑跳过 | L2 降级"仅题注检索"，图片文件仍保留 |
| SQLite/manifest 双源漂移 | manifest 为事实源 + 启动对账重建 | — |
| embedding 换型成本 | cache_key 含模型版本，天然增量重嵌入（旧向量按 doc 删） | — |
| 编辑迁移误匹配（fuzzy） | 阈值 0.6 + 人工逐条确认，不自动生效 | 关闭找回功能，仅提示"有旧编辑" |
