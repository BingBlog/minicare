### 12.3 Prompt 版本化

LLM 触点（关键词生成）的 prompt 必须**带版本号落盘**，版本号进 manifest 与 cache key；改 prompt 视为参数变更 → 相关步骤标 `stale`。

**目录位置**（PRD v1.0 未指明，`TECH-015` §8.9 定义）：放在 `minicare-platform/api/prompts/`（随管线仓库走，便于 git 追溯），不在平台工程里 —— 理由是 prompt 属于**管线行为**，CLI 与平台共用同一份。

```
minicare-platform/api/prompts/
  keyword_extraction/v1.md     # 输入：切片标题 + 正文；输出 JSON：keywords[] / confidence
```

**启动校验**：目录内每个 prompt 文件名必须能被解析出版本号，否则启动报错（防止漏版本化）。

### 14.4 分期硬约束

1. **单期 ≤ 1 张新表**（第 1 期 `kb_task`；第 3 期 `kb_corpus`；第 5 期 `kb_gap` + `kb_search_log` 需再排）
2. **每期必须能独立发版并独立验收**（上表的"用户可见变化"列即验收口径）
3. **H1（迁移 021）不得与第 1 期同时上生产** —— 第 1 期只做 dev 演练，把跨项目一致性风险隔离开
4. **第 2 期必须在第 3 期之前** —— 先有安全底线，再有"更快的接入"，否则接入越快、噪声进得越多
5. **契约文档冻结（并行轨 A）可立即开工**，它是对现状的固化，不依赖任何新能力

## 15. 验收

### 15.1 平台级验收（全部故事完成后统一执行）

| 项 | 验收口径 |
|---|---|
| 零命令行 | 从登记一份新指南到它可被检索，**全程只通过浏览器完成**，不打开代码编辑器、不敲命令 |
| 单步可重跑 | 改动任一步骤参数，日志可见上游被跳过、下游被重跑，且缓存命中耗时 < 1 秒 |
| 断点恢复 | 处理中断后重启，已完成步骤产物不丢失、不重算 |
| 质量门禁 | 被排除块与待复核块在检索结果中**永不出现**（含 agent-poc 侧） |
| 发布可退 | 任意一次发布都能在 1 步操作内回滚，回滚后库内切片数等于快照记录值 |
| 质量可拦 | 召回回归不达标时发布被拦下（或经二次确认留痕放行） |
| 契约受保护 | 删减契约字段或破坏语义约束会阻断发布 |

### 15.2 分期验收（各期按当期能力子集验收）

| 期 | 验收项 |
|---|---|
| 第 1 期 | 改切块参数只重跑 `④⑤⑥`；断点续跑；取消后无半成品被下游引用；产物按 `run_id` 分目录不累积 |
| 第 2 期 | 参考文献块与空表不进向量索引与全文索引；回填数字后向量被重算；`agent-poc` 过滤条件同步且检索结果语义不回退 |
| 第 3 期 | 新增语料零改代码；元数据改字段不重解析；退回重解析保留已填字段；重切后旧编辑可找回 |
| 第 4 期 | 发布前 4 项检查各自能单独拦下；写入中途失败不留半批数据；发布后验证 4 项；一键回滚不重解析 |
| 第 5 期 | 关键词含正文词且不可用时降级告警；LLM 关键词不重复调用；未命中归因区分覆盖缺口与切片问题；契约校验拦截三类破坏 |

### 15.3 不在本期验收范围

- 多用户 / 权限 / 多租户
- 多格式（Office / EPUB / OFD）
- 多模态向量检索
- RAPTOR / rerank
- 平台对外提供服务
- NFR 级性能承诺（解析耗时取决于 MinerU 云端，本期只承诺"进度可见 + 可取消 + 可重试"）
