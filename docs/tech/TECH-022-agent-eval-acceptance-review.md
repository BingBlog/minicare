## 0. 结论摘要

1. **核心链路全部打通，验收通过**：发起 → 前置检查 → 进度轮询 → 中止 → 入库 → 报告 → 历史 → 四管理面（用例/任务/裁判/维度）→ 配置物化执行。本轮实测新建 run `20261009-191524`（指定 2 条 · judge 关），链路闭环 ✅。
2. **但报告页回答不了"过没过"**——PRD-010 US-03 承诺的「闸门结论（达标/未达标）+ 失败速览」未实现；叠加「硬幻觉率」数值语义反显、用例集快照显示错误等，共 **10 项偏差/缺陷**（其中 2 项 P0）。这是"体感差"的第一主因：*页面全是事实陈列，缺观点与指引*。
3. **对标行业最佳（Braintrust / Langfuse / LangSmith / Promptfoo / 百炼）**，报告层差距收敛为 4 个模式：**结论先行（verdict-first）**、**证据链单页归因**、**跨轮 diff**、**配置可试跑/可校准**。后两者 TECH-021 §8.2 已规划，属二期。
4. **建议节奏**：先修完 10 项缺陷（批次 A，不动架构）→ 报告页重构（批次 B，1 个迭代）→ 二期对比/趋势/校准（批次 C，已有规划）。

## 2. 体感诊断（为什么"体感差"）

把 1.2 的缺陷放到一起看，根因收敛为 6 条：

1. **没有"结论"**——页面回答不了用户最想问的一句话："这轮过没过？"。8 张 KPI 卡 + KV + 表格全是*事实陈列*，没有*观点与指引*（D1/D2/D10）。对标：Braintrust 实验页首屏是 "Pass rate 43/46 → 41/46 (+2)"、CI gate 报告首行是 verdict。
2. **信息层级平铺**——无 hero 结论区；"较上轮"被压缩成 12px 灰色小字；失败用例需要自己从表格里数（D1/D7）。重要信息与装饰信息同权。
3. **证据链断裂**——要回答"为什么挂"需跨 3 个页面拼信息：问题原文（message）在用例库、期望断言在用例库、judge 细节藏在未渲染字段里（D6）。**任何单页都无法完成一次归因**。
4. **状态语义混淆**——"未测 / 未启用 / N/A / 0 / 未通过"混用且视觉无区分；「硬幻觉率」反显（D2）。
5. **工作流断点**——看旧轮无 delta（D7）；想对比两轮无入口；改了裁判/维度后想验证要先真跑一轮（无一键试跑）；重跑要回发起区重建参数。
6. **开发者痕迹重**——JSON 裸编辑、英文 stage（`deterministic`）、mono hash、"46 条"硬编码、"（46 条）"（D3）；"工具感"强、"产品感"弱。

### 3.2 用例钻取（对象：单用例展开）——「一条证据链」

现状是"能看"但拼不成因果。重构为固定顺序的证据链（对标 Promptfoo assertion matrix + Langfuse item 详情 + PRD US-04）：

1. **问题**：`message` 原文 + `ctx` 摘要（当前完全没显示）；
2. **期望 vs 实际**：断言结构化渲染——期望（"调用 search_knowledge ×1，query 含『血』；回答非空"）与 实际（"未调用任何工具"）并排，差异高亮；失败断言逐条列出（D6）；
3. **回答**：Markdown 渲染（现在是无格式 `<pre>`）+ 复制按钮；默认展开首屏可见（现在藏二层折叠）；
4. **工具轨迹**：时间线列表（工具名 + **入参** + 耗时 + 返回摘要）（D6）；
5. **judge 卡**：四宫格——忠实度（硬幻觉标红）/ 完整度（覆盖 x/y + 缺失点列表）/ 护栏（就医引导·危险建议两标记）/ 风格（reasons 数组逐条渲染）（D6）；
6. **trace 深链**（已有）。
