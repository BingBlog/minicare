## 0. 结论摘要（先看这个）

1. **行业把「测试检索」拆成两个形态，且分工明确**：
   - **即席测试** —— Dify「召回测试」/ FastGPT「搜索测试」/ RAGFlow「检索测试」/ Coze「命中测试」：
     调参、排障、单案例验证；回答"这条问题召回了什么"；
   - **批量评测** —— ES `_rank_eval` / LangSmith / RAGAS：判定列表（或数据集）+ 指标 + 版本对比；
     回答"这批题还够不够好"。
   → 我们的两个形态**都已存在或已规划**：即席 = 本次抽出的「检索测试」页；批量 = 「检索质检」页 + PRD-011 质检台。
     两者共用同一份 `retrieval.py`，口径天然一致。
2. **即席测试的交互五件套**（四家国内平台高度一致）：
   ① 问题输入；② 参数区（TopK / 阈值 / 模式或权重）；③ 召回明细（得分 + 内容 + 来源）；
   ④ **最近查询**历史；⑤ **测试-配置分离**（测试期改的参数只影响本次测试，确认后才写入正式配置）。
3. **分数是核心调试信号**：RAGFlow 把**加权混合分直接标注在每个召回块的左上角**（可逐位验算公式）；
   Dify / FastGPT 展示单一相似度分；ES 判定列表用整数相关性分级。共识：**分数必须可见、可解释**。
4. **方法论共识**（可直接复用的操作手册）：
   - **三类问题法**（Coze 社区总结得最清楚）：原文原句 / 口语化表达 / 同义替换问法 ——
     只有「原文原句」命中 = 语义检索没生效（实为纯关键词在跑）；全不中 → 回解析层查；
   - **"期望的块出现在结果里"是验收标准**（RAGFlow 原话：调阈值直到结果里出现期望的答案、且没有太多不必要的信息）；
   - **测试先行、逐层排除**：解析 → 切片 → 检索 → 生成；先证明"能召回正确块"，才好把余下问题归因给 LLM。
5. **对 minicare 的落点（本次已实施）**：独立页 `retrievaltest` + `POST /api/quality/search`（含耗时与链路诊断）；
   最近查询（localStorage）；行展开完整召回复本 + 复制 JSON；路由分内联（全文相关度 / 向量余弦 / 名次）。
   **刻意不做**的项与理由见 §5 —— 阈值预演、临时调参、查询改写都触碰"与智能体同口径"的定位红线。

## 2. 即席检索测试 · 四家详解

### 2.1 Dify —「召回测试」

- **入口与布局**：知识库 → 「召回测试」页签。左侧 Source Text 输入框，右侧 Recalled Paragraph 实时看召回结果；
  输入框右上角可打开检索设置弹层（**测试期专用**）。
- **最近查询**：Recent Queries 区块记录历史查询，**包括从已关联应用里触发的查询** ——
  "在应用里踩的坑，回到知识库页能复现"。
- **参数**：检索方式（向量 / 全文 / 混合）+ TopK（默认 3）+ Score 阈值（默认 0.5，可开关）+
  Rerank 模型；混合模式下额外给「语义权重 / 关键词权重」滑杆（拖到两端即退化为纯向量 / 纯全文）。
- **关键机制：测试期参数不影响正式配置**。确认参数好用后，要到「知识库设置 → 召回设置」正式落地 ——
  "**先试、后配**"，避免边测边把线上配置改乱。
- **官方建议步骤**：① 设计覆盖常见问题的测试题组；② 选检索策略；③ 调 TopK 与 Score：
  TopK 小 / 阈值高 → 更精准但可能漏；TopK 大 / 阈值低 → 召回多但噪声多。

### 2.2 FastGPT —「搜索测试」

- **四种模式**：语义检索 / 全文检索 / 混合检索（**RRF 融合**）/ 结果重排（Rerank，输出 0-1 相关性分）。
- **完整链路**（官方文档原文口径）：问题优化（指代消除 / 扩展）→ 多路召回 → RRF 合并 →
  Rerank 二次排序 → 相似度过滤 + 引用上限裁剪。
- **一条重要边界（官方明说）**：**混合检索的结果不能直接按相似度过滤，需要配 Rerank 做最终过滤** ——
  RRF 融合分是"名次分"，没有绝对相似度语义。**这与我们的处境完全一致**（见 §5 的阈值决策）。
- 参数：topk、相似度过滤阈值、引用上限。

### 2.3 RAGFlow —「检索测试」

- **入口**：知识库 → 检索测试（建议**在配置聊天助手之前**先测；前置条件 = 文件已成功解析）。
- **配置项**：相似度阈值（默认 0.2，混合分低于阈值直接过滤）、关键字相似度权重（默认 0.7，
  另一半为向量余弦或 rerank 分）、Rerank 模型（留空则用向量余弦）、知识图谱开关、跨语言搜索。
- **分数公式（可验算）**：`混合分 = 关键字相似度 × 权重 + 向量余弦 × (1 − 权重)`；
  每个召回块的**左上角直接标注混合分**（如 40.85 ≈ 阈值 0.4085），调试时对着公式算一指就知道阈值该怎么调。
- **方法论原话**：「调阈值，直到回复结果里能包含期望的答案，又不会有太多不必要的信息」；
  「检索测试绝不是多余步骤 —— 先证明能召回正确的块，你才知道该把精力放在检索还是生成」。
- 同样**测试与落地分离**：测试页改的参数只影响测试；要生效需到聊天配置里改。

### 2.4 Coze（扣子）—「命中测试」

- **入口**：知识库详情页右上角「测试」。
- **三类问题法**（社区总结的实战 SOP）：① 知识库原文原句；② 用户口语化表达；③ 同义替换问法。
  观察哪类命中 —— **仅 ① 命中 ⇒ 语义检索根本没生效**（纯关键词在兜底）；三类全不中 ⇒
  回到解析层检查（"处理中"超 5 分钟未变 = 重新上传或转纯文本）。
- **调参三步**：查询改写开关 → 召回数量 + 最小相关度（社区实测在 0.35 → 0.52 之间微调：
  低于 0.52 误召回陡增、高于 0.55 开始漏片段）→ 确认混合检索双通道已勾选。
- **诊断链路**：**解析 → 切片 → 检索模式 → 参数**，逐层排除。

## 3. 批量评测（对侧形态，简述）

### 3.1 Elasticsearch `_rank_eval`（判定列表是行业标准名）

- 三要素：**文档集合 + 典型查询集合 + 每查询的文档相关性评分**（judgment list，整数分级，0 = 不相关）。
- 指标：Precision@k、Recall@k、MRR、DCG / NDCG、ERR；两个关键参数：`relevant_rating_threshold`
  （相关性判定门槛）、`ignore_unlabeled`（未标注文档是否计入）。
- 设计要点：支持模板化 query（同一结构不同参数）；官方强调"**持续在代表性测试集上评测** ——
  避免优化某个 query 的排序而恶化其他"。
- 纯 API、无交互界面；它贡献的核心词汇是「**判定列表**」。

### 3.2 LangSmith / RAGAS / Arize Phoenix（指标族）

- 检索层：Context Recall / Context Precision / Hit Rate@K / MRR / NDCG@K；
- 生成层（属 Agent 测评范畴，本文不展开）：Faithfulness / Answer Relevancy 等；
- 平台化对象：Dataset + Evaluators + Experiments（per-item 矩阵、跨实验对比、版本化）。
- 对位：我们的批量形态 = 「检索质检」页 + PRD-011 质检台（用例集 / 运行 / 结果 / 历史）。

## 4. 共性模式提炼

1. **两形态分工，别混一个工具**：即席测试要"快、无状态、单案例"；批量评测要"版本化、可对比、能当门禁"。
   行业里没有一家把两者塞进同一个界面。
2. **即席测试五件套**：问题输入 / 参数区 / 召回明细 / 最近查询 / 测试-配置分离。
3. **参数三件套**：TopK、Score 阈值、模式或权重（含 Rerank）。**阈值是各家差异最大的点**：
   Dify / RAGFlow 挂在加权混合分上；FastGPT 明说纯混合分不可直接过滤、要配 Rerank。
4. **分数可见、可解释**：块级打分（RAGFlow 标在块上）+ 公式可验算。等价格式 =
   总分 + 各路分（我们：RRF + 全文相关度 + 向量余弦 + 各路名次）。
5. **诊断链路模板**：解析 → 切片 → 检索模式 → 参数 → 生成，逐层排除；
   三类问题法用来快速区分"语义没生效"还是"根本没入库"。
6. **历史**：轻量做法是 Recent Queries（Dify）；重投入做法把它升级为 run 台账（批量形态的领地）。

### 5.2 差距与决策（明确不做 / 缓做，防止"对标焦虑"式堆砌）

| 行业能力 | 决策 | 理由 |
|---|---|---|
| Score 阈值预演（Dify / RAGFlow） | **暂不做** | 我们的排序分 = RRF（名次融合），**没有绝对阈值语义**（FastGPT 同款处境，官方结论是"配 Rerank 才能过滤"）。要引入得先定义"可阈值化的分"（全文 MATCH 分 / 余弦分各自设阈），属检索链路级改动 + 契约同步（agent-poc）→ 记入候选 |
| 测试期临时调参 | **部分落地（2026-10-09 晚，用户要求）**：检索模式（混合/仅全文/仅向量）+ 关键词权重已作为**实验参数**上线（默认=线上口径；非默认时页面显式标注「与线上口径不同」，防止误读）；实现为 `retrieve()` 的纯增量可选参数，默认路径逐字节不变（契约/质检零感知）。**未做**：Rerank（链路上无该组件）；Score 阈值（RRF 是名次分、无绝对阈值语义，需先定义"可阈值化的分"） |
| 查询改写（Coze） | **不做** | 属 agent-poc 检索链路的改动，不是测试工具的问题 |
| highlight 命中词 | 候选 | ngram 分词下"命中词" = 2-gram 集合，高亮语义弱于整词检索，收益有限 |
| 「存为用例」按钮 | 候选（等 PRD-011） | 即 LangSmith trace-to-dataset 的轻量版：把这条测试问题一键加入回归用例集。**依赖 PRD-011 的用例集对象落地**，届时本页加一个动作即可 |
| 判定列表 / 批量指标（MRR、NDCG…） | 已在 PRD-011 规划 | 本页只管即席；批量归质检台（三态标注、多档指标在 PRD-011 §11 待确认项） |
