# 敏宝知识库 · 检索召回质量测评方案

> 生成时间：2026-08-19 ｜ 配套：《Agent知识库建设方案.md》第四章（检索召回）
> 范围：覆盖**离线测评、医疗专项测评、在线监测**三个层面，直接可落地执行。

---

## 一、测评目标与指标分层

召回评测回答三个问题：**该召回的召回了没（全）？召回的排得对不对（准）？不该来的有没有来（净）？**

| 层级 | 指标 | 定义 | 目标值 |
|---|---|---|---|
| **排序指标** | Recall@k | Top-k 内命中 gold 条目的比例（k=5/10） | ≥ 90%（@10） |
| | Precision@k | Top-k 内有效条目的比例 | ≥ 70% |
| | MRR | 首个 gold 条目的位置倒数（越高越靠前） | ≥ 0.7 |
| | NDCG@k | 排序质量（gold 应排前面） | ≥ 0.8 |
| **医疗专项** | 关键信息完整率 | 剂量/禁忌/时限等关键要素是否都在 Top-k 中 | **100%** |
| | 有害召回率 | 急症查询是否召回急救条目（应召回为 100%） | 0 漏报 |
| | 无关召回率 | 负样本问题强召回比例 | ≤ 10% |
| **工程** | P99 延迟 | 单查询端到端检索耗时 | ≤ 500ms |
| | 吞吐 | QPS | 视部署规模 |

## 二、测试集构建（测评的地基，80% 的功夫在这）

### 2.1 测试问题来源

| 来源 | 说明 | 占比建议 |
|---|---|---|
| **家长真实问题** | minicare 已有用户咨询/反馈；孕婴社区公开提问（脱敏后） | 60% |
| **医生/医学编辑拟题** | 覆盖知识清单 40 条目的"标准问法" | 25% |
| **边界/对抗题** | 口语化、错别字、方言、多实体混合、超范围问题 | 15% |

> ⚠️ 用社区问题需脱敏，不采集任何可识别个人信息；或仅作"表达形态参考"自拟。

### 2.2 分层抽样设计

按知识清单 **8 大模块分层**，保证每模块 ≥ 10 题；高危场景（F 急救、C5 检测指征、D4 配方）**强制覆盖 ≥ 5 题**：

| 模块 | 题目数 | 代表性问题（示例） |
|---|---|---|
| A 基础认知 | 10 | "牛奶过敏和不耐受是一回事吗？" |
| B 预防体系 | 15 | "宝宝 5 个月了，辅食什么时候加？要不要先避开鸡蛋花生？" |
| C 诊断检测 | 12 | "过敏原检测阳性就是过敏吗？" |
| D CMPA 专项 | 15 | "宝宝喝了奶粉就拉血便，是不是牛奶蛋白过敏？" |
| E 营养喂养 | 12 | "确诊牛奶过敏后怎么保证营养？要不要补钙？" |
| F 症状急症 | 12 | "宝宝吃了花生嘴唇肿了怎么办？"（高危） |
| G 长期管理 | 10 | "牛奶过敏什么时候能喝普通奶粉？" |
| H 就医联动 | 8 | "这种情况该挂儿科还是变态反应科？" |
| **负样本** | 6 | "宝宝可以吃燕窝吗？""如何选婴儿床？"（库外） |
| **合计** | **100** | 种子集可先做 50 条再扩展 |

### 2.3 标注规范（gold label 判定）

每条测试问题标注三类答案：

```json
{
  "question": "宝宝喝了奶粉就拉血便，是不是牛奶蛋白过敏？",
  "gold": ["KB-D1-001", "KB-C4-002"],
  "acceptable": ["KB-D2-001"],
  "negative": ["KB-B4-003"],
  "note": "gold=症状识别(必召回) + 回避-激发(次必)；acceptable=诊断路径；negative=辅食时机(应排后)"
}
```

**判定标准：**
- `gold`：不含该条目就无法正确回答
- `acceptable`：有助于回答，但非必需
- `negative`：与问题无关，若排进 Top-5 视为一次有害召回
- **双人标注 + 仲裁**：标注一致性（Cohen's κ）≥ 0.8 才视为合格

## 三、离线测评执行（迭代开发期）

### 3.1 测评流程（每次检索策略变更后必跑）

```
1. 固定测试集（100 题）与参数（k=5/10）
2. 跑检索 → 输出每题的 Top-k 结果
3. 与 gold/acceptable/negative 比对 → 算指标
4. 输出报告 + 错误分析
5. 对比上一个版本 → 判断"变好/变差/回归"
```

### 3.2 消融实验（定位哪个环节在起作用）

| 实验组 | 配置 | 目的 |
|---|---|---|
| A | 纯向量检索 | baseline |
| B | 向量 + BM25（RRF 融合） | 混合检索增益 |
| C | B + 查询改写 | 口语→医学概念增益 |
| D | C + 元数据过滤（年龄/模块） | 过滤增益 |
| E | D + 图谱实体链接 | 消歧增益 |
| F | E + reranker | 排序增益（另一评测线） |

> 每个实验输出同一指标表，可量化每个组件的贡献，决定是否值得投入。

### 3.3 错误分析（error analysis，必做）

把召回错误的题目**分类归因**，而不是只看总分：

| 错误类型 | 典型表现 | 修复方向 |
|---|---|---|
| 术语不匹配 | "便血" 命不中 含"血便"条目 | 同义词表/BM25 词形归一 |
| 口语未归一 | "拉肚子" vs "腹泻" | 查询改写补映射 |
| 多实体混合 | 一题含"牛奶过敏+湿疹+辅食" | 问题分解/图谱扩展 |
| 范围错配 | 问急症却召回科普 | 风险门控前置 |
| 粒度错配 | 命中模块级而非条目级 | 条目切分检查 |

## 四、医疗专项测评（独立于通用指标，一票否决）

### 4.1 关键信息完整率（硬指标）
对每道题定义"回答必需的关键要素"，检查它们**是否同时**出现在 Top-k 中：

| 领域 | 关键要素示例 |
|---|---|
| 配方选择（D/E） | eHF 与 AAF 的适用分界、初始疗程 6 个月、复评 3-6 月 |
| 辅食引入（B） | 4-6 月窗口、单一添加观察 2-3 天、不推迟致敏食物 |
| 急救（F） | 肌注肾上腺素一线、观察时限、双相反应 |
| 检测（C） | 不能脱离病史、不能预测严重程度 |

> 判定：任一关键要素缺失即该题**不通过**（无论通用指标多高）。

### 4.2 有害召回测试（安全向）

| 场景 | 输入示例 | 必须行为 |
|---|---|---|
| 急症必召回 | "吃花生后嘴唇肿了/喘不上气" | Top-1 必须命中急救条目 |
| 不淡化风险 | "湿疹有点严重要不要紧" | 召回 AD 护理 + 就医边界条目 |
| 不诱导自诊 | "我怀疑宝宝过敏要不要自己停奶粉" | 召回"回避需医生指导"条目 |

### 4.3 对抗与边界测试

- **口语/错别字**："宝宝喝奶拉希（稀）便便""鸡蛋过敏改吃鸭蛋行不"
- **方言表达**："宝宝不吃饭是积食还是过敏"（多义消歧）
- **超范围**："补铁辅食食谱""益生菌哪个牌子好" → 应低分或拒答（负样本）

## 五、在线监测（上线后持续）

### 5.1 查询日志埋点

```
每查询记录：
  query / 改写后 query / 用户年龄上下文 / 命中条目IDs / Top-5顺序
  / 用户是否展开"查看来源" / 是否反馈"不相关" / 答案采纳率
```

### 5.2 指标看板

| 指标 | 定义 | 报警线 |
|---|---|---|
| 无命中率 | 检索返回空/低分比例 | > 5% 触发查询改写补全 |
| 反馈率 | 用户点"不相关"占比 | > 8% 触发错误分析 |
| 高危命中率 | 高危问题命中急救条目的比例 | 100%（<100% 立即告警） |
| 引用展开率 | 用户点击"查看来源"的比例（信任信号） | 趋势监控 |

### 5.3 回归与回流闭环

- 线上 bad case → 加入测试集 → 修复 → 回归通过 → 发布
- 每月增量评测：新问题抽样入库，防测试集陈旧

## 六、工具与实现建议

### 6.1 评估脚本骨架（伪代码）

```python
def evaluate(retriever, dataset, k=10):
    rows = []
    for item in dataset:
        top_k = retriever.retrieve(item.question, k=k)  # 返回条目IDs
        gold = set(item.gold)
        hit = [d for d in top_k if d in gold]
        rows.append({
            "q": item.question,
            "recall@k": len(hit) / max(len(gold), 1),
            "mrr": 1/(first_gold_index+1) if any else 0,
            "ndcg@k": compute_ndcg(top_k, gold),
            "harmful": any(d in item.negative for d in top_k[:5]),
            "key_info_complete": check_key_info(top_k, item.key_info),
        })
    return aggregate(rows)  # 平均 + 按模块/类型分组
```

### 6.2 工具选型

| 环节 | 工具 |
|---|---|
| 通用指标计算 | Ragas（Recall/NDCG 等）或自研（推荐自研，可控） |
| 标注管理 | 表格（腾讯文档/CSV）+ 仲裁流程 |
| 检索基线 | 同一套索引不同策略配置对比 |
| 报告 | 每次跑批输出 CSV + 差异 diff |

## 七、执行建议（结合敏宝现状）

1. **先建种子测试集（50 题）**：由医学编辑/产品按上表 8 模块生成，双人标注——预计 1-2 天
2. **搭评估脚本 + baseline**：纯向量检索跑一轮，得指标基线（无论多差，先有基线）
3. **逐层加组件**（消融 A→F），每个组件看指标增量，决定是否保留
4. **高危场景专项先过**：急救 20 题先测（一票否决项），再跑通用集
5. **定"发布门槛"**：通用 Recall@10 ≥ 90%、关键信息完整率 100%、有害召回 0 才允许上线
