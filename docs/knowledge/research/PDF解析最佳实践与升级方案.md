# 敏宝知识库 · PDF 解析最佳实践与升级方案

> 生成时间：2026-08-19 ｜ 背景：当前 20 份源文件用 pypdf 直接提取文本，丢失标题层级、表格结构、图片、双栏阅读顺序等关键信息。本文调研行业最佳实践，给出升级方案。

---

## 一、当前解析的问题诊断

用 pypdf/pdfminer 直接提取文本（现 `源文件解析文本/*.txt`），对照行业标准存在四类信息损失：

| 问题类型 | 具体表现 | 对知识库的影响 | 实测样例（2025 过敏共识） |
|---|---|---|---|
| **双栏混排** | 左右栏文字交错拼接，段落被切断 | 检索到的是语义断裂的文本碎片，gold 标注失准 | 中文正文与英文摘要逐行交错混排 |
| **页眉页脚污染** | 期刊名、页码、"·354·"等混入正文 | 污染 chunk，产生无意义召回 | 每页混入"中国妇幼卫生杂志 2025 年 10 月…" |
| **结构层级丢失** | 标题层级（1/2/3 级）、列表结构丢失 | 无法按标题分块，父子分块无依据 | 标题与正文混成一段连续文本 |
| **图表/公式全丢** | 表格结构坍塌、图片无描述、公式变乱码 | 配方阶梯表、剂量表、流程图等关键信息不可检索 | 表格行被压成单段 |

**结论**：现方案满足"文本可检索"底线，但达不到医疗知识库"证据可溯源、结构可分块、表格可查询"的要求。解析层是知识库的地基——行业共识是**解析器决定一切**（ClinRAG 实战报告：解析质量差时，"无论 embedding 多好、检索策略多先进，RAG 都建在沙子上"）。

## 二、行业标准解析流水线（五层）

现代文档解析不是"一个工具转文本"，而是一条流水线：

```
PDF 页面
  │
  ├─ ① 版面分析（Layout Analysis）
  │     用深度学习模型把页面划分为：正文/标题/表格/图片/页眉/页脚/公式 区域
  │     模型：DocLayNet、PP-StructureV3、LayoutLMv3、YOLO 系
  │
  ├─ ② 阅读顺序重建（Reading Order）
  │     按版面区域排序恢复正确阅读顺序（解决双栏/图文混排）
  │     依据区域坐标 + 语义关系模型
  │
  ├─ ③ 内容识别（按区域类型分流）
  │     ├─ 文本区 → 文本抽取（原生文本或 OCR）
  │     ├─ 表格区 → 表格结构识别（TableFormer/RapidTable，转 HTML/Markdown）
  │     ├─ 图片区 → 图片裁剪 + 视觉模型生成图注（图 + 描述双存）
  │     └─ 公式区 → 公式识别（转 LaTeX）
  │
  ├─ ④ 结构化输出（Markdown/JSON）
  │     保留标题层级、列表、表格、图注、代码块；可选去除页眉页脚
  │
  └─ ⑤ 语义分块 + 元数据标注（知识库侧）
        按标题/语义切块，每块打上：来源、页码、证据级别、风险分级、文档版本
```

**关键认知**：解析的产出物应是**带结构的 Markdown/JSON**（含元数据），不是纯文本。这直接决定下游能否做"按标题分块、父子分块、表格独立成块"。

### 商用 / 云 API（数据出域需评估合规）

| 方案 | 特点 | 适用 |
|---|---|---|
| Mathpix | 公式/表格识别业界最强，有校对编辑器 | 高质量要求、预算充足 |
| LlamaParse / Mistral OCR / Azure Document Intelligence | 云 API 简单，需网络 | 不想自建、数据可出域 |
| 阿里云文档智能 / 腾讯 TextIn | 国内云，中文好 | 国内合规数据管线 |
| NetMind ParsePro 等 | H100 集群托管 | 规模化 |

### VLM 直接解析（前沿趋势）

把 PDF 页光栅成图像直接喂多模态模型输出 Markdown，绕过坐标/字体/阅读顺序问题：
- 闭源：Gemini 2.5 Pro / GPT-4o（综合最强）
- 开源：Qwen2.5-VL-72B、InternVL3、DeepSeek-OCR（中文强）
- 轻量：Phi-4、Pixtral 12B

适用：极复杂版式（杂志、非标准排版）、扫描件。对标准医学期刊版式，MinerU 已足够，VLM 成本高、速度慢，作为兜底补充。

## 四、针对敏宝 20 份资料的落地建议

### 4.1 推荐路线：MinerU 为主 + PyMuPDF 兜底

**为什么选 MinerU**：
1. **中文医学文档最优**——20 份资料中国内 7 份为中文双栏期刊排版，正是 MinerU 强项（中文 TED-Struct 满分、自动去页眉页脚）
2. 国际指南（EAACI/NIAID/DRACMA）为英文单栏或双栏，MinerU 同样处理良好
3. Apache-2.0 可商用、持续更新、支持 Apple Silicon（MPS 模式，本机 macOS 可直接跑）
4. 输出 Markdown + JSON（含版面框坐标），可直接对接语义分块

**执行步骤**：
```bash
pip install "magic-pdf[full]"          # 安装 MinerU
# 配置 ~/magic-pdf.json 启用 rapid_table + formula + mps
magic-pdf -p 源文件/国内/xxx.pdf -o 源文件解析v2/ -m auto -l ch
```
产出：每份 PDF → `.md`（带标题层级/表格/图注）+ `.json`（版面元数据）+ 图片目录。

**验证门禁**（解析质量可量化）：
- 双栏文档抽查 3 份，人工核对阅读顺序正确率 ≥ 95%
- 表格抽查（配方阶梯表、剂量表）HTML 结构完整率 100%
- 页眉页脚残留 0
- 标题层级与原文章节一一对应

### 4.2 知识库侧配套改造

| 环节 | 现状 | 升级后 |
|---|---|---|
| 存储格式 | `.txt` 纯文本 | `.md` 结构化 + `.json` 版面元数据 |
| 分块策略 | 无（整文件） | 按标题层级切块（父块=章节，子块=段落/表格），表格独立成块 |
| 图片处理 | 全部丢失 | 图片裁剪保存 + VLM 生成图注，图注入块；关键图表（流程图/阶梯图）人工补描述 |
| 元数据 | 无 | 每块标注：来源文档/页码/文档版本/证据级别/风险分级（复用《Agent知识库建设方案》的 schema） |
| 溯源 | 无 | 块 ↔ 原文 PDF 页码双向索引，回答可点击跳转原图/原文 |
| 版本管理 | 无 | 记录解析工具版本+日期，指南更新时重解析对应文件 |

### 4.3 分档处理策略（按文档复杂度）

| 文档类型 | 示例 | 解析策略 |
|---|---|---|
| 中文双栏期刊（扫描/文字混合） | 2025 过敏共识、AD 外用共识、严重过敏反应共识 | MinerU（OCR 兜底扫描页） |
| 中文双栏期刊（数字原生） | 用户提供的 2 份 CMPA PDF | MinerU（文字层为主，更快） |
| 国际英文指南 | EAACI/NIAID/DRACMA | MinerU 或 Marker（英文更快） |
| 纯网页归档 | FDA 公告、HealthyChildren、卫健委 HTML | 无需 PDF 解析，直接用 HTML→Markdown（`markitdown` 或自写提取器） |
| 政策文件 HTML | 卫健委喂养评估指南、广东共识 | 同上 |

| 阶段 | 动作 | 成本 | 产出 |

## 六、风险与注意

1. **MinerU 首次加载慢**（模型加载 30-60 秒），批量跑一次即可，不影响后续使用
2. **扫描件质量差的页面**可能识别错误——关键条目（剂量/禁忌）需人工对照原文复核
3. **商业合规**：MinerU Apache-2.0 无问题；若后续用云 API（TextIn 等）需数据出域合规评估
4. **医学审核不变**：无论解析多好，LLM 抽取/生成的高危关系仍须医学人工审核（与《知识图谱-概念层设计》结论一致）
5. 解析升级后，**旧 `.txt` 文件保留**（作对照基线），`源文件获取状态清单.md` 中登记解析工具版本
