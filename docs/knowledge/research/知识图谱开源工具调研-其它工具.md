## 二、Graphiti（Zep）—— 实时时态知识图谱

| 项 | 信息 |
|---|---|
| Stars | **~22.9k**（2026 中，活跃） |
| 许可证 | Apache-2.0 ✅ |
| 论文 | arXiv:2501.13956《Zep: A Temporal Knowledge Graph Architecture for Agent Memory》 |
| 团队 | Zep（其商业平台的核心引擎开源） |

### 核心特性
- **双时间模型（Bi-temporal）**：每条事实同时记录"事件发生时间"和"摄入时间"，支持点/时间段历史查询（"某日期时知识状态"），矛盾事实自动时间失效而非删除——**审计友好**
- **增量实时构建**：以 Episode 为单位增量入库，无批处理重算（对比 GraphRAG 的批处理）
- **混合检索**：语义向量 + BM25 + 图遍历，检索期无 LLM 调用，**亚秒级**
- **自定义实体**：Pydantic 定义节点/边，适配领域本体
- **多后端**：Neo4j / FalkorDB / Kuzu / Amazon Neptune（可插拔）
- **MCP Server + REST**：供 Claude/Cursor 或自建前端集成
- **社区检测**：自动聚类层次化知识组织

### 敏宝适配判断
✅ 增量更新（新指南发布只补相关 Episode）、时间感知（指南版本时间线）、混合检索（亚秒）、MCP 接入
⚠️ 定位偏"Agent 长期记忆/动态对话数据"，对"20 份静态权威文档+严格 Schema+逻辑推理"场景，逻辑形式推理不如 KAG 设计
📌 定位：**敏宝的"活跃落地底座"候选**（相比 LightRAG 多了时间模型与更强图能力，相比 KAG 生态活跃）

## 三、GraphScope（阿里）—— 一站式图计算

| 项 | 信息 |
|---|---|
| Stars | ~3k+（持续增长） |
| 许可证 | Apache-2.0 |
| 定位 | 分布式图计算平台：图分析（GRAPE）+ 交互查询（GIE）+ 图学习（GL），Vineyard 内存存储 |
| 现状 | 演进到 **GraphScope Flex**（模块化），2025-04 LDBC SNB 交互负载破纪录（2.0× 吞吐） |

### 特点
- Python 原生接口，K8s/standalone 部署
- 100+ 图算法、Gremlin/Cypher 支持
- 论文顶会产出（SIGMOD 最佳论文、VLDB 等）

### 敏宝适配判断
⚠️ GraphScope 定位是**大规模图计算引擎**（数亿边、风控/推荐场景），敏宝 400-600 三元组规模**严重过重**
📌 不推荐直接使用；可借鉴其"图分析算法"（社区发现/PageRank）思路用于图谱后处理

## 四、HugeGraph（百度 → Apache 顶级）

| 项 | 信息 |
|---|---|
| 出身 | 百度开源 → 捐赠 Apache 软件基金会（顶级项目） |
| 许可证 | Apache-2.0 |
| 能力 | 图数据库：Gremlin + Cypher 查询、图分析算法、可视化组件 |
| 特点 | 国产、企业级（百度内部大规模验证）、文档中文友好 |

### 敏宝适配判断
✅ 若需"国产可商用图库 + 中文文档"，HugeGraph 是 Neo4j 的国内替代
⚠️ 仍需独立服务部署（对比 Kuzu 嵌入式）；400-600 三元组规模用嵌入/单机图库更轻
📌 定位：**敏宝图存储的"国产服务端"备选**（Kuzu 嵌入式 → HugeGraph 服务端，视部署形态）

## 五、生物医学知识图谱构建

### BioCypher
- 定位：**生物医学知识图谱**构建框架（面向 bioinformatics），统一"数据→图谱"流水线
- 特点：面向生命科学本体（基因/蛋白/疾病/通路）、适配 Neo4j、模块化 ETL
- 敏宝：英文生物医学通用层可参考，**婴幼儿过敏专科价值有限**（过敏类知识非其重点）

### OntoGPT（斯坦福，Monarch Initiative）
- 定位：**本体引导的 LLM 抽取**（Ontology-Guided GPT），从文本抽取结构化知识并映射到现有本体
- 特点：可定义 schema（YAML），输出严格符合本体的三元组；生物医学本体丰富（HPO 等）
- 敏宝：**可借鉴**——用 OntoGPT 思路定义"敏宝 Schema（YAML）"引导抽取，输出对齐 HPO/DO

## 八、敏宝选型结论（三篇汇总更新）

| 需求 | 推荐 |
|---|---|
| **端到端**（逻辑推理优先） | KAG 架构（若接受冻结则直接用；否则借鉴其思想） |
| **端到端**（活跃生态优先） | **Graphiti** 或 LightRAG 为底座 |
| **增量更新+时间线** | Graphiti（唯一原生双时间） |
| **中文抽取** | CMeKG_tools + OneKE |
| **本体引导抽取** | OntoGPT 的 Schema 思路 |
| **嵌入式存储** | Kuzu |
| **国产服务端图库** | HugeGraph |

**最终建议路径**：
1. **Phase 0 原型**：用 KAG medicine 示例验证"逻辑推理"价值（1-2 天）
2. **底座选型决策**：
   - 逻辑推理价值高 + 接受冻结维护 → KAG 直用
   - 否则 → **Graphiti（活跃、时态、混合检索）** 为底座 + 自建 Schema/溯源/审核层
3. 存储 Kuzu（嵌入）起步，规模大再迁 HugeGraph/Neo4j
