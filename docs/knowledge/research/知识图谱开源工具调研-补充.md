## 一、重点发现：KAG —— 最贴合敏宝场景的开源框架

**KAG（Knowledge Augmented Generation）**，蚂蚁集团开源，github.com/OpenSPG/KAG

| 项 | 信息 |
|---|---|
| 定位 | **专业领域知识增强生成框架**（图谱+大模型结合），专为"垂直领域知识库逻辑推理+事实性问答"设计 |
| 技术栈 | OpenSPG（语义图谱）+ TuGraph-DB（图存储）+ 大模型 |
| 许可证 | Apache-2.0 |
| 已验证场景 | 政务问答准确率 91%、**医疗指标解读准确率 90%+**（支付宝"支小宝"） |
| 医学示例 | 自带 `examples/medicine/`（医学图谱构建 + 问答 demo） |

### KAG 五大核心增强（对敏宝的对应价值）

| KAG 能力 | 说明 | 对敏宝的意义 |
|---|---|---|
| 1. LLM 友好知识表示（LLMFriSPG） | 兼容有 Schema/无 Schema 知识构建，图谱与文本分层表示 | 先有概念层 Schema，再灵活抽取 |
| 2. 图谱与文本互索引 | 图谱节点 ↔ 原文片段双向索引，可溯源 | **对应敏宝"溯源到源文件+页码"硬需求** |
| 3. 逻辑符号引导混合推理 | 图谱推理+逻辑计算+chunk 检索+LLM 推理四合一 | 支持"3 月龄/已确诊/回避中"等条件推理 |
| 4. 语义知识对齐 | 概念对齐提升领域专业表现 | 家长口语→医学概念对齐 |
| 5. KAG-Model（指令合成） | 小模型逼近大模型效果，降成本 | 降低部署成本 |

### KAG vs 已有备选（敏宝语境）

| 维度 | KAG | LightRAG | Microsoft GraphRAG |
|---|---|---|---|
| 领域适配 | **医学已验证 ✅** | 通用 | 通用 |
| 逻辑推理 | **强（符号引导）** | 中 | 中 |
| 溯源展示 | **图谱↔文本互索引，可解释** | 一般 | 一般 |
| 构建成本 | 中（需 Schema） | 低 | 高 |
| 增量更新 | 支持 | 支持 | 不支持 |
| 适用规模 | 中小/专业领域 | 中小 | 大规模 |

> **判断**：若敏宝要"专业领域 + 严谨推理 + 可解释溯源"，**KAG 是最优选**（比 LightRAG 更专业，比 GraphRAG 更轻且支持增量）。配合 OpenSPG 已有医疗案例。

## 二、CMeKG / CMeKG_tools —— 中文医学图谱现成资产

| 项 | 信息 |
|---|---|
| 定位 | **中文医学知识图谱**（覆盖 10 万+ 医学实体、多关系，开放下载）+ 配套工具包 |
| CMeKG_tools | 医学分词（BERT-LSTM-CRF）+ 医学实体识别（疾病/症状/药物/检查）+ 关系抽取（18-24 种医学关系） |
| 来源 | 高校/科研机构构建，开源可商用（以仓库 LICENSE 为准） |
| 对敏宝价值 | ① 预训练医学 NLP 模型可直接用于抽取 ② 实体/关系体系可**对齐**敏宝概念层（避免自造词）③ 关系类型可参考扩展 |

**注意**：CMeKG 是"通用中文医学图谱"，不含婴幼儿过敏专项知识；敏宝应**复用其工具与词表，构建自己的领域子图**，而非直接依赖其图谱数据。

## 三、RDF / 语义网生态（补充存储与查询选项）

| 工具 | 语言 | 特点 | 适用 |
|---|---|---|---|
| **RDFLib** | Python | RDF 处理事实标准库，SPARQL 查询 | 轻量建模/验证 |
| **Oxigraph** | Rust | 嵌入式 SPARQL 引擎，高性能 | 轻量 RDF 存储 |
| **Blazegraph** | Java | 开源 RDF 三元组库，Wikidata 曾用 | RDF 大数据 |
| **Apache Jena + Fuseki** | Java | RDF/SPARQL + 推理（已列入主调研） | 标准语义栈 |
| **Virtuoso（开源版）** | C | 图+关系+文档混合存储 | 大规模 RDF |

> **敏宝判断**：本项目是"内部知识服务"而非公开语义网发布，**RDF/SPARQL 体系非必需**；图存储仍推荐 Kuzu/SQLite（嵌入）或 TuGraph-DB（KAG 配套）。

## 四、生物医学 NLP 工具（补充抽取/标注选项）

| 工具 | 说明 | 对敏宝 |
|---|---|---|
| **SciSpacy**（scispaCy） | 生物医学文本 NLP（NER/依赖），英文医学实体 | 处理英文指南（EAACI/NIAID） |
| **PubTator Central** | 生物医学实体自动标注 API（基因/疾病/化学物） | 英文文献实体标注 |
| **BioBERT / PubMedBERT** | 生物医学预训练模型 | 英文医学语义检索嵌入 |
| **MediLexicon / UMLS 映射** | 医学词表标准化 | 概念归一（CMPA↔CMA） |

> 敏宝语料中文为主 → 中文侧用 CMeKG_tools/OneKE；英文指南侧用 SciSpacy/BioBERT。

## 五、LangChain LLMGraphTransformer（低门槛上手）

- 功能：`LLMGraphTransformer` 一行配置，把文本块用 LLM 抽取为节点/关系，写入图库（Neo4j 等）
- 价值：**快速原型**——用已解析的 20 份文本几分钟出图谱雏形
- 局限：抽取质量依赖 LLM、需人工审核（与所有 LLM 抽取一致）
- 定位：适合"先看效果"，正式构建仍建议 OneKE/KAG 流水线 + 审核

## 九、敏宝最终选型建议（更新）

| 层次 | 推荐 | 备选 |
|---|---|---|
| **端到端框架** | **KAG（蚂蚁，医学已验证）** | LightRAG（快速原型） |
| **中文抽取** | CMeKG_tools（现成医学模型）+ OneKE | DeepKE |
| **图存储** | TuGraph-DB（KAG 配套） | Kuzu（嵌入） |
| **英文指南抽取** | SciSpacy | BioBERT |
| **概念对齐** | HPO + CMeKG 词表 + 概念字典 | DO/ICD |
| **可视化** | ECharts 关系图 | Cytoscape.js |

**三步落地**：
1. **原型验证**：LangChain LLMGraphTransformer 或 LightRAG 跑通"20 份文本 → 图谱雏形"
2. **正式构建**：KAG + OpenSPG，用 CMeKG_tools/OneKE 抽取，人工审核三元组
3. **问答接入**：KAG Solver 混合推理，接《召回质量测评方案》验证
