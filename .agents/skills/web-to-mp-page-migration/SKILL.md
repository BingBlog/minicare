# Web→MP 页面迁移 Skill

## 适用范围与目标

本 Skill 适用于以下场景：

- 用户要求将某个 `minicare-web` 页面迁移到 `minicare-mp`
- 用户要求 Web 与 MP 页面在逻辑、样式、交互上保持一致
- 用户要求对已迁移页面进行结构重整（复用、抽离、可读性优化）

目标：

1. 在业务语义层面实现“行为一致”
2. 在视觉与交互层面实现“体验一致”
3. 在工程结构层面实现“可维护、可复用、可扩展”

---

## 一致性优先级模型（Migration Parity Model）

迁移一致性分为三层，验收优先级如下：

1. `BusinessParity`（最高）
   - 字段语义、业务规则、排序、状态计算、边界行为一致
2. `InteractionParity`
   - 用户路径一致：点击、弹层、编辑、删除、导航、重试一致
3. `VisualParity`
   - 样式与视觉一致：字号、颜色、间距、层级、对齐一致

判定规则：

- 必须先满足 `BusinessParity`
- `InteractionParity` 不得破坏业务语义
- `VisualParity` 不得通过牺牲语义换取“看起来像”

---

## 页面迁移完整流程（Gated Workflow）

必须按以下 6 个阶段执行。每个阶段都有门禁，未通过不得进入下一阶段。

### 阶段 1：Web 页面全量分析

输入：

- 目标页面入口文件（如 `index.tsx`）
- 同目录组件文件（如 `HeroSection.tsx`、`TodayTimeline.tsx`）
- 关联依赖（`lib`、`api`、`components`）

动作：

- 梳理页面文件拓扑：入口、子组件、工具、常量、样式
- 梳理数据流：API -> adapter -> view model -> 组件渲染
- 梳理交互流：点击、弹层、导航、编辑、删除、排序等

产出：

- 页面依赖清单（文件粒度）
- 业务规则清单（字段解释、排序规则、映射规则）
- 交互能力清单（包括依赖的库能力）

通过标准：

- 任何一个 UI 区块都能追溯到其来源文件和规则
- 已明确所有“规则源文件”（常量、工具、配置）

Exit Criteria：

- 已给出“文件拓扑 + 数据流 + 交互流”三份结果

Evidence（必须留痕）：

- 文件粒度依赖清单
- 关键数据流说明（API -> adapter -> UI）
- 关键交互链路说明（触发 -> 状态变化 -> 结果）

---

### 阶段 2：复用性判定（可复用 / 不可复用）

动作：

- 对 Web 页面涉及的每个文件做复用等级判定：
  - `L1 完全复用`：纯函数、常量、映射规则、排序规则
  - `L2 结构复用`：组件职责和拆分方式复用，视图代码重写
  - `L3 语义复用`：目标一致，技术实现差异化

产出：

- 文件粒度复用判定表（见本 Skill 模板）

通过标准：

- 每个文件都有明确复用等级和处理策略
- 差异化项有明确理由（平台限制/运行时差异）

Exit Criteria：

- 文件级别复用等级覆盖率 100%

Evidence（必须留痕）：

- 文件粒度复用判定表（L1/L2/L3）
- 差异化理由清单（逐条可追溯）

---

### 阶段 3：可复用部分保持绝对一致

动作：

- 迁移 `L1` 内容时保持语义与规则 1:1
- 禁止“同义改写”导致规则漂移
- 规则源只能有一份，禁止复制多份常量和映射

通过标准：

- 排序、映射、字段语义与 Web 对照完全一致
- 关键逻辑不出现“双份定义”

Exit Criteria：

- `BusinessParity` 核心规则对齐完成

Evidence（必须留痕）：

- 规则源文件对照（web->mp）
- 关键纯函数/常量映射清单

---

### 阶段 4：差异化部分按规则处理

动作：

- 对不可直接复用项，按差异化规则进行适配（见清单）
- 先保语义一致，再做实现替换
- 所有差异化实现必须可解释且可回溯

通过标准：

- 差异化仅发生在“允许差异”白名单内
- 白名单外差异必须回退修正

Exit Criteria：

- 非白名单差异为 0

Evidence（必须留痕）：

- 差异化处理日志（差异点、原因、替代方案、风险）

---

### 阶段 5：文件粒度对比复核（迁移后）

动作：

- 按文件对照表逐项检查：职责、逻辑、样式、交互
- 对关键路径做回归检查（空态、错误态、加载态、编辑态）
- 若存在不通过项，进入“验收失败闭环修复流程”（见下文），修复后回到本阶段复核

产出：

- 最终文件粒度对比结果（含遗留差异与风险）

通过标准：

- 所有核心路径达到“逻辑一致 + 表现一致”
- 遗留差异必须有业务可接受说明

Exit Criteria：

- 对比表覆盖率 100%，核心路径回归通过

Evidence（必须留痕）：

- 文件粒度对比表
- 回归用例执行结果

---

## 验收失败闭环修复流程（最多 5 次）

当阶段 5 验收出现不通过项时，必须执行以下闭环：

1. 记录不通过项
   - 标注文件、问题类型（Business/Interaction/Visual）、严重级别
2. 自主修复
   - 优先修复 `BusinessParity`，其次 `InteractionParity`，最后 `VisualParity`
3. 立即复验
   - 回到阶段 5，使用同一对比模板重新验收
4. 持续迭代
   - 若仍有不通过项，重复步骤 1-3
   - 总迭代次数不得超过 5 次

执行授权规则：

- 在 5 次迭代上限内，Agent 默认获得“自动修复 + 自动复验”授权
- 5 次内每一轮修复无需再次征求用户同意
- Agent 仅需在每轮结束后同步阶段结果（通过项/未通过项/下一轮计划）

迭代上限规则：

- 第 1-4 次：必须继续“修复 + 复验”
- 第 5 次后仍不通过：必须停止继续修改，输出“阻塞清单”

阻塞清单必须包含：

- 未通过项列表（文件粒度）
- 根因分析（平台限制/依赖缺失/需求冲突）
- 建议方案（临时方案 + 最终方案）
- 风险评估（影响范围）

---

### 阶段 6：按最佳实践重组文件与注释

动作：

- 页面瘦身：入口页面仅保留编排与状态装配
- 抽离业务规则到 `lib`/`adapters`/`constants`
- 注释统一描述“为什么”，避免注释无意义的“做了什么”

通过标准：

- 组件职责边界清晰
- 规则集中，复用入口明确
- 新成员可在低上下文成本下读懂页面

Exit Criteria：

- 页面组件复杂度明显下降（仅保留编排）

Evidence（必须留痕）：

- 抽离前后文件职责对照
- 新增/调整的公共模块清单

---

## 数据契约检查（强制门禁）

在进入编码前必须完成接口与数据契约校验：

1. 响应结构契约
   - 确认是否有包装层（如 `data`）或裸对象
2. 字段可空性契约
   - 明确 `null/undefined/空字符串` 的业务语义
3. 枚举契约
   - 枚举值全集、默认值、未知值 fallback
4. 时间契约
   - 时间字段格式、时区、展示格式、排序字段优先级
5. 子类型契约
   - 如 `feeding` 子类型（formula/breast/complementary/supplement）及其明细字段

未完成数据契约检查，不得开始 UI 对齐。

## 路由注册强制门禁（MP 必做，3 处同步注册）

**每创建一个新的 MP 页面，必须在以下 3 个位置同步注册路由。漏任何一处都会导致导航失败或回退到中间分发页。**

### 1. `src/app.config.ts` — Taro 框架页面注册

```ts
pages: [
  // ...
  'pages/records/<page>/index',  // 新增
]
```

注册后 Taro 编译器才会将这个页面纳入构建。缺失则页面不可访问。

### 2. `src/lib/constants.ts` → `HOME_RECORD_MP_ROUTES` — 首页直达映射

```ts
export const HOME_RECORD_MP_ROUTES: Record<string, string> = {
  // ...
  '/records/form/<key>': '/pages/records/<page>/index',  // 新增
}
```

`HOME_RECORD_ROUTES[key]` 产生 Web 路径（如 `/records/form/sleep`），`HOME_RECORD_MP_ROUTES` 将其映射到 MP 真实路径。首页 `navigateToRecord()` 优先查此表，命中则直接跳转；缺失则回退到 `/pages/records/index?target=...` 分发器。

### 3. `src/pages/records/index.tsx` → `MP_ROUTE_MAP` — 分发器降级映射

```ts
const MP_ROUTE_MAP: Record<string, string> = {
  // ...
  '/records/form/<key>': '/pages/records/<page>/index',  // 新增
}
```

当 `HOME_RECORD_MP_ROUTES` 缺失导致路由进入分发器时，此表作为二次解析。两表都缺失则分发器展示「目标页面尚未迁移」降级 UI。

### 路由流转链路

```
首页 QuickAction/FabSheet
  → HOME_RECORD_ROUTES[key]              // e.g. '/records/form/sleep'
  → HOME_RECORD_MP_ROUTES[path]          // 查表 1：直接跳转 MP 页面 ✓
     ↓ 缺失
  → /pages/records/index?target=...      // 进入分发器
  → MP_ROUTE_MAP[targetPath]             // 查表 2：分发跳转 ✓
     ↓ 缺失
  → 「目标页面尚未迁移」降级 UI          // 阻塞
```

### 验证清单

- [ ] `app.config.ts` pages 数组已包含新页面
- [ ] `HOME_RECORD_MP_ROUTES` 已包含 Web 路径 → MP 路径映射
- [ ] `MP_ROUTE_MAP` 已包含 Web 路径 → MP 路径映射
- [ ] 首页快捷操作点击能直接进入页面（不经分发器）
- [ ] 分发器 `target=<Web路径>` 也能正确跳转

## Web→MP 必须完全复用规则清单

以下项必须保持与 Web 一致，不允许语义偏移：

1. 业务字段解释规则（如 `feeding` 子类型、`detail` 字段语义）
2. 排序与分组规则（类型顺序、时间顺序、分组头策略）
3. 文案语义规则（状态文案、空态文案、摘要文案）
4. 配置常量来源（key/group/route/subtitle/order 等）
5. 组件职责分层（页面编排 vs 业务规则 vs 展示组件）
6. API 响应解析层级（字段读取路径一致）
7. 状态计算逻辑（统计卡片、banner 状态判断、最近记录计算）

强制要求：

- 同一规则只允许一个权威来源
- 不允许在页面和工具层重复定义同一规则

---

## Web→MP 差异化处理规则清单（允许差异）

以下项允许实现差异，但必须保持语义一致：

1. 路由与导航实现
   - Web：`react-router-dom`
   - MP：`Taro.navigateTo/reLaunch` 等
2. 本地存储实现
   - Web：`localStorage`
   - MP：`Taro.getStorageSync/setStorageSync`
3. 网络约束与配置
   - MP 需处理合法域名与开发工具网络限制
4. 样式技术栈
   - Web：Tailwind/DOM 结构
   - MP：Taro 组件 + SCSS
5. 交互能力替代
   - 如 dnd、portal、浏览器特有交互需替换为 MP 可行方案

约束：

- 仅允许上述白名单差异
- 每个差异点必须在对比表中标注原因
- 白名单外差异必须在评审中单列并给出回退方案

## 文件组织规范（复用性与易读性）

### 强制规则：MP 组件拆分必须与 Web 1:1 对应

**MP 迁移页面中的子组件文件必须和 Web 同名、同职责、同接口——禁止将所有组件内联到一个 `index.tsx`。**

这是硬性门禁，理由如下：

1. **对比复核的前提**：文件粒度对比表要求逐文件对应，组件合并后无法定位差异来源
2. **后续迁移的可复用性**：其他页面迁移时，同名组件可直接复用结构模板
3. **维护一致性**：Web 侧修改某组件时，MP 侧可通过文件名直接定位对应文件

```
Web 结构                     MP 结构（必须一致）
pages/feeding/              pages/records/feeding/
├── index.tsx                ├── index.tsx          ← 页面编排（瘦）
├── TabSelector.tsx           ├── TabSelector.tsx    ← 同名、同职责
├── FormulaSection.tsx        ├── FormulaSection.tsx
├── BreastSection.tsx         ├── BreastSection.tsx
├── SupplementSection.tsx     ├── SupplementSection.tsx
├── FoodSection.tsx           ├── FoodSection.tsx
└── types.ts                  └── types.ts           ← L1 可直接复用
```

### 允许合并的情况
- 仅当 Web 侧组件是**纯展示**且**少于 30 行**时，可合并到父组件
- 工具函数（scoopUtils 等）统一放 `lib/`，不走组件文件

### 推荐结构
```text
pages/<page>/
├── index.tsx            # 页面编排与状态装配（瘦）
├── index.scss           # 页面样式入口
├── types.ts             # 页面内类型定义
├── <Section>.tsx        # 展示组件（与 Web 1:1 对应）
└── <page>Records.ts     # 该页面业务规则（adapter/display rules）

lib/
├── constants.ts         # 全局常量与标签映射
├── recordsSort.ts       # 通用排序规则
└── utils.ts             # 通用工具函数
```

### 组织原则

- 页面组件不承载大段业务判断
- 规则函数可单测（纯函数优先）
- 配置常量统一收口，禁止分散硬编码

---

## 迁移反模式清单（禁止）

以下做法一律判定为不通过：

1. 在页面组件中内联大段业务规则（排序、映射、摘要生成）
2. 同一规则在多个文件重复定义（如 route map、type order、label map）
3. 仅对齐样式，不对齐业务字段语义
4. 将“平台限制导致的改动”扩散到业务规则层
5. 未经说明删除 Web 已有边界行为（空态/错误态/重试/鉴权失效）
6. 将 Web 中的多个子组件合并/内联到 MP 的单一 `index.tsx`（详见 §文件组织规范 · 强制规则）

---

## 性能与体积检查（MP 必做）

迁移完成后增加 MP 侧质量门禁：

1. 首屏可用时间（含加载态）是否可接受
2. 关键交互是否存在明显卡顿（弹层、切换、排序）
3. 组件渲染是否存在重复/冗余计算
4. 资源体积与图片策略是否合理（避免无必要大图）

说明：

- 性能优化不得破坏 `BusinessParity`
- 任何性能改造都必须保留可读性与可回归性

---

## 文件粒度对比模板（必须产出）

迁移完成后，按以下表格对比：

| Web 文件 | MP 对应文件 | 职责一致性 | 逻辑一致性 | 样式一致性 | 复用等级 | 差异原因 |
|---|---|---|---|---|---|---|
| `web/pages/x/index.tsx` | `mp/pages/x/index.tsx` | ✅/⚠️/❌ | ✅/⚠️/❌ | ✅/⚠️/❌ | L1/L2/L3 | 说明 |
| `web/pages/x/Timeline.tsx` | `mp/pages/x/Timeline.tsx` | ✅/⚠️/❌ | ✅/⚠️/❌ | ✅/⚠️/❌ | L1/L2/L3 | 说明 |
| `web/lib/records-sort.ts` | `mp/lib/recordsSort.ts` | ✅/⚠️/❌ | ✅/⚠️/❌ | N/A | L1 | 说明 |

判定要求：

- `逻辑一致性` 优先级最高
- `样式一致性` 不通过时必须给出具体节点差异

## 最终验收清单（必须全通过）

### A. 功能与逻辑

- [ ] 关键业务规则与 Web 完全一致
- [ ] 排序/分组/摘要/状态计算一致
- [ ] 空态、加载态、错误态行为一致

### B. 样式与交互

- [ ] 字号、颜色、层级、间距达到页面级一致
- [ ] 核心交互流程一致（点击、弹层、切换、编辑）

### C. 工程质量

- [ ] 页面瘦身完成，业务规则已抽离
- [ ] 常量与配置集中管理，未出现重复定义
- [ ] 文件命名与注释清晰，易读性达标

### D. 迁移文档化

- [ ] 已输出文件粒度对比表
- [ ] 已标注所有差异化点及理由
- [ ] 可作为下一页面迁移的复用模板

### E. 数据契约与回归

- [ ] 数据契约检查已完成并留痕
- [ ] 核心状态机路径（加载/空态/错误/成功/重试）已回归

### F. MP 专项质量

- [ ] 小程序侧性能与体积检查通过
- [ ] 差异化点均在白名单内且可追溯

### G. 闭环修复与复验

- [ ] 若存在不通过项，已执行“验收失败闭环修复流程”
- [ ] 修复与复验迭代次数 <= 5
- [ ] 超过上限时，已输出阻塞清单并停止修改

## 最小回归用例集模板（建议至少 12 条）

1. 正常加载（有数据）
2. 空列表
3. 后端 4xx（含鉴权失败）
4. 后端 5xx
5. 超时与网络失败
6. 枚举未知值 fallback
7. 时间字段异常值处理
8. 子类型分支（如 feeding 四子类型）
9. 编辑态交互
10. 弹层开关与遮罩行为
11. 关键导航跳转
12. 重试与恢复路径

## 执行要求（对使用本 Skill 的 Agent）

- 先分析，后编码；未完成阶段门禁不得推进
- 优先复用规则，不优先复用 UI 代码
- 对任何“看似合理但与 Web 规则不一致”的实现，一律判定为不通过
