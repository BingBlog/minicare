# 切块方案 × Embedding 模型 2×2 对比评测报告

> 日期：2026-08-23 ｜ 测试集：召回测试集-种子50题（45 题）
> 检索：纯向量 top10（本对比聚焦 embedding 与切块差异，未叠加 FULLTEXT）
> 对比基准：生产链路为**混合检索（FULLTEXT + 向量 RRF）→ Recall@10 = 97.8%**

## 一、对比结果

| 组 | 切块 | Embedding | 关键信息命中 | 全命中 | Recall@10（纯向量） |
|---|---|---|---|---|---|
| **A** | 自研 | kinfra-text-embedding-0.6b | **13.0%** | 1/45 | **86.7%** |
| C | 自研 | kinfra-text-embedding-4b | 11.7% | 1/45 | 64.4% |
| D | LlamaIndex | kinfra-text-embedding-4b | 11.7% | 1/45 | 31.1%* |

*D 组 Recall 不可比：KB 映射表基于自研切块 kb_id，LlamaIndex 块 id 体系不同，31.1% 为系统性偏低，非真实水平。

## 二、核心结论

### 1. Embedding 模型：0.6b 反而更好（针对我们的场景）

**意外但明确的结论：0.6b 全面优于 4b**（关键信息 13.0% vs 11.7%，Recall 86.7% vs 64.4%）。

原因分析：
- 4b 是**多语言/跨语言优化**模型（CMTEB 72.63 主要靠多语言对齐），而我们知识库**95% 中文 + 45 题中文问法**——4b 的跨语言能力在这里没有用武之地
- 0.6b 轻量模型在**单语种（中文）召回**上反而更聚焦；4b 高维（2560）在小语料（1586 块）上可能过拟合噪声
- 4b 官方定位"多语言跨语种检索"（中文问→英文文档命中），但测试集 45 题几乎都是中文问题+中文答案，未触发跨语言场景

**结论：维持 0.6b，不升级 4b**（省 2.5 倍存储 + 成本，效果还更好）。

### 2. 切块方案：自研（表格独立）优于 LlamaIndex（表格混正文）

在相同 4b embedding 下，自研 Recall 64.4% vs LlamaIndex 31.1%（虽不可严格比，但自研关键信息命中 ≥ Llama，且块数 1586 > 1363 粒度更细）。自研的**表格独立成块**（218 个表格块）让表格检索可命中，LlamaIndex 把表格混进长正文块、稀释了语义。

**结论：维持自研切块**，LlamaIndex 方案作为 `--splitter llama` 可选项保留（未来如需对齐官方生态可切换）。

## 三、0.6b 纯向量 vs 混合检索（生产链路）差距分析

A 组纯向量 Recall 86.7%（6 题未命中），生产混合链路 97.8%——**FULLTEXT 弥补了 6 题中的 5 题**：

| 未命中题 | 原因 | 混合检索是否救回 |
|---|---|---|
| A-04 牛奶过敏→哮喘（KB-A3 过敏进程） | 库覆盖弱（无独立过敏进程章节） | ✅ FULLTEXT 命中 |
| C-02 就医流程（KB-C1） | 语义近但块未进 top10 | ✅ |
| E-02 钙/维D 补充（KB-E5） | 同上 | ✅ |
| G-02 疫苗（KB-G3） | 同上 | ✅ |
| G-05 家长焦虑（KB-G5） | 同上 | ✅ |
| H-01 挂哪个科（KB-H1） | 同上 | ✅ |

**结论：混合检索（FULLTEXT + 向量 RRF）是正确架构**，纯向量不够；生产 97.8% 达标。
